## 프로젝트가 지향하는 게임

플레이어는 직접 싸우는 용사가 아니라 던전을 미리 답사한 **고블린 길잡이**다.
경로와 조언을 고르고, 파티를 살려 명성과 계약금을 쌓을지 파티를 희생해 유품
골드를 얻을지 결정한다. 캠페인 마지막에는 단순 승패보다 다음 질문이 남아야 한다.

> S급 길잡이라는 목표를 위해 나는 어떤 선택을 했는가?

설정집에서 확인되는 고정 축은 다음과 같다.

| 축 | 현재 규칙 |
| --- | --- |
| 캠페인 | 던전 15개를 클리어하거나 조기 엔딩이 날 때까지 반복 |
| 던전 | 거미굴·사막·묘지 3테마 × 5개, 초기 위험도 ★1~5 |
| 인력 | 5직업 × 6명의 캐릭터 30명, 캠페인 중 충원 없음 |
| 파티 | 원정마다 서로 다른 직업 3명을 임시 편성 |
| 개입 | 경로 선택, 조언 3개 중 1개, 상인 사건 거래 |
| 추론 | 공개 생태 규칙·현장 단서·이전 결과로 도움/방해/중립을 추론 |
| 신뢰 | 캐릭터별 0~100, HP·신뢰·기억은 원정 뒤에도 지속 |
| 성장 | C→B→A→S 수동 승급, 명성 무료 승급 또는 골드 승급 |
| 실패 대가 | 사망·신뢰 0은 영구 손실, 전멸 시 명성 손실과 위험도 상승 |
| 결과 | 정상 완주 등급 또는 불신·고발·인력 소진·실직 조기 엔딩 |
| 재현성 | 캠페인 시드와 선택이 같으면 같은 결과 |

핵심 자원과 수치는 다음과 같다.

| 항목 | 값 |
| --- | --- |
| 시작 상태 | C급, 명성 30, 현재 골드 10, 누적 골드 0 |
| 승급 | 명성 60/120/200 또는 골드 150/320/600 |
| 던전 진입 | C ★2, B ★3, A ★4, S ★5까지 |
| 공개 생태 | ★1~2는 3개, ★3~4는 2개, ★5는 1개 |
| 신뢰 0 누적 | 2명부터 전체 판정 불이익, 5명에서 누적 고발 |
| 월드턴 | 비출전 인원의 휴식·백그라운드 원정·중상 처리 |

중요한 설계 원칙은 **규칙이 결과를 계산하고 화면은 그 결과를 설명한다**는
것이다. 일반 전투·보스전·정산·엔딩을 UI에서 다시 계산하지 않는다.

## 현재 구현 구조

기술 스택은 Next.js 16.3, React 19.2.8, TypeScript, Zustand, Vitest,
Framer Motion, Tailwind CSS다.

```text
lib/domain       도메인 타입과 상태 계약
lib/content      캐릭터·테마·사건 콘텐츠와 검증기
lib/rules        지도·조언·전투·정산·승급·엔딩의 순수 규칙
lib/store        캠페인 전이와 화면을 잇는 Zustand 스토어
components/game  U1~U6 화면과 규칙→화면 어댑터
app/campaign     실제 통합 캠페인 진입점
app/u*-test      화면별 상태를 확인하는 프리뷰·검증 진입점
docs             공식 설정집, 배정표, 설계·계획, 유예 기록
```

현재 흐름은 다음과 같이 연결되어 있다.

```text
/campaign
→ 인트로
→ 게시판·계약·승급
→ 지도
→ 사건·조언·일반 전투
→ 보스전
→ 정산
→ 월드턴
→ 다음 게시판 또는 엔딩
```

`CampaignState`와 세션 전용 원정 문맥은 분리되어 있고, 잘못된 전이는 예외로
화면을 깨뜨리지 않고 거부 결과로 남긴다. bfcache에서 돌아온 화면은 다시 그리며,
현재 `phase`와 규칙 전이 검증이 낡은 조작을 추가로 막는다.

### B1 밸런스 재측정 — 지금 시작할 작업

완료 기준은 다음 세 가지다.

- 배신 의도가 실제 전략으로 성립한다.
- S 도달률이 100%가 아니다.
- 추론 정확도 0.4와 0.7 전략의 결과 차이가 유의미하다.

배정표의 I2 완료 기록은 현재 자동 순회 흐름으로 150시드를 실행했고, 엔딩 분포가
`exhausted` 148 · `unemployed` 2였다고 남긴다. 즉, 지금 자동 전략은 거의 항상
인력 소진으로 끝나므로 캠페인 밸런스 또는 자동 전략 모델이 한쪽으로 크게 기울어
있다. 저장소에 상시 남은 회귀 검사는 이 가운데 40시드를 순회한다.

B1에서 먼저 필요한 산출물은 다음과 같다.

1. 현행 모델용 전략 정의: 생존 우선·균형·배신 우선 × 추론 정확도 0.4/0.7
2. `runToEnd` 흐름을 재사용하는 결정적 다중 시드 실행기
3. 완주율, 등급 도달률, 엔딩 분포, 생존·전멸, 자원·신뢰·사망 분포
4. 생성 오류·거부 전이·진행 불가를 별도 실패로 집계하는 검사
5. 재생성 가능한 새 `BACKTEST_REPORT.md`
6. 보고서를 근거로 한 상수 조정과 관련 공식 설정집 동시 갱신

기존 `2026-08-17` 밸런스 spec/plan은 구 카드 모델을 전제로 하므로 그대로 실행하면
안 된다. 프로젝트 규칙에 따라 현행 B1을 대상으로 brainstorming → 공식 문서 검토
→ 새 spec 승인 → plan 순서를 다시 밟는 편이 안전하다.

### Q1 접근성·전체 검증

B1 뒤에 수행한다.

- 키보드 조작과 포커스 흐름
- 색 외 상태 단서와 감소 동작 선호
- 선택 전 위험, 선택 후 변화 원인 표시
- lint·typecheck·test·build
- 실제 브라우저 캠페인 흐름
- 문서 수치와 코드 상수 일치
- 숨은 조언 정답·내부 식별자·`undefined`·`NaN`의 DOM 누출 방지

열린 PR #130은 마지막 항목을 위한 실제 캠페인 DOM 검사 7개를 추가한다. 프로덕션
코드는 건드리지 않고 게시판·지도·진행·정산·엔딩 렌더 결과를 확인하며, 현재
GitHub에서 병합 가능하고 Vercel 검사는 성공 상태다. B1 전에 검토·병합하면 Q1의
검증 기반을 먼저 확보할 수 있다.

## 현재 검증 결과

현재 체크아웃의 설치 상태까지 포함한 결과다. 저장소의 선언과 로컬 의존성 설치
상태를 구분해서 봐야 한다.

| 검사 | 결과 | 해석 |
| --- | --- | --- |
| Git | clean, `origin/main`과 0/0 | 조사 전 사용자 변경 없음 |
| lint | 종료 코드 0, 경고 44개 | 주로 의도적인 `<img>` 사용 경고, 미사용 import 4개 |
| typecheck | 실패 | 로컬 `node_modules`에 `framer-motion`이 없음 |
| test | 94 파일·910 테스트 통과, 3 파일 실패 | 2개 suite는 같은 의존성 누락, 1개는 40시드 검사의 5초 timeout |
| backtest | 실패 | `vitest.backtest.config.ts`가 요구하는 `*.run.ts`가 없음 |
| build | 미실행 | 의존성 누락으로 typecheck가 먼저 불완전한 상태 |

`framer-motion@13.1.1`은 `package.json`과 `pnpm-lock.yaml`에는 정상 선언되어 있다.
따라서 이 항목은 소스 누락이라기보다 현재 워크스페이스의 `node_modules`가 오래된
상태다. 정식 Q1 전에 잠금 파일 기준으로 의존성을 새로 설치하고 전체 검증을 다시
해야 한다.

40시드 회귀는 기능 거부를 보고한 것이 아니라 기본 5초 제한을 넘겨 timeout이 났다.
배정표 기록상 같은 검사는 최근 40시드와 150시드에서 끝까지 통과했으므로, Q1에서는
성능 회귀 여부를 재고 합리적인 명시적 timeout을 둘지 결정해야 한다.

## 문서와 현재 상태의 불일치

마감 전에 정리해야 할 문서 부채다.

1. **배정표 머리말의 개수가 낡았다.** `39개 완료·4개 남음`이라고 쓰지만 실제
   43개 행은 `40개 완료·3개 대기`다. 임계 경로와 표는 B1→Q1→Q2로 맞다.
2. **기존 백테스트 보고서가 현행 보고서처럼 연결되어 있다.** 2026-08-19의
   `BACKTEST_REPORT.md`는 `survivalFirst`·`card-truth-*`·승급 점수 등 폐기된
   모델을 기록한다. 현재 `pnpm backtest` 실행기는 존재하지 않는다.
3. **최상위 README의 C2 설명이 낡았다.** 공고별 공개 환경 특성이 있다고 하지만
   공식 루프와 완료된 U3 계약은 게시판에서 생태·환경 특성을 공개하지 않는다.
4. **게임 개요의 프로토타입/후속 문구가 어긋난다.** 자동 전투 장면 연출을 후속
   확장처럼 적었지만 게임 원칙의 고정 범위와 배정표 U5-2에는 이미 포함·완료되어
   있다.
5. **상위 개편 spec에 대체 상태 문구가 없다.** 유예 문서에도 기록된 항목이며,
   최신 공식 설정집과 E1·E2 후속 설계가 우선임을 문서 첫머리에 밝혀야 한다.
6. **유예 문서 일부는 I1/I2 이전 시점이다.** bfcache 대응은 이미
   `CampaignStoreProvider`에 구현됐다. `memberChanges`는 U6가 직접 표시하지는
   않지만 C8 통계·이력과 정산 상태 반영에는 쓰인다. U4·U5 빈 공간 항목도 실제
   로직 연결 뒤 다시 판정해야 한다.

이 문서 수정들은 게임 동작을 바꾸지 않는 정합성 작업이다. B1 spec을 쓰기 전에
1·2·5를 먼저 정리하면 새 작업의 기준을 오해할 가능성이 줄고, 3·4·6은 Q1 문서
전수 대조에 묶어도 된다.

스프라이트, 복잡한 전투 이펙트, 직접 전투 개입, 독립 아이템 인벤토리는 현재
마감 작업에 포함하지 않는다.

## 추천 실행안

### 바로 할 일

1. PR #130을 리뷰하고 이상이 없으면 병합한다.
2. 배정표 개수와 상위 개편 spec의 대체 상태를 짧은 문서 정합성 변경으로 고친다.
3. B1의 현행 목표를 대상으로 brainstorming하고 새 spec을 작성해 승인받는다.

### B1에서 결정해야 할 질문

- `추론 정확도 0.4/0.7`이 어떤 조언 선택 알고리즘을 뜻하는가?
- 생존·균형·배신 의도는 경로, 조언, 상인, 승급 방식을 각각 어떻게 고르는가?
- 현재 150시드가 인력 소진으로 쏠린 원인이 전투 수치, 파티 손실, 자동 전략 중
  어디에 있는가?
- “유의미한 차이”를 어떤 지표와 최소 차이로 판정할 것인가?
- 빠른 회귀용 시드 수와 정식 보고서용 시드 수를 얼마로 둘 것인가?

### B1 완료 뒤

의존성을 잠금 파일 기준으로 재설치하고 Q1 전체 검증을 수행한다. Q1에서 문서·코드
상수 검사, 실제 브라우저 접근성, 루트 진입점, 테스트 timeout을 함께 정리한다.
그 결과가 모두 통과한 뒤에만 Q2 배포와 시드 재현 확인으로 넘어간다.
