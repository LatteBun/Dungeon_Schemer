# 프로토타입 작업 배정표

## 목적

이 문서는 Dungeon Schemer 프로토타입의 큰 구현 영역과 담당자를 한곳에서 관리한다.
새 작업을 시작하기 전에 관련 행의 범위와 담당자를 갱신하고, 작업 범위가 독립적으로 커지면 새 행으로 분리한다.

## 배정표

| 구현 영역 | 프로토타입 목표 | 주요 포함 범위 | 담당자 |
| --- | --- | --- | --- |
| 게임 진행 기반 | 한 번의 플레이가 시작부터 결과까지 끊기지 않고 진행된다. | 게임 시작, 상태 전환, 방 이동, 턴·선택 흐름, 종료 조건 | |
| 파티와 개인 신뢰 | 서로 다른 파티원이 각자의 신뢰 상태를 갖고 반응한다. | 파티 생성, 직업·성격, 개인별 신뢰도, 신뢰 변화와 표시 | |
| 정보와 기만 | 길잡이가 진실·거짓·중립 정보를 통해 진행에 개입한다. | 정보 카드, 정보 제공 대상, 적발 위험, 정보 선택의 효과 | |
| 던전 이벤트와 보스 | 경로와 사건, 보스가 플레이어 선택에 따라 달라진다. | 길 선택, 일반 사건, 휴식·상인, 보스 거래, 보스전 개입 | |
| 선택 결과와 보상 | 선택의 이득·위험과 실제 결과가 명확하게 전달된다. | 즉시 결과, 자원 변화, 파티·던전 영향, 정산과 보상 | |
| UI와 온보딩 | 처음 30초 안에 길잡이의 역할과 첫 선택을 이해한다. | 시작 안내, 핵심 화면 구성, 선택 UI, 결과 피드백, 접근성 기본값 | |
| 데이터와 상태 관리 | 프로토타입 상태가 예측 가능하게 저장·복원되고 확장 가능하다. | 도메인 모델, 상태 관리, 랜덤 시드·데이터, 저장 전략 | |
| 검증과 배포 준비 | 핵심 플레이 흐름을 안정적으로 확인하고 공유할 수 있다. | 핵심 시나리오 검증, 오류 처리, 품질 점검, 빌드·배포 설정 | |

## 관리 원칙

- 담당자는 구현을 맡기로 합의한 사람의 이름 또는 식별자를 적는다.
- 한 사람이 여러 영역을 맡을 수 있지만, 인수인계가 필요하면 담당자 칸에 함께 표기한다.
- 새 기능은 가장 가까운 기존 영역에 추가하고, 범위가 독립적이면 새 행을 만든다.
- 세부 작업은 각 영역의 spec과 plan에서 관리하며, 이 표에는 큰 구현 책임만 기록한다.
