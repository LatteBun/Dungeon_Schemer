# 정보와 기만 시스템

## 목적

정보와 기만은 고블린 길잡이가 전투와 사건의 결과를 바꾸는 핵심 수단이다. 플레이어는 일반 지점에서 상황을 읽고 용사 파티에게 조언 하나를 건넨다.

플레이어가 정하는 것은 `무엇에 대해 말할지`가 아니라 **현재 상황에서 어떤 말을 할지**다. 조언의 내부 정답은 숨기되 판단에 필요한 생태와 관찰 근거는 남긴다.

## 대상과 조언

조언을 받는 대상은 살아 있는 용사 파티원뿐이다. 보스에게 파티 정보를 제공하거나 보스와 거래하지 않는다.

한 조언 기회는 상황 묘사와 조언 3개로 이루어진다. 조언은 내부적으로 도움·방해·중립을 정확히 한 개씩 담지만, 이 유형은 선택 전후 모두 플레이어에게 직접 공개하지 않는다.

조언은 효과가 언제 나타나는지로 갈린다.

| 시점 | 뜻 | 예 |
| --- | --- | --- |
| 즉시형 | 현재 사건의 결과를 바꾼다 | 횃불을 이용해 거미를 흩뜨리거나 잘못 유도해 피해를 키운다 |
| 지연형 | 보스전까지 개인별 믿음을 들고 간다 | 보스의 공격 신호를 믿고 피하거나 잘못 대응한다 |

지연형은 보스 관련 정보뿐이다. `보스 관련 정보`는 보스에게 주는 정보가 아니라 **파티에게 보스에 관해 건네는 조언**이다.

## 조언 기회와 Depth

**모든 일반 Depth에서 실제로 방문한 일반 지점이 조언 기회다.**

일반 Depth 수는 E1이 던전의 `initialRiskLevel`로 고정한다.

| 초기 위험도 | ★1 | ★2 | ★3 | ★4 | ★5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 일반 Depth 수 | 6 | 6 | 7 | 8 | 8 |

보스 정보 기회 수는 E2가 **현재 `riskLevel`**로 정한다.

| 현재 위험도 | ★1 | ★2 | ★3 | ★4 | ★5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 보스 정보 Depth | 1 | 1 | 2 | 2 | 2 |

보스 정보는 특정 공통 노드가 아니라 Depth를 예약한다. 모든 경로가 같은 Depth 수를 지나므로 어느 갈래를 골라도 보장 횟수를 충족한다. E2는 Depth만 계획하고, 실제 보스 정보 사건 ID는 E3가 해당 Depth의 실제 방문 순간 선택한다.

일반 사건의 선택·중복 방지·연계·방문 시 물질화 방식은 E3 책임이다. E2가 일반 사건 ID를 지도에 미리 배치하지 않는다.

```text
지점 선택
→ 상황 묘사 확인
→ 조언 3개 중 하나 선택
→ 살아 있는 파티원별 수용·의심·적발 판정
→ 한 명이라도 수용하면 실행 / 아무도 수용하지 않으면 기본 결과
→ E3가 사건 효과 또는 기본 결과 적용
→ E2가 결과를 바탕으로 즉시 신뢰 검증
→ 결과와 변화 표시
```

## 활성 생태 규칙과 공개

던전에서 참인 활성 생태 규칙 3개는 C1이 생태 패키지와 함께 `CampaignDungeon.activeRuleIds`로 확정한다. E2는 다시 뽑지 않는다.

공개 수는 현재 위험도를 따른다.

| 현재 위험도 | 공개 규칙 수 |
| --- | ---: |
| ★1~2 | 3 |
| ★3~4 | 2 |
| ★5 | 1 |

활성 규칙 3개에는 던전별 결정적 공개 우선순위가 있다. `attempt`는 이 우선순위에 넣지 않으므로 재도전으로 위험도가 오르면 공개 규칙이 무작위로 교체되지 않고 이전 공개 집합의 부분집합으로 줄어든다.

게시판과 계약 상세에서는 생태 규칙이나 별도의 공개 환경 특성을 보여주지 않는다. 공개는 계약 뒤 원정 진입부터 시작한다.

## 유형과 생태 규칙

테마 전용 조언의 내부 유형은 현재 활성 규칙과의 관계로 해석한다.

| `EcologyRelation` | 내부 `AdviceOutcome` | 의미 |
| --- | --- | --- |
| `consistent` | `help` | 현재 규칙과 정합해 파티에 이롭다 |
| `contradictory` | `harm` | 현재 규칙과 모순되어 파티에 해롭다 |
| `unrelated` | `neutral` | 생태 규칙과 무관하다 |

테마 전용 도움·방해는 생태 규칙을 참조한다. 중립은 생태 규칙을 참조하지 않는다.

### 조건부 규칙

조건부 생태 규칙은 두 조건을 모두 만족할 때만 조언 근거가 된다.

1. 현재 던전의 `activeRuleIds`에 포함된다.
2. 현재 사건에서 그 조건이 실제로 성립한다고 콘텐츠가 선언한다.

사건의 조건 성립 선언은 `satisfiedConditionalRuleIds`로 표현한다. 조언이 조건부 규칙을 `source`로 참조했다는 사실 자체로 조건을 자동 충족시키지 않는다. 현재 콘텐츠는 사건 ID별 독립 선언 목록과 사건 필드가 일치하는 회귀 검증을 두어 이 순환을 막는다.

조건이 성립하지 않은 조건부 규칙을 참조하는 조언 하나만 제거하지 않는다. 조언 3개 불변식을 지키기 위해 그 사건 전체를 현재 후보에서 제외한다.

### 공용 사건

`rest`, `merchant`, 공용 `special`은 생태 규칙을 참조하지 않는다. 세 조언의 `relation`은 모두 `unrelated`이고, 도움·방해·중립은 콘텐츠가 직접 선언한다. 플레이어는 장면에 적힌 관찰 가능한 사실로 판단한다.

```text
상황  상인이 말린 약초와 붕대를 내민다.
      포대는 마르고 끈은 막 잘라낸 듯 깨끗하다.

① 약초와 붕대를 사서 바로 처치하세요   (내부 도움)
② 그냥 지나가세요                    (내부 중립)
③ 싸구려 분말을 사서 급히 바르세요    (내부 방해)
```

괄호의 내부 유형은 설명용이며 실제 UI에는 표시하지 않는다.

상황 묘사에는 사실을 적고 결론을 적지 않는다. `끈은 막 잘라낸 듯 깨끗하다`는 사실이고 `이 약초는 안전하다`는 결론이다.

콘텐츠 공급은 테마 생태 규칙마다 그 규칙을 참조하는 **도움 2개·방해 2개 이상**을 유지한다. 중립은 규칙과 무관하므로 규칙별로 세지 않고 테마 전체 풀이 공급한다.

## 조언 표시 순서와 정보 은닉

콘텐츠 배열의 위치가 정답 힌트가 되지 않도록 조언 3개는 사건마다 결정적으로 셔플한다.

셔플 입력은 최소 다음을 포함한다.

- campaign seed
- dungeon id
- attempt
- depth
- event id

조언 순서 RNG는 반응 RNG와 독립한다. 같은 상태와 같은 기회에서는 순서가 같고, 다른 사건이나 다른 attempt에서는 달라질 수 있다.

플레이어용 선택 데이터에는 다음 내부 값을 넣지 않는다.

- `outcome`
- `relation`
- `source`
- 보스 피해 modifier
- 수용·적발 확률
- 예상 신뢰 변화

merchant의 실제 `goldCost`처럼 선택 전에 알아야 하는 비용은 공개한다.

## 파티원별 독립 반응

같은 조언을 살아 있는 모든 파티원에게 전달하고, 각 인물은 자신의 신뢰와 성격으로 `accepted`, `suspected`, `exposed`를 독립 판정한다. 사망자는 판정 대상에서 제외한다. `exposed`는 방해에서만 나온다.

### 기본 확률

| 내부 유형 | 수용 | 적발 | 의심 |
| --- | ---: | ---: | --- |
| 도움 | 70% | 0% | 나머지 |
| 중립 | 55% | 0% | 나머지 |
| 방해 | 45% | 15% | 나머지 |

### 신뢰 보정

| 현재 개인 신뢰 | 수용 보정 | 방해 적발 보정 |
| --- | ---: | ---: |
| 0~33 | -20 | +15 |
| 34~66 | 0 | 0 |
| 67~100 | +15 | -10 |

### 성격 보정

| 성격 | 수용 보정 | 방해 적발 보정 |
| --- | --- | ---: |
| 의심 많음 | -20 | +20 |
| 정의로움 | 도움 +15 / 방해 -10 / 중립 0 | +15 |
| 탐욕스러움 | +10 | -5 |
| 신중함 | -10 | +10 |
| 충동적 | +15 | -10 |

C6가 나중에 제공하는 신뢰 0 누적 캠페인 보정은 이 값 위에 더한다. E2 자체가 누적 신뢰 0 인원을 계산하지 않는다.

### clamp와 판정 순서

도움·중립은 모든 수용 보정을 합친 뒤 5~95%로 제한하고, 나머지를 의심으로 둔다.

방해는 적발률을 먼저 5~80%로 제한한다. 그다음 수용률을 5% 이상, `95% - 적발률` 이하로 제한한다. 1~100 카드 한 장에서 **적발 → 수용 → 의심** 순서로 구간을 해석한다.

살아 있는 파티원마다 `card` 난수 하나를 사용한다. 다른 파티원의 추가·제거·순서 변경이 결과를 흔들지 않도록 난수 입력에 `characterId`를 포함한다.

## 실행

파티원별 반응은 독립이지만 사건 행동은 하나다.

### 한 명 이상 수용

한 명이라도 `accepted`면 조언은 **한 번 실행**된다.

- E2는 `executed: true`만 결정한다.
- E3가 선택 조언의 실제 사건 효과를 파티 전체에 정확히 한 번 적용한다.
- 여러 명이 수용해도 효과를 중복 적용하지 않는다.
- 의심한 파티원은 실행에 참여하지 않았지만 파티 전체 결과는 함께 받는다.
- 한 명이 방해를 `exposed`해도 다른 한 명이 `accepted`했다면 실행을 취소하지 않는다.

적발은 거부권이 아니다.

### 아무도 수용하지 않음

`accepted`가 0명이면 `executed: false`다. E3는 선택 조언의 효과를 적용하지 않고 사건의 기본 결과를 적용한다.

기본 결과는 파티가 길잡이 조언 없이 처리한 세계 안의 결과다.

## 즉시형 신뢰 검증

신뢰는 조언을 클릭한 순간이 아니라 **사건 결과가 실제로 나온 뒤** 움직인다.

### 실행된 경우

| 반응 + 내부 유형 | 결과 뒤 신뢰 행동 |
| --- | --- |
| accepted + help | `adviceHelped` |
| accepted + harm | `adviceHarmed` |
| accepted + neutral | 없음 |
| suspected | 없음 |
| exposed + harm | `adviceHarmed` 후 `deceptionExposed` |

`adviceHarmed`는 틀린 조언 자체에 대한 비교적 작은 손실이고, `deceptionExposed`는 고의적 기만을 눈치챈 추가 손실이다.

### 아무도 수용하지 않은 경우

기본 결과가 나온 뒤 의심이 옳았는지 검증한다.

| 선택한 내부 유형 | suspected 인물 |
| --- | --- |
| help | `suspicionWasCostly` |
| harm | `suspicionWasCorrect` |
| neutral | 변화 없음 |

방해를 즉시 `exposed`한 인물은 실행 여부와 무관하게 `adviceHarmed`와 `deceptionExposed`를 받는다.

실행된 사건의 `suspected` 인물에게는 `suspicionWasCostly/Correct`를 적용하지 않는다. 이미 파티 전체가 실행 결과를 받았기 때문이다.

옛 정보 카드 흐름의 `deceptionAccepted`는 사용하지 않는다. 방해가 단순히 믿어졌다는 이유만으로 결과 확인 전에 신뢰를 올리지 않는다.

## 보스 관련 정보

보스 정보도 같은 확률표로 개인 반응을 판정하지만 결과 기반 신뢰는 보스전까지 미룬다.

| 반응 + 내부 유형 | 개인 보스 피해 보정 | 선택 시 신뢰 검증 |
| --- | ---: | --- |
| accepted + help | -20% | 보스전까지 대기 |
| accepted + neutral | -10% | 없음 |
| accepted + harm | +25% | 보스전까지 대기 |
| suspected | 0% | 보스전까지 대기(help/harm만) |
| exposed + harm | 0% | 즉시 `adviceHarmed` + `deceptionExposed` |

보스 정보가 두 번인 경우 수용한 개인 보정을 합산한다. 피해 감소는 최대 -30%, 피해 증가는 최대 +50%로 제한하며 실제 합산과 전투 적용은 E4가 담당한다.

보스전 뒤 E4는 pending 검증 기록을 다음 신뢰 행동으로 바꾼다.

| 기록 | 보스전 뒤 행동 |
| --- | --- |
| accepted help | `adviceHelped` |
| accepted harm | `adviceHarmed` |
| suspected help | `suspicionWasCostly` |
| suspected harm | `suspicionWasCorrect` |
| neutral | 없음 |

적발되지 않은 accepted harm이 보스전 결과가 나빴다는 이유만으로 자동 `deceptionExposed`가 되지는 않는다.

현재 던전의 `bossId`와 다른 `targetBossId`의 보스 정보 사건은 `INVALID_GENERATION`으로 거부한다.

## 단서와 진행 기록

모든 사건의 상황 묘사는 관찰 가능한 사실을 담는다. 규칙 문장을 그대로 결론으로 말하지 않는다.

현재 원정에서 확인한 근거는 진행 화면 하단 콘솔의 `진행 기록`에서 다시 볼 수 있다.

```text
[전체] [단서] [전투] [생태]
```

`생태`에서는 두 범주를 구분한다.

- **확인된 생태**: E2가 현재 위험도에 따라 직접 공개한 규칙
- **관찰 단서**: 현재 원정에서 실제로 본 상황·흔적·결과

관찰 단서는 숨은 규칙 문장으로 자동 승격하지 않는다. 시스템이 `이 단서의 정답은 규칙 B`라고 결론을 내려주지 않는다.

새 원정이나 재도전을 시작하면 현재 원정의 관찰·진행 기록은 초기화한다. 활성 규칙 3개와 던전별 공개 우선순위는 유지되며, 플레이어가 이전 원정에서 스스로 배운 내용을 기억해 활용하는 것은 허용한다.

## 단서 연계

연계는 E3가 소유한다.

| 세기 | 규칙 |
| --- | --- |
| 약한 연계 | 방문해 획득한 단서가 있으면 이후 사건의 조언 슬롯 하나를 같은 유형의 강화판으로 교체 |
| 강한 연계 | 위험도별로 서로 다른 Depth 슬롯에 선행·후속 사건을 예약하고 실제 방문 시 물질화 |

강화판은 네 번째 선택지로 추가되지 않는다. 조언은 항상 3개다. 교체 대상 슬롯의 유형도 유지해야 한다.

E2의 보스 정보 예약 Depth와 E3의 강한 연계 예약 Depth는 겹치지 않는다. 충돌 검증과 강한 연계 계획은 E3가 담당한다.

## 피드백 원칙

### 선택 전

플레이어에게 보여주는 것은 판단의 재료이지 정답이 아니다.

- 살아 있는 파티원의 현재 신뢰와 성격
- E2가 직접 공개한 확인된 생태
- 현재 원정에서 본 관찰 단서와 사건 묘사
- 조언 문장과 merchant라면 실제 가격

조언 세 개는 같은 디자인으로 제시하고 **유형, 정답 색, 정합·모순 관계, 발각 확률, 예상 신뢰 변화량을 모두 감춘다.**

### 선택 뒤

다음 인과만 보여준다.

```text
선택한 조언
→ 파티원별 수용 / 의심 / 적발
→ 실제 사건 결과
→ HP · 골드 · 상태 변화
→ 신뢰 변화와 사람이 읽는 이유
```

`도움 조언이었습니다`, `방해 조언이었습니다`, `consistent`, `contradictory` 같은 정답 라벨은 결과 뒤에도 표시하지 않는다.

### 사후 검증

보스전과 이후 결과에서는 어떤 과거 조언이 현재 피해와 신뢰 변화에 영향을 주었는지 사람이 읽을 수 있는 원인 문장으로 연결한다. 내부 outcome enum을 정답표처럼 보여주지는 않는다.

## 조언 콘텐츠 계약

사건 하나는 상황 묘사와 조언 3개로 이루어지고, 조언은 도움·방해·중립을 정확히 한 개씩 담는다.

각 사건은 다음을 가진다.

- 상황 묘사. 관찰 가능한 사실을 담고 단서를 실어 나른다
- 조언 3개. 각각 선택지 문구, 고블린의 근거 대사, 결과 문구를 가진다
- 결과 문구는 **무슨 일이 왜 일어났는지** 드러낸다
- 테마 도움·방해는 참조 생태 규칙과 relation을 가진다. 중립은 참조 규칙이 없다
- 조건부 규칙을 쓰면 사건별 조건 성립 선언을 가진다
- 아무도 수용하지 않았을 때의 기본 결과 문구
- 강화판이 있으면 교체할 슬롯과 그 대체 조언

사건은 생태 규칙을 참조하면 테마 전용이고, 참조하지 않으면 공용이다. 공용 사건은 모든 테마의 던전에 나올 수 있다.

| 구분 | 수량 |
| --- | ---: |
| 테마 전용 | 테마당 30 |
| 공용 | 90 |
| 한 테마에서 만날 수 있는 것 | 120 |

사건 식별자·문구는 중복되거나 비어 있을 수 없다. 실제 방문한 사건 ID가 한 원정에서 중복되지 않게 하는 것은 E3 책임이다.

콘텐츠 검증은 수량·문구·source·relation·조건부 선언 불변식을 확인한다. 수용·의심·적발 확률과 개인 반응, 실제 사건 효과, 보스전 합산은 각 규칙 시스템이 계산한다.

## 생성 오류

다음 계약 위반은 조용히 재추첨하거나 선택지를 줄이지 않고 `RuleError("INVALID_GENERATION", ...)`로 실패한다.

- 조언이 정확히 3개가 아니거나 도움·방해·중립 각 1개가 아님
- 테마 도움·방해가 비활성 또는 테마 밖 규칙을 참조함
- 조건부 규칙을 참조하지만 사건 조건 성립 계약이 맞지 않음
- 보스 정보가 현재 던전 보스와 다른 보스를 대상으로 함
- 보스 정보 Depth 예약 수·범위를 만족하지 못함
- 공개 활성 규칙 3개의 계약이 깨짐

살아 있는 파티원이 0명인데 다음 조언 판정을 호출하는 것은 생성 오류가 아니라 원정 종료 전이가 먼저 와야 하는 `INVALID_STATE`다.
