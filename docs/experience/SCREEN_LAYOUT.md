# 화면 규격

## 목적

캠페인 화면이 같은 게임 셸을 쓴다는 것과, 그 셸 안에서 각 화면이 무엇을 어디에 두는지를 정한다. 화면이 바뀌어도 플레이어가 상단 상태와 우측 패널의 자리를 다시 배우지 않아야 한다. 캠페인 밖의 메인 메뉴와 업적 기록 화면은 아래의 전체 캔버스 규격을 따른다.

이 문서는 화면의 구조와 시각 규약만 다룬다. 각 화면이 보여주는 규칙과 수치의 근거는 해당 시스템 문서에 있고, 플레이어가 무엇을 이해해야 하는지는 [온보딩과 인터페이스](ONBOARDING_AND_INTERFACE.md)에 있다.

## 게임 셸

```text
GameShell
├─ TopStatusBar   길잡이 등급 · 명성 · 골드 · 승급 가능 여부 · 남은 던전
├─ MainContent    좌측 약 60%
└─ RightPanel     우측 약 40%
```

좌우 비율은 3:2(좌 60%·우 40%)다. 왼쪽은 게임 세계와 플레이어가 조작하는 대상, 오른쪽은 그 대상의 상세와 상태다. 화면이 바뀔 때 셸은 유지하고 두 영역의 콘텐츠만 교체한다.

상단 상태 바는 탐험 중에도 사라지지 않는다. 던전 안에서는 던전 이름과 현재 위험도를 함께 표시한다. 현재 명성이 내려가도 한번 얻은 길잡이 등급은 유지되므로, 둘을 서로 다른 표시로 구분한다.

## 고정 캔버스

| 기준 | 값 |
| --- | --- |
| 고정 캔버스 | 1920×1080 (16:9) |
| 창 대응 | 캔버스를 균일 확대·축소하고 남는 공간은 레터박스 |

화면은 창 크기와 무관하게 늘 같은 1920×1080 그림이다. 창이 작아지면 배치를 다시 짜는 것이 아니라 그림 전체가 작아진다. 이것은 관리 프로그램이 아니라 게임이기 때문이다. 플레이어가 창을 줄였다고 해서 방금 보던 화면과 다른 화면을 만나면 안 된다.

창 비율이 16:9가 아니면 남는 공간은 검은 레터박스로 남고 캔버스는 가로·세로 모두 가운데 정렬된다. 어떤 창 크기에서도 가로·세로 스크롤은 만들지 않는다. 가로로 잘린 정보는 플레이어가 있는 줄도 모르기 때문이다.

### 화면 루트의 캔버스 점유

고정 캔버스를 만드는 것과 그 안의 화면 루트가 캔버스 전체를 쓰는 것은 서로
다른 계약이다. 일반 화면의 최상위 DOM 요소는 `.game-canvas`의 폭과 높이를
전부 점유한다. 내부 패널, 배경, 카드에 의도적인 여백을 두는 것은 허용하지만,
그 여백 때문에 화면 루트 자체의 크기를 줄이지 않는다.

전체 점유가 화면 의도와 충돌하는 승인된 예외만 최상위 요소에
`data-canvas-layout="intrinsic"`을 선언할 수 있다. 예외는 해당 화면 spec에 이유와
기대 크기를 기록하고 화면별 테스트와 고정 캔버스 테스트의 허용 목록에 함께
등록한다. 단순한 내부 여백이나 작은 패널은 예외 사유가 아니다.

## 공용 요소 규칙

화면이 늘어나도 같은 것은 같아 보여야 한다. 공용 요소는 **한 곳에만 정의하고 화면별로 다시 선언하지 않는다.**

이 규칙이 없었을 때 상단 상태 바가 u1·u2·u3 에서 각각 다른 높이(88.8 / 67.4 / 82.6px)로 벌어졌다. 둘을 맞추려고 만든 동기화 파일이 또 하나의 정의가 되어 셋이 넷이 됐다. 화면을 하나 더 만들면 다섯이 된다.

| 요소 | 정의 위치 | 조정 방법 |
| --- | --- | --- |
| 상단 상태 바 | `app/globals.css` 의 `.game-shell__status-*` | `--status-*` 토큰 |
| CTA 아이콘 광학 정렬 | `app/globals.css` 의 `--cta-icon-optical-lift` | 버튼에 `--cta-text-size` 선언 |

새 화면은 `GameShell` 을 쓰면 공용 요소를 그대로 물려받는다. 특정 화면에서만 크기가 달라야 할 이유가 생기면, 화면 CSS 에 덧쓰지 말고 왜 달라야 하는지를 먼저 이 문서에 적는다.

### CTA 아이콘 정렬

한글 글자는 라인박스 중앙보다 잉크가 위에 놓인다. 하강부 자리를 비워 두지만 한글 글리프가 거의 쓰지 않기 때문이다. 그래서 아이콘을 박스 중앙에 두면 글자보다 낮아 보인다. 두 CTA 에서 실측한 어긋남은 글자 크기의 10.3~10.9% 로 일정했다.

아이콘은 박스 중앙이 아니라 **글자의 광학 중심선**에 맞춘다. 자산 자체의 잉크가 캔버스 중앙에 있는 아이콘은 `--cta-icon-optical-lift` 를 그대로 쓰고, 화살표처럼 자산이 이미 위로 치우친 경우에는 그 치우침이 같은 몫을 하므로 빼야 한다.

### 자산의 투명 여백

아이콘 자산은 투명 여백을 남기지 않는다. 여백이 좌우로 어긋나면 그림이 치우쳐 보이고, CSS 크기와 실제로 보이는 크기가 달라진다.

예외는 둘이다. 나란히 놓이는 자산끼리 비율을 맞춰야 할 때(빈 별 PNG 와 채운 별 SVG), 그리고 도형이 상하 비대칭이라 무게중심 보정이 필요할 때(계약 인장은 아래가 뭉툭해 아래 2px 을 남긴다)다. 두 경우 모두 의도된 값이므로 테스트에 이유를 적는다.

## 화면별 구조

| 화면 | MainContent | RightPanel |
| --- | --- | --- |
| 인트로 | 길잡이 역할과 캠페인 목표 | 우측 레일 유지 · 콘텐츠 없음 |
| 게시판 | 상단 길잡이 등급 버튼과 게시판 위 공고 최대 5장 | 던전 정보 · 출전 3인 · 계약 |
| 지도 | 범례 없는 공간형 지도 | 파티 상태 · 계약 전 답사 · 다음 지점 · 이동 |
| 진행 | 상 40% 장면 슬롯 / 하 60% 플레이어 콘솔 | 실시간 파티 상태 · 최근 반응 |
| 정산·엔딩 | 원인 순서대로 나열한 정산 | 위험도·보상 변화 · 엔딩 원인 |

### 캠페인 밖 메타 화면

`/` 메인 메뉴와 `/achievements` 업적 기록은 진행 중인 캠페인의 일부가 아니다.
두 화면은 `GameShell`과 `TopStatusBar` 없이 `.game-canvas`의 1920×1080을 전부
점유한다. 고정 캔버스의 균일 확대·축소와 레터박스 원칙은 캠페인 화면과 같다.

- 메인 메뉴는 `캠페인 시작`과 `업적 기록`의 두 실제 링크, 그리고 이 브라우저의
  업적 달성 수를 한 화면에 둔다.
- 업적 기록은 상단 제목·달성 수, 본문의 4열×3행 카드 열두 장, 하단의 메인 메뉴
  링크와 확인 절차가 있는 기록 초기화를 한 화면에 둔다. 카드 이미지는 비율을
  유지하며 스크롤 없이 보여야 한다.

### 인트로

우측 패널에 담을 캠페인 상태가 아직 없으므로 콘텐츠는 비워 둔다. 다만 공통 셸의 3:2(좌 60%·우 40%) 구조와 우측 레일은 유지하며, 인트로도 다른 화면과 같은 열 비율을 사용한다. 화면별 콘텐츠만 교체하고 셸의 두 열을 합치지 않는다. 상단 상태 바는 시작 값 그대로 유지해, 플레이어가 첫 공고를 고르기 전에 자신이 가진 것을 본다.

### 게시판

왼쪽은 실제 길드 게시판처럼 보이되 공고 하나하나는 클릭 가능한 카드다. 다섯 장을 판 전체를 채우지 않는 작은 동일 크기로 두고, 위치와 회전각을 서로 다르게 해 손으로 하나씩 붙인 듯한 비대칭을 만든다. 카드끼리 겹치거나 읽기·클릭 순서를 바꾸지는 않는다. 고정 캔버스가 작은 창에 맞춰 축척되어도 같은 배치와 조작성을 유지한다.

공고에는 던전 이름, 위험도 ★1~5, 진입 가능 여부, 보상 요약만 적는다. 생태 추론 정보는 던전 진입 뒤 공개한다. 출전 인물과 생존 인원별 계약 조건은 우측 상세에서 본다.

우측 상세에는 선택한 던전의 이름·위험도·보상, 출전 3인의 직업·성격·HP·신뢰·소지 골드, `전원/2명/1명 생존`과 `전원 사망`의 계약 결과를 보여준다. 던전 정보와 계약 조건 뒤에는 장면 이미지를 깔지 않고 어두운 공통 카드 바탕을 사용한다. 별도의 정찰 보고·답사 기록·소요 시간 영역은 두지 않는다.

진입 불가 공고도 숨기지 않는다. 붉은 테두리와 진입 불가 문구로 구분하고, 클릭하면 우측에서 사유를 확인할 수 있다. 캠페인이 끝나는 이유를 플레이어가 공고로 직접 본다.

상단 길잡이 등급은 클릭 가능한 버튼이다. C·B·A 등급은 조건 미달이어도 같은 버튼으로 다음 등급, 현재값, 요구값과 부족 사유를 확인한다. 명성 또는 골드 조건을 만족하면 색 외의 강조와 빛나는 효과를 제공하고 해당 경로를 활성화한다. S급은 승급 선택을 열지 않는다. 버튼을 누르면 게시판 셸 안에서 명성·골드 승급 선택을 열고, 완료 결과를 확인한 뒤 갱신된 공고로 돌아온다.

### 지도

범례 영역은 두지 않는다. 지점 자체를 아이콘으로 표현하고(몬스터 · 모닥불 · `?` · 보스 전용 문양), 다음 다섯 가지를 지도만 보고 구분할 수 있게 한다.

- 현재 위치
- 방문 완료
- 선택 가능한 다음 지점
- 지금 선택할 수 없는 다른 갈래
- 보스방

선 위의 원형 노드가 아니라 방·복도·갈림길·합류 지점이 있는 공간으로 그린다.
우측은 파티 상태, 계약 전 답사, 현재 선택한 다음 지점 순으로 읽히게 한다.
선택한 지점과 이동 버튼은 우측 최하단에 두고, 이동 버튼이 화면의 마지막
조작 요소가 되게 한다.

### 진행

왼쪽을 위아래로 나눈다. 위 40%는 자동 전투 장면을 포함할 수 있는 파티 이동·전투 장면 슬롯이고, 아래 60%는 플레이어가 직접 조작하고 원정 정보를 되짚는 콘솔이다. 조작 영역이 장면보다 넓다는 원칙을 유지한다. 전투 장면은 정적 PNG 기반의 공격·피격·HP 변화·사망·승패 결과를 보여주며, 전투 규칙과 수치는 기존 rules 계층이 소유한다.

하단 콘솔은 다음 두 모드를 가진다.

```text
[행동 / 조언] [진행 기록]
```

`행동 / 조언`에서는 상황 묘사를 먼저 보여주고 같은 디자인의 조언 3개를 그 아래 둔다. 현재 상황 패널은 남는 세로 공간을 채워 조언 카드 또는 선택 후 결과 바로 위까지 이어지며, 제목과 본문은 패널의 좌측 상단에 둔다. 패널과 다음 영역 사이에는 작은 기존 행 간격을 유지한다. 조언 유형·발각 확률·예상 신뢰 변화는 표시하지 않는다. 선택이 필요한 순간에는 이 모드를 자동으로 전면에 두고, 선택 뒤 결과가 나오거나 전투가 진행되는 동안에는 `진행 기록`으로 전환할 수 있다. 플레이어는 언제든 두 모드를 수동으로 바꿀 수 있다.

조언 3개는 하단 콘솔의 남은 높이를 전부 채우지 않는다. 내용에 필요한 같은 높이로 맞추고 콘솔 아래쪽에 정렬하되, 콘솔의 기존 안쪽 여백은 남겨 바닥에 붙어 보이지 않게 한다. 외형은 모서리를 잘라낸 금속 명패, 이중 테두리, 리벳을 쓰되 세 카드의 색·장식·크기를 모두 같게 유지한다. 카드 외형이 조언의 유형이나 유불리를 암시해서는 안 된다.

`진행 기록`은 현재 원정의 시간 순 기록을 보여주며 최소 다음 필터를 제공한다.

```text
[전체] [단서] [전투] [생태]
```

- **생태**: E2가 현재 위험도에 따라 직접 공개한 활성 생태 규칙을 다시 보여준다.
- **단서**: 사건에서 관찰한 사실과 결과를 보여준다. 숨은 규칙 문장으로 자동 승격하지 않는다.
- **전투**: 자동 전투의 행동·피해 기록을 보여준다.
- **전체**: 조언 선택·파티 반응·사건 결과를 포함해 원정 흐름을 시간 순으로 합친다.

조언 3개는 항상 같은 디자인이다. 무엇을 감추고 무엇을 보여주는지는 [정보와 기만](../systems/INFORMATION_AND_DECEPTION.md)의 「피드백 원칙」을 따른다. 화면이 지는 몫은 셋이 시각적으로 구별되지 않게 하는 것과, 추론의 근거인 공개 생태 규칙과 관찰 단서를 같은 화면 안에서 다시 확인할 수 있게 하는 것이다.

선택 뒤에는 인과 순서로 보여준다.

```text
선택 → 파티원별 반응 → 사건 결과 → HP · 신뢰 · 상태 변화
```

내부 `help / harm / neutral`, `consistent / contradictory` 같은 정답 라벨은 선택 뒤에도 직접 표시하지 않는다. 실제 결과 문구와 수치 변화, 파티원의 세계 안 반응으로 원인을 이해하게 한다.

전투가 아닌 진행 장면에는 현재 파티원 3명의 기존 PNG를 장면 좌측 하단에 세운다. 캐릭터가 오른쪽을 바라보는 원본 방향을 유지하고, 크기와 높이를 조금 달리해 깊이감만 준다. 전투 장면에서는 전투 참가자 표현으로 교체하며 비전투 파티를 중복 표시하지 않는다.

우측은 살아 있는 파티원의 HP·신뢰·소지 골드와 최근 반응을 실시간으로 갱신한다. 일반 몬스터 전투와 보스전의 주요 CTA는 우측 하단 한 자리를 공유한다. 재생 중에는 `전투 건너뛰기`만 제공하고 다음 단계 이동을 허용하지 않는다. 자연 종료 또는 건너뛰기로 complete frame에 도달한 뒤 일반전은 같은 자리를 `지도로 돌아간다`, 보스전은 `정산으로`로 바꾼다. 완료 뒤 `다시 보기`를 시작하면 재생이 끝날 때까지 다시 `전투 건너뛰기`로 돌아가며 다음 단계 이동을 잠근다. 비전투 사건의 다음 단계 CTA는 기존 흐름을 유지한다.

전투 장면 우측 상단에는 결과 이동과 분리된 로컬 `×1 / ×2` 재생 속도 토글을 둔다. 모든 일반전과 보스전은 새 원정에서 `×1`로 시작하고, 같은 원정의 다음 전투와 `다시 보기`는 선택한 속도를 유지한다. 원정 정산 뒤 새 계약을 시작하거나 새 브라우저 문서를 열면 `×1`로 돌아간다. 속도 토글은 재생 중과 complete frame 모두 남으며, 우측 하단 `전투 건너뛰기`·다음 단계 CTA의 자리나 잠금 정책을 바꾸지 않는다.

### 정산·엔딩

정산 왼쪽은 `원정 결과 표제 → 마지막 조언과 파티의 판단 → 원정대 결과 3인` 순으로 읽힌다. 고정된 다섯 단계와 번호는 사용하지 않는다. 피해 수치와 신뢰 변화는 인물별 결과에, 보상과 던전 변화는 우측 캠페인 변화에 한 번만 둔다.

클리어는 던전 이름과 `정복`, 귀환 인원과 사망자 이름을 표시한다. 클리어한 던전은 게시판에서 제거되므로 위험도 유지 여부를 표시하지 않는다. 전멸에서만 위험도 전후 또는 ★5 상한과 재도전 보상을 보여준다.

정산 오른쪽은 던전 결과, 명성, 계약 골드, 전멸 유품 골드, 살아 있는 신뢰 0 누적과 현재 보정만 보여준다. 살아 있는 신뢰 0 인물은 변화량이 없어도 `정체 발각`과 `원정 출전 불가`를 표시하며, 사망자는 신뢰 0 누적에서 제외한다. 승급 가능 여부는 상단 상태 바가 계속 알리고 정산 패널에 중복하지 않는다.

정산을 마치고 게시판으로 돌아가는 CTA는 우측 패널의 최하단에 둔다. 다른 화면의
다음 단계 CTA와 같은 높이·글자 크기·좌우 여백을 사용하되, 패널 전체 폭으로
늘리지 않고 문구에 필요한 내용 폭으로 우측 정렬한다.

## 시각 방향

다크 판타지로 통일한다. 짙은 목재 프레임, 금속 장식, 양피지 질감, 따뜻한 광원, 금색 계열 테두리와 포인트다. 관리 프로그램이 아니라 길드와 던전 세계 안에 있는 물건처럼 보이게 한다.

세계관 표현과 조작 UI를 분리하지 않는다. 게시판 배경은 실제 게시판처럼, 공고 종이는 실제 클릭 가능한 카드처럼 만든다.

| 색 | 의미 |
| --- | --- |
| 초록 | 활성 · 선택 · 진행 가능 · 수용 |
| 금색 | 선택 가능 · 강조 · 의심 |
| 붉은색 | 위험 · 진입 불가 · 보스 · 적발 |

## 색 외 단서 원칙

세 시각 레퍼런스는 위 시각 언어와 정보 위계의 근거다. [캠페인 게시판](../diagram/png/REFERENCE_UI_01_CAMPAIGN_BOARD.png)은 좌 공고·우 계약 상세, [던전 지도](../diagram/png/REFERENCE_UI_02_DUNGEON_MAP.png)는 경로·파티 정보, [던전 진행](../diagram/png/REFERENCE_UI_03_DUNGEON_PROGRESS.png)은 장면·선택지·최근 반응 구획을 참고한다.

레퍼런스 PNG는 구현 자산이 아니다. React 화면에 임베드하거나 복제하지 않고, CSS의 명도·프레임·정보 밀도와 콘텐츠 구획에만 반영한다.
**색만으로 의미를 전달하지 않는다.** 색을 쓸 때는 항상 텍스트나 형태 단서를 함께 둔다.

| 상황 | 색 | 함께 두는 단서 |
| --- | --- | --- |
| 진입 불가 공고 | 붉은 테두리 | `진입 불가`와 사유 문구 |
| 지도의 현재 위치·방문 완료·비활성 | 초록 · 흐린 회색 · 어두움 | 아이콘 형태와 테두리 모양 |
| 보스방 | 붉은 문양 | 보스 전용 문양 |
| 파티원 반응 | 초록 · 금색 · 붉은색 | `수용` · `의심` · `적발` 문구 |

조언 유형은 색으로도 텍스트로도 표시하지 않는다. 이 원칙은 감춰야 할 것을 드러내라는 뜻이 아니라, 드러내기로 한 것을 색에만 맡기지 말라는 뜻이다.

## 구현 구조

```text
app/play/layout.tsx
└─ GameShell
   ├─ TopStatusBar
   ├─ MainContent
   └─ RightPanel
```

게임 도메인을 아는 컴포넌트는 `components/game/`에, 도메인을 모르는 범용 프레임과 패널은 `components/ui/`에 둔다.

모션은 공고 선택, 경로 활성화, 파티 이동, 피격, 조언 선택, 반응 표시, HP·신뢰 변화 같은 결과 피드백에 쓴다. 모션을 보여주려고 정보를 늦추거나 가리지 않는다.

## 프로토타입 범위 밖

- 다프레임 스프라이트, 전용 파티클 이펙트, 복잡한 카메라를 쓰는 자동 전투 장면 연출
- E4가 실제로 해석한 보스전 결과·턴 기록의 원정 통합과 시각 표현. 단, U5-2
  Task 1~2의 공유 전투 장면 계약을 검증하는 명시적 라벨의 정적 타입 fixture는
  이 범위에 포함한다.
- 최종 아트 스타일과 고유 던전·보스 서사 화면
- 작은 브라우저 창과 모바일 대응
- 지도 카메라 이동과 줌
- 캠페인 저장·복원과 계정 UI. 브라우저 업적 기록과 그 초기화 UI는 범위 안이다
