# 캐릭터 UI 에셋

## 목적

직업별 캐릭터 초상을 파티 UI와 결과 UI에서 재사용하기 위한 자산 카탈로그다. 캐릭터의 생존·사망·신뢰·출전 가능 의미는 [캐릭터와 신뢰 시스템](../systems/CHARACTERS_AND_TRUST.md)이 소유하고, 이 문서는 해당 상태를 표시할 때 사용할 정적 파일의 경로와 시각 규칙을 소유한다.

## 정적 경로 규칙

```text
/assets/characters/live/{archer|cleric|mage|rogue|warrior}/{class}_{a..f}.png
```

상태 디렉터리와 직업 디렉터리를 모두 포함해야 한다. `a`·`b`는 시각 변형이며 성격, 신뢰, 고유 캐릭터 ID, 능력치를 뜻하지 않는다.

## 공식 에셋 목록

각 상태에 다섯 직업의 두 변형이 있어 총 20개다. `live`와 `dead`의 같은 직업·변형 파일은 동일한 원본 해상도 계약을 따른다.

| 상태 | 직업 디렉터리 | 표시 직업 | 파일 | 원본 해상도 |
| --- | --- | --- | --- | --- |
| `live`·`dead` | `archer` | 궁수 | `archer_a.png`, `archer_b.png` | 1024×1536 |
| `live`·`dead` | `cleric` | 성직자 | `cleric_a.png`, `cleric_b.png` | 1024×1536 |
| `live`·`dead` | `mage` | 마법사 | `mage_a.png`, `mage_b.png` | 1024×1536 |
| `live`·`dead` | `rogue` | 도적 | `rogue_a.png`, `rogue_b.png` | 1024×1536 |
| `live`·`dead` | `warrior` | 전사 | `warrior_a.png`, `warrior_b.png` | 1086×1448 |

예를 들어 궁수의 생존 변형은 다음 경로를 사용한다.

```text
/assets/characters/live/archer/archer_a.png
/assets/characters/live/archer/archer_b.png
```

사망 변형은 `live`를 `dead`로 바꾼 동일한 구조를 사용한다.

## 상태별 UI 사용 규칙

### `live`

도메인 상태가 생존으로 판정된 캐릭터의 다음 UI에 사용한다.

- 게시판 계약 상세의 출전 파티원 카드
- 지도 화면의 파티 상태 패널
- 진행 화면 우측 파티 상태와 반응 영역
- 생존 파티원을 보여주는 정산·캠페인 결과 UI

### `dead`

실제 사망이 확정된 캐릭터의 다음 UI에만 사용한다.

- 전멸·사망 결과 기록
- 사망자가 포함된 정산 내역
- 캠페인 기록 또는 사망 캐릭터 목록

신뢰 0, 중상, 현재 미출전, 잠시 출전 불가 상태는 사망이 아니다. 그런 상태를 시각적으로 구분해야 할 때는 도메인 상태 문구·테두리·아이콘·HP 표시를 사용하고 `dead` 이미지를 대신 쓰지 않는다.

## 변형 매핑 규칙

`a`·`b` 중 어느 파일을 특정 캐릭터에 배정할지는 이 카탈로그가 정하지 않는다. 캐릭터 ID와 초상 변형을 연결하는 별도 UI·도메인 작업에서 안정적인 매핑을 정의한다.

- 같은 캐릭터가 화면이나 세션마다 무작위로 다른 변형으로 바뀌지 않게 한다.
- 변형 선택으로 성격·신뢰·직업·능력치를 추론하게 만들지 않는다.
- 매핑이 없을 때는 화면 컴포넌트 안에서 임의의 파일명을 조립하지 말고 승인된 placeholder 또는 선택적 매핑 계약을 사용한다.

## 표시 기준

- 원본은 세로 초상이다. 기본 표시 방식은 비율 왜곡이 없는 `object-fit: contain`으로 한다.
- `cover` crop이 필요한 화면은 해당 UI 작업 문서에서 머리·장비·실루엣이 잘리지 않는지 확인하고 별도로 승인한다.
- 원본을 임의로 다시 저장하거나 리사이즈하지 않는다. 목표 슬롯보다 원본이 큰 경우 UI 표시 크기에서 축소한다.
- 캐릭터 상태를 색만으로 전달하지 않는다. `생존`, `사망`, `중상`, `신뢰 0`처럼 공식 상태 의미에 맞는 텍스트·형태·수치 단서를 함께 사용한다.
- 새 파티 UI를 배치하거나 기존 UI를 확장할 때는 [UI 구현 가이드](UI_IMPLEMENTATION_GUIDE.md)와 [화면 규격](SCREEN_LAYOUT.md)을 함께 확인한다.

# 현재 초상화 자산 계약 (2026-08-26)

초상화는 공식 캐릭터 ID에서만 해석하며, 경로는 아래로 고정한다.

```text
/assets/characters/live/{class}/{class}_{a..f}.png
```

- `lib/content/character-roster.ts`의 `portraitVariant`가 파일 suffix를 결정한다.
- 사망, 중상, 신뢰, 출전 가능 여부는 초상화 파일 경로를 바꾸지 않는다.
- `dead/` 자산은 더 이상 제공하지 않는다. 사망은 카드 상태와 텍스트로 표현한다.
- 원본 이미지의 해상도와 비율은 서로 다를 수 있으며 UI는 이를 강제 통일하지 않는다.
