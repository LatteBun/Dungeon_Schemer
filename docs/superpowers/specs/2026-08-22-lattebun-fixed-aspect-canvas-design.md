## 1. 문제와 목표

지금 화면은 브라우저 창 크기를 따라 계속 모양을 바꾼다. `.game-shell`이
`100vh`를 채우고, `app/*.css`의 `clamp()` 약 180곳이 `vw`·`vh`를 섞어 쓰며,
미디어 쿼리 10개가 폭과 높이에 따라 서로 다른 배치를 켠다. 그 결과 같은
게시판이 창 크기마다 다른 밀도로 보이고, 창을 조금만 줄여도 압축 규칙이 켜져
방금 보던 화면과 다른 화면이 된다.

이 프로젝트는 관리 도구가 아니라 게임이다. 게임 화면은 창 크기와 무관하게 늘
같은 그림이어야 하고, 플레이어가 창을 줄였을 때 배치가 재구성되는 대신 그림
전체가 작아져야 한다.

완료 목표는 다음과 같다.

- 모든 화면이 16:9 고정 캔버스 안에서만 그려진다.
- 캔버스는 창 안에 들어갈 수 있는 가장 큰 크기로 균일하게 확대·축소된다.
- 캔버스가 채우지 못한 나머지 공간은 빈 레터박스로 남고, 캔버스는 가로·세로
  모두 가운데 정렬된다.
- 창 크기를 바꿔도 요소 사이의 상대 비율과 줄바꿈이 달라지지 않는다.
- 가로·세로 스크롤이 생기지 않는다.

## 3. 기준 해상도 변경

`docs/experience/SCREEN_LAYOUT.md`의 기준 해상도는 1280×720, 최소 지원은
1024×640이다. 고정 캔버스에서는 최소 지원이라는 개념이 사라진다. 창이 작아도
같은 그림이 작게 보일 뿐이기 때문이다.

캔버스 해상도는 1920×1080으로 정한다. 근거는 셋이다.

1. `app/u3-large-screen.css`의 `@media (min-width: 90rem)`·`(min-width: 120rem)`
   블록은 1440px·1920px 이상에서 켜지는 고밀도 디자인이고, U3 작업에서 가장
   최근까지 다듬은 결과물이다. 캔버스를 1920으로 두면 이 디자인이 기본값이
   된다. 1280으로 두면 이 블록 전체가 사장되고, 대신 짧은 세로 화면용 압축
   디자인이 고정된다.
2. `public/assets/u2/intro-background-full.png`가 1920×1080이다. 자산이 이미
   이 해상도를 전제한다.
3. 캔버스가 원본 자산보다 작으면 축소만 일어나 선명하지만, 크면 확대되어
   흐려진다. 1920은 대형 모니터에서도 확대 배율이 1을 크게 넘지 않는다.

따라서 `SCREEN_LAYOUT.md`의 「기준 해상도」 표를 다음으로 바꾼다.

| 기준 | 값 |
| --- | --- |
| 고정 캔버스 | 1920×1080 (16:9) |
| 창 대응 | 캔버스를 균일 확대·축소하고 남는 공간은 레터박스 |

「최소 지원 아래에서는 세로 스크롤을 허용하되 가로 스크롤은 만들지 않는다」는
문장은 더 이상 성립하지 않으므로 고정 캔버스 설명으로 교체한다.

## 4. 확대·축소 방식

### 4.1 `transform: scale`을 쓰지 않는 이유

고정 캔버스를 만드는 흔한 방법은 1920×1080 상자에 `transform: scale()`을 거는
것이다. 이 방법은 두 가지 문제가 있다. 배율을 계산하려면 길이를 길이로 나눠
무단위 수를 얻어야 하는데 그 계산의 브라우저 지원이 균일하지 않고, 대안으로
JavaScript를 쓰면 클라이언트 컴포넌트와 첫 렌더 시점 문제가 따라온다.

### 4.2 루트 글꼴 크기로 배율을 만든다

대신 루트 글꼴 크기 자체를 창에 맞춰 축척으로 쓴다.

```css
html {
  font-size: min(100vw / 120, 100vh / 67.5);
}
```

`120 × 16px = 1920`, `67.5 × 16px = 1080`이므로 창이 정확히 1920×1080일 때 루트
글꼴 크기는 기본값 16px이 된다. 길이를 수로 나누는 계산이라 별도 지원 조건이
없다.

캔버스는 이 축척 단위로 크기를 잡는다.

```css
.game-canvas {
  width: 120rem;
  height: 67.5rem;
  container-type: size;
  container-name: game;
}
```

루트 글꼴 크기가 변하면 `rem`으로 쓴 모든 값이 같은 비율로 함께 변한다. 현재
CSS는 여백·글꼴·최소 높이·그리드 열 폭을 대부분 `rem`으로 쓰고 있으므로 이
한 줄이 전체 축척을 담당한다. 확대할 때 비트맵을 늘리는 것이 아니라 레이아웃을
다시 계산하므로 글자는 모든 배율에서 선명하다.

### 4.3 레터박스

```css
body {
  display: grid;
  place-content: center;
  min-height: 100vh;
  overflow: hidden;
  background: #000;
}
```

캔버스는 창보다 한쪽 축에서만 작으므로, 남는 공간은 위아래 또는 좌우에 검은
띠로 남고 캔버스는 두 축 모두 가운데에 놓인다. 레터박스 색은 화면 배경
(`#080604` 계열)과 구분되도록 순수 검정을 쓴다. 캔버스 경계가 어디인지
플레이어가 볼 수 있어야 하기 때문이다.

## 5. 뷰포트 단위 정리

### 5.1 구조 높이

캔버스 안에서 `100vh`는 창 높이를 가리키므로 더 이상 캔버스 높이가 아니다.
다섯 곳을 캔버스 기준으로 바꾼다.

| 위치 | 현재 | 변경 |
| --- | --- | --- |
| `app/globals.css:34` | `min-height: 100vh` | `min-height: 100%` |
| `app/globals.css:87` | `min-height: calc(100vh - 4.75rem)` | `min-height: calc(100% - 4.75rem)` |
| `app/u2-intro.css:3` | `height: 100vh` | `height: 100%` |
| `app/u3-board.css:3` | `height: 100vh` | `height: 100%` |
| `app/u3-board.css:13` | `height: 100vh` | `height: 100%` |

`app/page.tsx`의 `min-h-screen`도 같은 이유로 캔버스 높이를 따르게 바꾼다.

### 5.2 크기 계산 단위

`clamp()` 안의 `vw`·`vh`는 창 크기를 따라가므로 고정 캔버스와 어긋난다.
캔버스를 크기 컨테이너로 선언했으므로 컨테이너 질의 단위로 바꾼다.

```text
vw → cqw
vh → cqh
```

이 치환은 값을 바꾸지 않는다. 캔버스가 `120rem × 67.5rem`이므로 `1cqw`는
`1.2rem`, `1cqh`는 `0.675rem`이고, 기준 상태에서 각각 19.2px과 10.8px이다.
이는 1920×1080 창에서의 `1vw`·`1vh`와 정확히 같다. 즉 **오늘 1920×1080 창에서
보이는 화면이 그대로 모든 창 크기의 화면이 된다.**

값을 손으로 계산해 상수로 바꾸지 않는 이유가 있다. 치환 대상이 약 180곳이라
산술 오류가 섞이기 쉽고, `clamp(0.72rem, calc(0.58rem + 0.18vw + 0.12vh), 1.05rem)`
같은 식이 상수 하나로 바뀌면 그 값이 어떤 의도에서 나왔는지 읽을 수 없게 된다.
컨테이너 단위는 「캔버스 기준」이라는 뜻을 그대로 유지한다.

## 7. px 값 처리

`px`로 쓴 값은 74곳이고 성격이 갈린다. 속성별로 나누면 다음과 같다.

| 속성 | 개수 | 값 |
| --- | --- | --- |
| `border` 계열 | 36 | `1px` ×36, `2px` ×4, `999px` ×2 |
| `box-shadow` | 18 | 링 `1~5px`, 번짐 `12~80px` |
| `filter: drop-shadow` | 7 | `1~3px` |
| `outline` | 6 | `3px`, `outline-offset: 4px` |
| `text-shadow` | 3 | `1~2px` |
| `height`·`inset`·`transform` | 5 | `1px`, `-1px`, `5px` |

### 7.1 그대로 두는 값

`1px` 테두리 36곳, `height: 1px` 구분선, `translateY(-1px)` 호버 넘김,
`inset 0 0 0 Npx` 형태의 링 장식, `drop-shadow`와 `text-shadow`의 `1~3px`은
배율과 무관하게 물리 픽셀로 고정될 때 가장 선명하므로 그대로 둔다.

`border-radius: 999px` 두 곳은 알약 모양을 만드는 관용구라 값 자체가 배율과
무관하다. `outline: 3px` 포커스 링과 `outline-offset: 4px`도 두께가 일정한
편이 접근성에 낫다.

### 7.2 축척으로 옮기는 값

축척을 따르지 않으면 화면 밀도가 실제로 어긋나는 두 종류만 `rem`으로 옮긴다.

**나뭇결 무늬** — `app/u3-board.css:131`의 게시판 목재 질감이다.

```css
/* 현재 */
repeating-linear-gradient(0deg, #382313 0 4px, #2b190f 4px 8px, #321d10 8px 13px)
/* 변경 */
repeating-linear-gradient(0deg, #382313 0 0.25rem, #2b190f 0.25rem 0.5rem, #321d10 0.5rem 0.8125rem)
```

이것은 그림자가 아니라 구조다. 13px 주기가 고정되면 판이 커질수록 결이
촘촘해 보이고 작아질수록 성겨 보인다. 게시판 면적이 넓어 상대 밀도 변화가
바로 보인다.

**번짐 반경 12px 이상인 그림자 층** — 10곳이다. 링(번짐 0)은 건드리지 않고,
번짐이 큰 층만 그 층의 오프셋까지 함께 옮긴다.

| 위치 | 현재 | 변경 |
| --- | --- | --- |
| `app/u2-intro.css:21` | `0 2px 12px` | `0 0.125rem 0.75rem` |
| `app/u2-intro.css:107` | `inset 0 0 80px` | `inset 0 0 5rem` |
| `app/u3-board.css:27` | `0 2px 12px` | `0 0.125rem 0.75rem` |
| `app/u3-board.css:135` | `inset 0 0 38px` | `inset 0 0 2.375rem` |
| `app/u3-board.css:136` | `0 4px 18px` | `0 0.25rem 1.125rem` |
| `app/u3-board.css:177` | `inset 0 0 20px` | `inset 0 0 1.25rem` |
| `app/u3-board.css:195` | `0 5px 14px` | `0 0.3125rem 0.875rem` |
| `app/u3-board.css:214` | `0 0 14px` | `0 0 0.875rem` |
| `app/u3-board.css:587` | `0 0 12px` | `0 0 0.75rem` |
| `app/u3-u2-status-sync.css:9` | `0 2px 12px` | `0 0.125rem 0.75rem` |

`app/u2-intro.css:107`의 `80px` 인트로 배경 비네트와 `app/u3-board.css:135`의
`38px` 게시판 안쪽 어둠이 가장 크다. 판은 커지는데 번짐만 그대로면 가장자리
어둠이 상대적으로 얇아 보인다.

`app/u2-intro.css:211-214`의 모서리 장식 대각선은 `1px` 선을 `1rem` 칸에
그리는 형태라 칸이 함께 커지고 선만 1px로 남는다. 의도한 동작이므로 두었다.

### 7.3 브라우저 확대

브라우저 확대(zoom)는 CSS 픽셀 기준 창 크기를 바꾸므로 캔버스도 함께 커지거나
작아진다. 즉 확대해도 화면이 잘리지 않고 배율만 달라진다. 반대로 사용자가
설정한 기본 글꼴 크기는 루트 글꼴 크기를 우리가 덮어쓰므로 반영되지 않는다.
고정 캔버스 게임 화면에서는 의도한 동작이다.

- 1280×1024(5:4)에서 위아래에 검은 띠가 생기고 캔버스가 가운데 온다.

  서로 동일하다.
