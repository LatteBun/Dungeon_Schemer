# 불규칙 층 구조 지도 생성 설계

- 관련: [사건 행동과 자동 보스전](2026-08-15-sbh3821-event-action-boss-fight-design.md)

## 확정 방향

회의에서 정한 것을 그대로 옮긴다.

- 맵 형태가 불규칙해 보여야 한다
- 한 지점에서 다음 선택지는 **최대 2개**
- 갈라진 경로가 **나중에 다시 합쳐질 수 있다**
- 어느 루트를 골라도 보스까지 진행 횟수가 같다
- 등급별로 고정된 사건 진행 횟수를 둔다
- 층이 딱딱한 계단으로 보이지 않게 좌표를 흔든다

내부는 깊이가 일정한 그래프를 쓰되 화면에서는 동굴 길처럼 보이게 한다.

## 지금 구조가 맞지 않는 이유

현재는 입구에서 한 번 갈라져 끝에서 한 번 합친다.

```
입구 ──┬── 갈래1 (L칸) ──┬── 합류 ── 보스
       └── 갈래2 (L칸) ──┘
```

갈래가 **한 번만** 갈라지고 **한 번만** 합쳐지므로 다시 만나는 구조를 만들 수
없다. 층 개념이 없어 좌표를 흔들 기준도 없다. 갈래 길이를 늘리면 두 줄이 나란히
길어질 뿐 불규칙해지지 않는다.

## 새 구조: 깊이가 일정한 층 그래프

```
깊이 0        [입구]
깊이 1..D     사건 층. 층마다 지점 1~3개
깊이 D+1      [보스]
```

간선은 **깊이 i에서 깊이 i+1로만** 간다. 그래서 어느 길로 가도 보스까지 사건을
정확히 `D`번 지난다. "진행 횟수 동일"이 구조에서 저절로 나오고 따로 검사할 필요가
없다.

| 규칙 | 구현 |
| --- | --- |
| 선택지 최대 2개 | 지점의 나가는 간선 ≤ 2 |
| 다시 합쳐질 수 있다 | 들어오는 간선에 상한을 두지 않는다 |
| 진행 횟수 동일 | 간선이 깊이를 정확히 1씩 늘린다 |
| 불규칙한 모양 | 층 너비가 1~3으로 시드마다 변한다 |

### 등급별 수치

| 등급 | 경로 길이 `D` | 전체 사건 지점 `T` | 평균 층 너비 |
| --- | ---: | ---: | ---: |
| C | 5 | 7 | 1.4 |
| B | 7 | 10 | 1.4 |
| A | 9 | 13 | 1.4 |
| S | 11 | 16 | 1.5 |

전체 지점은 `T + 2`다(입구와 보스방). `D`는 플레이어가 실제로 겪는 사건 수이고
`T`는 지도에 그려지는 사건 지점 수다. 둘이 다른 것이 이번 변경의 핵심이다. 지금은
갈래가 하나뿐이라 두 수가 붙어 있었다.

## 층 너비 정하기

너비 `w_i`는 다음을 지켜야 그래프가 성립한다.

- `1 ≤ w_i ≤ 3`
- `w_1 ≤ 2` — 입구의 나가는 간선이 2개까지다
- `w_{i+1} ≤ 2 × w_i` — 층 i가 만들 수 있는 간선이 그만큼뿐이다

모든 층을 1로 시작해 `T - D`개를 시드로 고른 층에 하나씩 얹는다. 얹을 때마다 위
조건을 확인하고 어기면 다른 층을 고른다. 조건을 만족하는 층이 없으면
`RuleError("INVALID_GENERATION")`이다. 조용히 넓이를 줄이지 않는다.

## 간선 잇기

층 i에서 층 i+1로 이을 때 두 가지를 함께 만족해야 한다.

1. 층 i+1의 **모든 지점에 부모가 하나 이상** 있어야 한다. 아니면 닿을 수 없는 길이 생긴다
2. 층 i의 **모든 지점에 자식이 하나 이상** 있어야 한다. 아니면 막다른 길이 생긴다

먼저 층 i+1의 지점마다 부모를 하나씩 배정한다. 나가는 간선이 2개 미만인 부모
중에서 시드로 고른다. 그다음 아직 자식이 없는 층 i의 지점에 자식을 하나씩 준다.
마지막으로 여유가 있는 곳에 두 번째 간선을 시드로 더해 갈림길을 만든다.

두 번째 간선이 갈라짐과 합쳐짐을 동시에 만든다. 층 i의 두 지점이 층 i+1의 같은
지점을 가리키면 그 자리가 합류점이다. 합류점이 여러 곳 생길 수 있다.

## 사건 분류

경로마다 네 분류를 최소 한 번씩 지나야 한다. 그런데 갈래가 여러 번 갈라지면 실제
경로 수가 최대 `2^D`이라 전수 검사가 무겁다. S급이면 2048개다.

**보장 깊이 4개를 고정한다.** 깊이 넷을 골라 그 깊이의 모든 지점이 같은 분류를
갖게 하고, 네 깊이에 네 분류를 하나씩 준다. 간선이 깊이를 1씩 늘리므로 어느 길로
가도 그 네 깊이를 반드시 지난다. 커버리지가 구조에서 나오므로 경로를 세지 않는다.

나머지 깊이는 지점마다 시드로 분류를 정한다. 그래서 **갈래에 따라 만나는 사건
구성이 달라진다.** `E3` spec이 의도라고 적어 둔 편차가 유지된다.

분류를 뽑을 때는 풀에 남은 용량에서만 뽑는다. 분류마다 남은 수만큼 표를 넣고
섞어 쓰면 한 던전 안에서 같은 사건이 두 번 나오지 않는다.

## 사건 풀 확장

`한 던전 안에서 같은 사건 콘텐츠를 중복하지 않는다`를 유지하기로 했으므로 S급의
16개 지점을 감당할 풀이 필요하다.

| | 현재 | 확장 |
| --- | ---: | ---: |
| 분류당 | 3 | **5** |
| 전체 | 12 | **20** |

S급이 16개를 쓰므로 20개면 4개 여유가 남는다. 여유가 없으면 자유 깊이의 분류
선택이 한 가지로 정해져 시드가 의미를 잃는다.

새로 쓸 사건은 8개(분류당 2개)다.

## 정보 전달 기회

**깊이 단위로 표시한다.** 어느 길로 가도 각 깊이를 정확히 한 번 지나므로, 깊이에
표시하면 경로별 정보 횟수가 저절로 같아진다. 지금 규칙을 그대로 일반화한 것이다.

보스 관련 보장도 같은 방식으로 고른 정보 깊이의 부분집합이다.

한 깊이에 지점이 여럿이면 **그 깊이의 모든 지점**에 표시한다. 한쪽만 표시하면
경로별 횟수가 어긋난다.

## 경로 목록을 없앤다

`GeneratedMap.paths`를 지운다. 깊이로 표시하는 순간 **모든 경로가 같은 값**을
가지므로 목록이 같은 수를 여러 번 반복할 뿐이다. S급이면 최대 2048개를 담게 되고
10,000시드 백테스트가 그만큼 무거워진다.

대신 지도 자체에 값을 둔다.

```ts
interface GeneratedMap {
  grade: Grade;
  nodes: MapNode[];
  entryNodeId: NodeId;
  bossNodeId: NodeId;
  /** 어느 길로 가도 지나는 사건 수. 층 수와 같다. */
  regularEventCount: number;
  infoCount: number;
  bossRelatedInfoCount: number;
}
```

## 화면 좌표

`MapNode`에 `column`을 더한다. 층 안에서 몇 번째인지다. 규칙이 정하고 화면이 읽는다.

화면은 `column`으로 자리를 잡은 뒤 **지점 ID에서 뽑은 고정 난수로 흔든다.** 난수를
매번 새로 뽑으면 다시 그릴 때마다 지도가 출렁인다. ID에서 뽑으면 같은 지도는 항상
같은 모양이다.

흔드는 폭은 지점이 겹치거나 간선이 꼬이지 않을 만큼만 둔다. 층 구조는 유지하되
계단처럼 보이지 않는 것이 목적이다.

## 검증 규칙

- 지점 수가 `T + 2`이고 층 너비가 모두 1~3이다
- 모든 간선이 깊이를 정확히 1 늘린다
- 나가는 간선이 2개 이하이고 보스방만 0개다
- 모든 지점이 입구에서 닿고 모든 지점에서 보스방에 닿는다
- 한 깊이의 지점들은 정보 표시가 같다
- 보장 깊이 넷이 각각 한 분류로 통일돼 있고 네 분류가 모두 있다
- 지도 안에서 사건 ID가 중복되지 않는다
- 사건 수·정보 횟수·보스 보장이 등급 요구와 같다
