# C8-B Campaign History Events Specification

## 1. Overview

C8-B defines the campaign event history layer.

C8-A records quantitative campaign statistics from SettlementResult.
C8-B records typed campaign events generated by domain systems and provides data for Chronicle and telemetry.

```
E2/E3/E4/C5/C6/C7
        |
        v
CampaignEvent
        |
        v
CampaignHistory
        |
 +------+------+
 |             |
 v             v
Chronicle   Telemetry
```

## 2. Goals

- Store campaign events without changing game results.
- Provide a shared event model for player history and balance analysis.
- Generate turning points from event importance rules.
- Keep event ownership in source systems, not C8.

## 3. Non Goals

C8-B does not:

- decide gameplay outcomes
- create domain events itself
- calculate endings
- change campaign state
- render UI
- persist storage implementation

## 4. Storage Model

Campaign history is separated from statistics.

```ts
interface CampaignHistory {
  events: CampaignEvent[];
  turningPoints: TurningPoint[];
}
```

## 5. Typed Campaign Events

Events use discriminated unions instead of unknown payloads.

```ts
interface BaseCampaignEvent {
  id: string;
  type: CampaignEventType;
  campaignTurn: number;
  expeditionId?: string;
  actors: string[];
  importance: 'minor' | 'major' | 'turningPoint';
  createdAt: number;
}
```

## 6. Initial Event Types

### Advice

- ADVICE_ACCEPTED
- ADVICE_REJECTED
- ADVICE_SUSPECTED

### Boss

- BOSS_BATTLE_RESULT

### Promotion

- GUIDE_PROMOTED

### Trust

- TRUST_COLLAPSE

### Campaign

- CAMPAIGN_ENDED

## 7. Event Processing

Source systems create events.

```
Domain System
      |
      v
CampaignEvent
      |
      v
C8 Event Processor
      |
 +----+----+
 |         |
 v         v
History   TurningPoint
```

## 8. Turning Points

Turning points are derived data.

Examples:

- first trust collapse
- important character death
- major boss breakthrough
- campaign ending

## 9. Chronicle Generation

Events are stored immediately.
Chronicle presentation is generated from history when needed, especially at campaign end.

## 10. Integration Boundaries

### E2/E3/E4/C5/C6/C7

Generate domain events.

### C8-B

Stores, classifies, and derives history.

### U6

Consumes Chronicle data only.

### I1

Owns persistence implementation.

## 11. Test Requirements

- Event append preserves ordering.
- Typed events reject invalid payloads.
- Importance processing creates expected turning points.
- History remains separate from statistics.
- C8 processing never changes gameplay state.
