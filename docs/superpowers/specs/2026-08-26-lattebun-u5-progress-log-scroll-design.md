# U5 진행 기록 내부 스크롤 설계

## 문서 정보

- 작성자: LatteBun
- 작성 도구: Codex
- 작성일: 2026-08-26
- 대상: 던전 진행 화면의 `진행 기록` 탭
- 기준 브랜치: `main` (`ad02033`)

## 1. 목표

던전 진행 화면의 `진행 기록` 탭에서 기록이나 생태 내용이 하단 콘솔 높이를
넘어도 마지막 항목까지 확인할 수 있게 한다. 스크롤 조작은 제공하되 평소에는
스크롤바가 화면의 다크 판타지 금속 패널과 충돌하지 않게 숨기고, 사용자가 해당
영역을 가리키거나 키보드로 접근했을 때만 얇고 어두운 금속색으로 표시한다.

완료 목표는 다음과 같다.

- 전체·단서·전투 기록이 콘솔 높이를 넘으면 내용 목록만 세로로 스크롤한다.
- 생태 필터의 확인된 생태와 관찰 단서도 같은 방식으로 마지막 항목까지 읽힌다.
- 필터 행은 스크롤되지 않고 콘솔 상단에 남는다.
- 평소 스크롤바 thumb은 보이지 않고 hover·keyboard focus에서만 드러난다.
- 휠·트랙패드·터치·키보드로 스크롤할 수 있다.

## 2. 원인과 근거

현재 `.u5-log`는 `auto minmax(0, 1fr)` 두 행으로 필터와 내용 영역을 나눈다.
그러나 일반 기록 목록인 `.u5-log__entries`에 `overflow: hidden`이 지정되어 있어
두 번째 행의 높이를 넘은 항목이 잘린다. `.u5-ecology`도 같은 두 번째 행을
사용하지만 자체 세로 스크롤 계약이 없다.

근거 문서는 다음과 같다.

- `docs/GAME_PRINCIPLES.md` — 현재 원정에서 본 근거는 진행 기록에서 다시 확인할 수 있어야 한다.
- `docs/experience/SCREEN_LAYOUT.md` — 진행 화면의 40:60 구조와 진행 기록의 전체·단서·전투·생태 필터 계약.
- `docs/experience/ONBOARDING_AND_INTERFACE.md` — 공개 생태 규칙과 관찰 단서를 같은 화면의 진행 기록에서 다시 찾아볼 수 있어야 한다.
- `docs/experience/UI_IMPLEMENTATION_GUIDE.md` — 1920×1080 고정 캔버스와 내부 콘텐츠 overflow 검증 기준.

이번 변경은 U5 진행 기록의 표시와 조작만 다룬다. 기록 데이터 생성, 필터 판정,
게임 규칙, 진행 단계와 다른 화면의 스크롤 정책은 바꾸지 않는다.

## 3. 화면 동작

### 3.1 스크롤 경계

`진행 기록` 탭의 필터 행은 기존 첫 번째 grid 행에 둔다. 두 번째 행에서는 현재
필터에 따라 다음 중 하나만 독립 세로 스크롤 영역이 된다.

- 전체·단서·전투: `.u5-log__entries`
- 생태: `.u5-ecology`

콘솔 전체나 페이지를 스크롤하지 않는다. 따라서 상단 장면 40%, 하단 콘솔 60%,
`GameShell` 60:40과 고정 캔버스는 그대로 유지된다. 가로 스크롤은 만들지 않는다.

### 3.2 스크롤바 표현

두 내용 영역은 같은 스크롤바 시각 계약을 사용한다.

- 기본 상태: track과 thumb을 투명하게 두어 패널 안에서 보이지 않게 한다.
- `:hover`: 얇은 thumb을 어두운 금속색으로 표시한다.
- `:focus-visible`: hover와 같은 thumb을 표시하고 기존 화면 언어에 맞는 focus 단서를 제공한다.
- track은 계속 투명하게 유지한다.
- thumb은 둥글고 낮은 대비를 사용하며 금색 CTA처럼 강조하지 않는다.

Firefox 계열은 표준 `scrollbar-width`·`scrollbar-color`를 사용하고, WebKit 계열은
`::-webkit-scrollbar` 계열 선택자로 같은 표현을 맞춘다. 스크롤바 표시 여부는
콘텐츠 폭을 흔들지 않도록 두 상태에서 같은 얇은 폭을 유지하고 색만 바꾼다.

### 3.3 입력과 접근성

- 마우스 휠, 트랙패드, 터치 스와이프는 native overflow 동작을 사용한다.
- 기록 목록과 생태 영역은 키보드 초점을 받을 수 있어야 한다.
- 각 영역에는 현재 내용을 설명하는 accessible name을 제공한다.
- 초점이 들어온 뒤 방향키, Page Up·Page Down, Home·End 같은 브라우저 기본 스크롤 조작을 막지 않는다.
- JavaScript로 wheel·touch 이벤트를 가로채거나 스크롤 위치를 별도 상태로 저장하지 않는다.

## 4. 컴포넌트와 CSS 경계

`components/game/U5ProgressScreen.tsx`는 두 스크롤 영역에 키보드 접근성과 이름만
부여한다. 새 React 상태, effect, ref, 이벤트 핸들러는 추가하지 않는다.

`app/u5-progress.css`는 다음만 담당한다.

- `.u5-log__entries`의 `overflow: hidden`을 세로 자동 overflow로 교체
- `.u5-ecology`에 같은 세로 overflow 계약 적용
- 두 영역의 공통 overscroll·스크롤바·focus 표현

새 공용 스크롤 컴포넌트나 전역 scrollbar 규칙은 만들지 않는다. 다른 화면의
스크롤바 외형과 동작은 변경하지 않는다.

## 5. 경계 조건

- 내용이 영역보다 짧으면 스크롤 위치와 thumb이 생기지 않으며 기존 배치를 유지한다.
- 필터 전환 때 스크롤 위치를 별도 상태로 저장·복원하거나 강제로 초기화하지 않고
  브라우저의 native 렌더 동작을 따른다.
- 긴 한 줄 때문에 가로 스크롤을 만들지 않고 기존 grid의 `minmax(0, 1fr)`와 줄바꿈을 유지한다.
- 생태의 두 열은 함께 세로로 이동하며 각 열마다 중복 스크롤바를 만들지 않는다.
- 터치 환경처럼 hover가 없는 입력에서도 thumb 노출과 무관하게 내용 스크롤은 작동한다.
- 기록이 비어 있거나 생태 목록이 비어 있어도 빈 스크롤 껍데기나 별도 메시지를 추가하지 않는다.

## 6. 테스트 계약

### 6.1 자동 테스트

- 일반 기록 목록과 생태 영역 모두 `overflow-y: auto` 계약을 가진다.
- 두 영역의 기본 scrollbar thumb은 투명하다.
- hover와 focus-visible에서 같은 얇은 금속색 thumb이 나타난다.
- Firefox 표준 속성과 WebKit scrollbar 선택자가 함께 존재한다.
- 기록 목록과 생태 영역이 키보드 초점을 받을 수 있고 accessible name을 가진다.
- 기존 네 필터와 필터링 결과 렌더링은 변하지 않는다.

### 6.2 브라우저 검증

긴 진행 기록 fixture를 사용해 다음을 확인한다.

1. 1920×1080에서 필터 행은 고정되고 마지막 기록까지 휠로 이동한다.
2. 생태 필터도 두 열 전체가 함께 스크롤되어 마지막 단서까지 보인다.
3. 기본 상태에서는 스크롤바가 보이지 않고 hover와 keyboard focus에서만 얇게 보인다.
4. 키보드만으로 마지막 항목까지 이동할 수 있다.
5. 1440×900과 1280×1024에서도 고정 캔버스가 균일 축소되고 페이지 스크롤은 생기지 않는다.
6. 필터 전환, 조언 화면, 상단 장면과 우측 파티 패널에 배치 회귀가 없다.

관련 U5 테스트와 `pnpm typecheck`, `pnpm lint`, `pnpm build`, `git diff --check`를
검증한다. 게임 규칙과 수치를 바꾸지 않으므로 백테스트는 실행하지 않는다.

## 7. 완료 조건

- 진행 기록과 생태 내용이 콘솔 높이를 넘어도 마지막 항목까지 읽을 수 있다.
- 필터는 스크롤되지 않는다.
- 스크롤바는 기본 상태에서 눈에 띄지 않고 hover·focus에서만 얇게 드러난다.
- 마우스·트랙패드·터치·키보드 스크롤이 동작한다.
- 고정 캔버스, U5 레이아웃, 기록 데이터와 다른 화면에는 회귀가 없다.

## 8. 변경하지 않는 것

- 진행 기록 데이터, 정렬 순서와 필터 판정
- 조언·전투·생태 규칙과 캠페인 상태
- U5 장면·콘솔 40:60 비율과 `GameShell` 60:40 구조
- 행동 / 조언 탭, 우측 파티 카드와 CTA
- 다른 화면의 scrollbar 스타일
- 이미지와 기타 시각 에셋
