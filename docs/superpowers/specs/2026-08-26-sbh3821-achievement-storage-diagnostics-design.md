# 업적 화면 저장 진단 설계

- 작성일: 2026-08-26
- 작성자: sbh3821
- 작성 도구: Codex
- 영역: 업적 화면 · 캠페인 이어하기 · 버그 제보

## 1. 목적

진행 중 캠페인은 상태 스냅샷이 아니라 시드와 성공한 조작을 localStorage에 남긴다.
이 때문에 제보자가 새 판이라고 기억해도 실제로는 저장된 판을 이어 했을 수 있다.
개발자가 같은 상태를 재현하려면 브라우저 개발자 도구를 안내하지 않고도 저장 원문을
복사할 수 있어야 한다.

업적 화면의 우상단 `달성 N / 12`를 숨은 진단 진입점으로 사용한다. 짧은 시간 안에
다섯 번 누르면 앱 소유 저장을 읽어 보여 주고, 제보용 전체 복사와 캠페인만 초기화하는
동작을 제공한다.

## 2. 범위

### 포함

- 업적 독립 화면과 캠페인 내 업적 overlay의 공통 진단 진입점
- `dungeon-schemer.*` localStorage 키의 스냅샷
- 캠페인 시드, 액션 수, 최근 액션 요약
- 정상 JSON pretty print와 손상 원문 보존
- 전체 복사
- 확인을 거친 캠페인 진행 키 단독 삭제
- 초기화 성공 뒤 `/campaign` 새 진입
- 저장 접근·복사·삭제 실패 안내

### 제외

- 저장값 편집 또는 임의 키 삭제
- 업적, 오디오 설정, 업적 손상 백업 초기화
- 진단 정보의 서버 자동 전송
- sessionStorage, 쿠키, IndexedDB, 다른 origin 또는 앱 밖 localStorage 수집
- 현재 캠페인의 파생 `CampaignState` 전체 직렬화

## 3. 진입 계약

우상단 달성 수는 기존 `game-shell__status-chip` 모양을 유지하는 `button`이 된다.
첫 클릭부터 2초 안에 다섯 번째 클릭이 들어오면 진단을 열고 카운터를 초기화한다.
2초가 지나거나 컴포넌트가 사라지면 누적 클릭도 초기화한다. 일반 플레이에서 한두 번
누른 흔적이 나중 클릭과 합쳐져 열리지 않게 한다.

버튼의 접근성 이름은 보이는 달성 수를 그대로 설명한다. 히든 동작은 일반 사용자용
기능 안내에 노출하지 않는다. 다섯 번째 클릭에서만 localStorage를 읽으므로 서버
렌더와 초기 hydration 결과는 변하지 않는다.

## 4. 진단 데이터

진단 스냅샷은 현재 origin localStorage의 키를 열거한 뒤 이름이
`dungeon-schemer.`로 시작하는 항목만 키 이름 순서로 담는다. 알려진 키만 하드코딩해
읽지 않는 이유는 미래 버전 키와 손상 백업도 제보에 필요하기 때문이다. 반대로 prefix
밖의 항목은 같은 origin을 쓰는 다른 코드의 정보일 수 있으므로 포함하지 않는다.

각 값은 다음처럼 표현한다.

- JSON 파싱 성공: 구조를 보존한 pretty JSON
- JSON 파싱 실패: 원문 문자열과 `invalid-json` 상태
- 값 없음: 스냅샷에 포함하지 않음
- localStorage 접근 실패: 오류 이유만 표시하고 빈 값으로 위장하지 않음

`dungeon-schemer.campaign-run.v1`이 정상 객체면 `seed`, `actions.length`, 마지막
액션의 `type`을 요약한다. 구조가 다르거나 손상됐으면 원문은 보존하되 추측해서
요약하지 않는다.

복사 문자열에는 진단 포맷 버전, 수집 시각, 브라우저 user agent, 캠페인 요약,
앱 저장 원문을 넣는다. URL 전체는 query에 재현용 시드나 다른 값이 있을 수 있어
자동 수집하지 않는다. 복사는 사용자 클릭으로만 실행하고 네트워크 요청은 하지 않는다.

## 5. 진단 dialog

진단은 기존 업적 초기화와 같은 native modal dialog로 연다. 상단에는 캠페인 요약과
저장 접근 상태, 본문에는 스크롤 가능한 고정폭 원문을 둔다. 하단 버튼은 다음 세 개다.

1. `전체 복사`: 현재 dialog가 보여 주는 스냅샷을 clipboard에 복사한다.
2. `캠페인 초기화`: 즉시 삭제하지 않고 전용 확인 상태로 전환한다.
3. `닫기`: dialog를 닫는다.

Escape는 진단 또는 확인 상태를 닫는다. 복사 성공·실패는 `role="status"`로 알리며,
clipboard API가 없거나 거부돼도 dialog와 게임은 유지한다.

## 6. 캠페인 초기화

확인 문구는 진행 중 캠페인만 삭제되고 업적과 오디오 설정은 유지된다는 사실을
명시한다. 확인 시 기존 `clearCampaignRun`과 같은 캠페인 저장 경계를 사용해
`dungeon-schemer.campaign-run.v1`만 제거한다.

삭제 뒤 같은 키를 다시 읽어 실제로 사라졌는지 확인한다. 삭제가 성공하면
`window.location.assign("/campaign")`으로 문서를 새로 연다. query 없는 `/campaign`은
새 무작위 시드를 만들고, 저장된 판이 없으므로 인트로를 표시한다.

삭제 접근이 예외를 던지거나 키가 남아 있으면 이동하지 않는다. 실패한 삭제 뒤
이동하면 이전 캠페인이 다시 복원되어 초기화 성공처럼 보이기 때문이다. 업적 프로필,
업적 손상 백업, 오디오 설정 및 prefix 밖 키는 어떤 경우에도 삭제하지 않는다.

## 7. 코드 경계

- `lib/diagnostics/local-storage-diagnostics.ts`
  - prefix 기반 저장 수집, JSON 표시, 캠페인 요약, 복사 문자열 생성
  - 브라우저 전역 대신 작은 Storage 입력을 받아 순수하게 테스트
- `components/game/AchievementStorageDiagnostics.tsx`
  - 5회 트리거 이후의 native dialog, 복사, 확인, 삭제, 이동
- `components/game/AchievementScreen.tsx`
  - 달성 수 버튼과 진단 open 상태 연결
- `app/achievements.css`
  - 기존 업적 화면 재질을 계승한 dialog, 원문 영역, 상태와 위험 버튼
- 기존 `lib/store/campaign-run-storage.ts`
  - 캠페인 키와 삭제 함수를 단일 출처로 재사용하고 삭제 결과를 검증 가능하게 조정

진단 로직은 업적 Store에 넣지 않는다. 업적 상태와 브라우저 전체 앱 저장 진단은
수명과 책임이 다르며, 캠페인 초기화가 업적 reducer를 거치면 삭제 경계가 흐려진다.

## 8. 오류 처리와 보안

- localStorage 열거·읽기·삭제가 던져도 React render를 깨뜨리지 않는다.
- 손상된 값은 고치거나 덮어쓰지 않고 제보 원문으로만 보여 준다.
- 알려진 앱 prefix 밖 저장은 수집하지 않는다.
- 진단은 자동 업로드하지 않으며 복사 전에 원문을 화면에서 확인할 수 있다.
- 캠페인 삭제 실패는 이동을 중단하고 명시적으로 알린다.
- 업적 초기화 dialog와 캠페인 초기화 확인은 서로 독립된 상태로 관리한다.

## 9. 검증

### 순수 진단

- 앱 prefix 키만 정렬해 수집
- 정상 JSON pretty print와 손상 원문 보존
- 정상 캠페인의 시드·액션 수·최근 액션 요약
- 빈 저장, 손상 캠페인, 접근 예외
- 복사 payload에 진단 버전과 수집 정보 포함

### UI

- 네 번 클릭에는 열리지 않고 2초 내 다섯 번에서 열림
- 제한 시간이 지나면 클릭 수 초기화
- 독립 화면과 overlay에서 같은 dialog 렌더
- 전체 복사 성공·실패 상태
- Escape와 닫기
- 캠페인 초기화의 확인·취소

### 삭제 경계

- 캠페인 키만 삭제
- 업적, 오디오, 손상 백업, prefix 밖 키 보존
- 삭제 성공 뒤 `/campaign` 이동
- 삭제 예외 또는 잔존 키에서 이동하지 않음

### 전체

- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build --webpack`
- Chromium에서 업적 route와 캠페인 overlay를 열어 5회 진입, 복사, 초기화 확인 취소,
  테스트 저장을 둔 초기화와 새 인트로 이동을 검증
