## 1. 작업 분류와 목적

이 작업은 이미 구현된 U5 진행 화면 안에서 정보 위계를 다듬는 **범위가 제한된 UI 변경**이다. 새로운 흐름, 상태, 데이터 계약이나 게임 규칙을 추가하지 않는다.

목표는 다음 두 요소가 한눈에 들어오게 만드는 것이다.

1. 플레이어가 현재 보고 있는 콘솔 모드가 `행동 / 조언`인지 `진행 기록`인지 즉시 구분한다.
2. 조언을 고르기 전에 읽어야 하는 상황 지문을 독립된 정보 패널로 인식한다.

조언 카드는 숫자 제거 뒤 현재 형태가 승인되었으므로 이번 작업에서 재설계하지 않는다.

## 2. 저장소의 현재 상태

### `components/game/U5ProgressScreen.tsx`

- 콘솔 상단은 `.u5-console__tabs` 안의 실제 `button` 두 개로 구성된다.
- 활성 상태는 `is-active` class와 `aria-pressed`로 표시한다.
- 상황 지문은 `.u5-advice-mode` 안에서 단독 `<p className="u5-situation">`로 렌더링된다.
- 조언 목록은 상황 지문 다음에 온다.
- 조언 카드의 내부 `slot` 값은 선택 callback에만 쓰이고 화면 숫자로 표시되지 않는다.

### `app/u5-progress.css`

- `.u5-console__tabs`와 `.u5-log__filters`가 같은 버튼 규칙을 공유한다.
- `.u5-situation`은 별도 프레임 없이 텍스트만 표시한다.
- 조언 카드 목록과 금속 명패 스타일은 이미 별도 규칙으로 완성되어 있다.

따라서 이번 변경은 **탭 전용 스타일 분리 + 상황 패널 마크업과 스타일 추가**가 중심이다.

## 3. Brainstorming 결과

### 접근 A. 기존 `<p>`를 유지하고 CSS 장식만 추가

상황 문단에 border와 background를 직접 적용하고 `::before`로 `현재 상황`을 표시한다.

- 장점: JSX 변경이 가장 작다.
- 단점: 제목이 실제 문서 구조에 존재하지 않고, 접근성·테스트·긴 문장 배치가 불명확하다.

### 접근 B. 상황을 제목이 있는 독립 `<section>`으로 만든다 — **채택**

`현재 상황` 제목과 실제 상황 문장을 하나의 얕은 프레임 안에 묶는다. 탭은 별도 스타일로 분리하되 기존 버튼 동작을 유지한다.

- 장점: 사용자가 승인한 시안의 정보 위계를 가장 정확히 표현한다.
- 장점: 제목과 본문이 DOM에서도 분리되어 읽기 순서와 테스트가 명확하다.
- 장점: 조언 카드와 진행 기록 필터에 영향을 주지 않고 변경 범위를 격리할 수 있다.
- 단점: JSX에 작은 구조 변경이 필요하다.

### 접근 C. 공용 `FramedInfoPanel` 컴포넌트를 새로 만든다

상황 패널을 범용 컴포넌트로 추출해 다른 화면에서도 재사용한다.

- 장점: 이후 비슷한 패널이 늘면 재사용할 수 있다.
- 단점: 현재 확인된 재사용처가 없고, 단일 화면의 작은 표현 변경에 비해 추상화 비용이 크다.

**결론:** 접근 B를 사용한다. 새 공용 컴포넌트나 에셋은 만들지 않는다.

## 4. 승인된 시각 계약

```text
┌─────────────────────────────────────────────────────────────┐
│ [행동 / 조언] [진행 기록]                                  │
│                                                             │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ 현재 상황                                               │ │
│ │ 파티가 멈춰 있는 동안 바닥의 물높이가 조금씩 올라간다. │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│        [현재 승인된 조언 카드 3장, 변경하지 않음]           │
└─────────────────────────────────────────────────────────────┘
```

### 4.1 모드 탭

- 탭은 콘솔 좌측 상단에 작은 직사각형 버튼 두 개로 나란히 둔다.
- 두 버튼의 높이, 글자 크기, padding과 모서리 형태는 같다.
- 활성 탭은 금색 계열 테두리, 따뜻한 암금색 바탕, 밝은 글자로 표시한다.
- 비활성 탭은 어두운 바탕과 낮은 채도의 글자를 사용한다.
- 버튼 폭을 콘솔 전체에 균등 분배하지 않고 문구에 필요한 내용 폭만 사용한다.
- 아이콘, 숫자, 배지와 새로운 모션을 추가하지 않는다.
- hover와 `focus-visible`은 제공하되 활성 상태와 혼동되지 않아야 한다.

### 4.2 현재 상황 패널

- 탭 아래에 콘솔 폭을 사용하는 얕은 독립 프레임을 둔다.
- 프레임은 기존 다크 판타지 콘솔과 같은 어두운 갈색 바탕, 얇은 금색 계열 테두리와 매우 약한 안쪽 음영을 사용한다.
- 좌측 상단에 `현재 상황` 제목을 둔다.
- 제목 아래에 `progress.situation`을 표시한다.
- 제목은 강조색을 쓰되 카드 제목보다 강하게 보이지 않는다.
- 상황 본문은 사용자가 승인한 **2안 수준의 작은 크기**를 사용한다. 기존 1안처럼 큰 헤드라인으로 만들지 않는다.
- 구현 시작값은 다음 범위를 사용한다.
  - 제목: `clamp(0.68rem, 0.70cqw, 0.92rem)`
  - 본문: `clamp(0.74rem, 0.78cqw, 1.05rem)`
  - 본문 line-height: `1.45`
- 문장은 말줄임표로 자르지 않는다. 정상 콘텐츠는 줄바꿈으로 모두 읽을 수 있어야 한다.
- 패널은 남은 세로 공간을 늘려 채우지 않고 콘텐츠 높이만 사용한다.
- 제목의 브라우저 기본 margin은 제거한다. 제목 margin 때문에 얕은 패널의 높이가
  브라우저 기본값에 따라 달라져서는 안 된다.
- 패널이나 본문에 고정 높이, 최대 높이, `overflow: hidden` 또는 내부 세로 스크롤을
  추가하지 않는다.

#### 지원 콘텐츠 경계

이 문서에서 **정상 콘텐츠**는 구현 시점의
`lib/content/event-registry.ts`가 `allSituationEvents()`로 반환하는 공식
`SituationEvent` corpus에서 콘텐츠 검증을 통과한 모든 `description`을 뜻한다.
프리뷰 표본 한 건만 정상 콘텐츠로 간주하지 않는다.

- 공식 corpus에서 가장 긴 상황 문구도 1920×1080 캔버스에서 말줄임·잘림·내부
  스크롤 없이 모두 읽을 수 있어야 한다.
- 선택 전에는 상황 패널과 현재 조언 카드 세 장이 콘솔 경계를 넘지 않아야 한다.
- 선택 뒤에는 상황 패널과 `파티원별 반응 → 사건 결과 → 수치·신뢰 변화` 세 구역이
  콘솔 경계를 넘거나 서로 겹치지 않아야 한다.
- 이후 공식 콘텐츠가 추가되어 이 계약을 넘으면 문구를 조용히 자르거나 이번 UI에
  임의 스크롤을 추가하지 않는다. 회귀 테스트를 실패시켜 콘텐츠 길이 또는 U5
  레이아웃 계약을 별도 설계로 다시 검토한다.

이번 작업은 `SituationEvent.description`에 새 글자 수 제한을 추가하지 않는다.
고정 캔버스에서 임의 길이 문자열까지 모두 수용하는 것은 이 변경의 범위가 아니며,
현재 공식 corpus 전체를 빠짐없이 수용하는 것이 완료 기준이다.

### 4.3 조언 카드

이번 작업에서는 다음을 **그대로 유지한다**.

- 숫자 `1`·`2`·`3`을 표시하지 않는다.
- 현재 금속 명패 실루엣, 리벳, 이중 테두리, 높이와 중앙 정렬을 유지한다.
- 조언 문구, 구분선, 근거 문구의 현재 배치와 간격을 유지한다.
- 세 카드의 색, 크기, hover, focus와 비활성 표현을 동일하게 유지한다.
- `AdviceOption` 마크업과 `.u5-advice*` 스타일을 이번 변경의 조정 수단으로 사용하지 않는다.

상황 패널과 카드 사이가 좁거나 넓으면 `.u5-advice-mode`의 행 간격만 조정한다.

## 5. 컴포넌트와 DOM 계약

`U5ProgressScreen`의 상황 영역을 다음 구조로 만든다.

```tsx
<section className="u5-situation-panel" aria-labelledby="u5-situation-title">
  <h3 id="u5-situation-title" className="u5-situation-panel__title">
    현재 상황
  </h3>
  <p className="u5-situation" data-testid="u5-situation">
    {progress.situation}
  </p>
</section>
```

계약은 다음과 같다.

- `progress.situation`의 데이터 흐름은 바꾸지 않는다.
- 기존 `data-testid="u5-situation"`은 본문에 유지한다.
- 상황 패널은 조언 목록 또는 결과 영역보다 먼저 렌더링한다.
- 선택 전뿐 아니라 선택 뒤 결과를 보는 동안에도 현재 상황 패널을 유지한다.
- 선택 뒤 결과의 `Outcome` 마크업과 `.u5-outcome*` 조형 규칙은 변경하지 않는다.
  새 패널 때문에 공식 콘텐츠의 결과가 잘리면 구현을 계속 밀어 넣지 않고 설계
  범위를 다시 확인한다.
- 탭의 실제 `button`, click handler, `is-active`, `aria-pressed` 계약은 유지한다.
- 완전한 ARIA tabs 패턴을 도입하지 않는 한 `role="tab"`만 부분적으로 추가하지 않는다.

## 6. CSS 경계

### 전용 탭 규칙 분리

현재 결합된 다음 selector를 분리한다.

```css
.u5-console__tabs,
.u5-log__filters { ... }
```

`행동 / 조언` 탭 스타일을 바꿔도 진행 기록 내부의 `[전체] [단서] [전투] [생태]` 필터가 함께 변하지 않게 한다.

- `.u5-console__tabs`와 그 버튼은 승인 시안 전용 규칙을 가진다.
- `.u5-log__filters`는 현재 외형과 기능을 유지한다.
- 공통값을 유지할 필요가 있으면 CSS custom property나 여러 selector의 최소 공통 선언만 사용하고, 활성 상태의 시각 계약은 각각 독립시킨다.

### 상황 패널 규칙

새 규칙은 `app/u5-progress.css`의 U5 namespace 안에 둔다.

- `.u5-situation-panel`
- `.u5-situation-panel__title`
- `.u5-situation`

패널은 `box-sizing: border-box`, `min-width: 0`을 사용해 긴 한국어 문장이 콘솔 폭을 밀어내지 않게 한다.
제목은 `margin: 0`을 명시하고, 기존 `.u5-situation`의 `margin: 0`을 유지한다.
패널은 grid의 `auto` 행에서 콘텐츠 높이만 차지하며, 고정·최대 높이와 자체 세로
스크롤을 갖지 않는다.

상황 패널 추가 뒤 세로 간격이 부족하면 먼저 `.u5-advice-mode`의 행 간격과 상황
패널 자체 padding을 승인 범위 안에서 조정한다. 조언 카드나 결과 영역을 축소·절단해
공간을 만들지 않는다. 공식 corpus의 선택 전·선택 후 상태가 이 경계 안에서 맞지
않으면 범위를 넓혀 임의 수정하지 않고 설계를 다시 검토한다.

### 고정 캔버스

- 1920×1080 고정 캔버스와 GameShell 60:40을 바꾸지 않는다.
- 진행 화면의 장면 40%·콘솔 60%도 바꾸지 않는다.
- 크기는 기존 규칙대로 `rem`, `cqw`, `cqh`를 사용한다.
- `vw`, `vh`, 화면별 `@media`와 새 의존성을 추가하지 않는다.

## 7. 접근성

- 두 모드 전환은 계속 실제 `button`으로 조작한다.
- 활성 모드는 색뿐 아니라 `aria-pressed`와 테두리·바탕 차이로 구분한다.
- 키보드 `focus-visible` 외곽선은 금색 테두리와 겹쳐 사라지지 않아야 한다.
- `현재 상황`은 실제 heading이며 상황 본문과 `aria-labelledby`로 연결한다.
- 상황 본문과 카드 텍스트의 대비는 기존 parchment 계열 본문 대비보다 낮아지지 않는다.
- 프레임과 안쪽 음영은 장식이며 읽기 순서를 만들지 않는다.

## 8. 테스트 계약

### 렌더 테스트

`components/game/U5ProgressScreen.test.tsx`에 다음 계약을 추가하거나 보강한다.

1. `현재 상황` 제목과 `progress.situation` 본문이 같은 패널에 존재한다.
2. DOM 순서가 `콘솔 탭 → 현재 상황 패널 → 조언 목록 또는 결과`다.
3. `initialMode="advice"`에서 행동/조언 버튼이 활성이고, `initialMode="log"`에서 진행 기록 버튼이 활성이다.
4. 진행 기록 모드의 네 필터와 기존 로그 콘텐츠는 그대로 렌더링된다.
5. 조언 카드 숫자 제거와 동일 구조 테스트는 계속 통과한다.
6. `allSituationEvents()`에서 가장 긴 `description`을 구해 선택 전·선택 후 렌더의
   `data-testid="u5-situation"` 본문에 원문 전체가 보존되는지 확인한다. 시각적
   잘림은 아래 브라우저 containment 테스트가 담당한다.
7. 선택 후 DOM 순서가 `콘솔 탭 → 현재 상황 패널 → 결과 영역`이며 결과의 기존 세
   구역 마크업이 유지된다.

### CSS 계약 테스트

기존 source-level CSS 테스트 방식에 맞춰 다음을 확인한다.

1. `.u5-situation-panel`에 border, background와 padding이 존재한다.
2. 상황 제목과 본문에 서로 다른 typography 규칙이 존재한다.
3. `.u5-console__tabs`의 활성 스타일이 `.u5-log__filters` 활성 스타일과 독립되어 있다.
4. `.u5-advice__button`, `.u5-advice__content`, `.u5-advice__divider`의 조형 규칙은 변경하지 않는다.
5. `.u5-situation-panel`과 `.u5-situation`에 고정·최대 높이, `overflow: hidden`과
   자체 세로 스크롤 규칙이 없다.
6. `.u5-outcome*` 규칙은 이번 변경에서 수정하지 않는다.

### 브라우저 상호작용·containment 테스트

기존 source-level 검사만으로는 실제 click handler, 계산된 스타일과 고정 캔버스
안의 잘림을 확인할 수 없다. 기존 Playwright 방식에 다음 회귀 계약을 추가한다.

1. `/u5-test`에서 두 모드 버튼을 실제로 클릭해 표시 영역과 두 버튼의
   `aria-pressed`가 함께 전환되는지 확인한다.
2. 진행 기록으로 전환한 뒤 네 필터의 높이, padding, 글자 크기, 테두리, 배경,
   글자색과 활성 표현이 분리 전의 필터 전용 기준값을 유지하는지 computed style로
   확인한다.
3. `allSituationEvents()`에서 구한 가장 긴 상황 문구를 기존 E2E의 긴 카드 문구
   검증과 같은 DOM 주입 방식으로 선택 전·선택 후 프리뷰에 각각 넣는다. 이를 위해
   `/u5-test`의 공개 프리뷰 항목이나 제품 props를 추가하지 않는다.
4. 상황 패널·조언 목록·결과 영역의 bounding box가 콘솔 안에 있는지 확인한다.
   상황 패널, 결과 영역과 결과의 세 `.u5-outcome__step`은 각각
   `scrollHeight <= clientHeight`여야 한다. 내부 스크롤이나 상위 `overflow: hidden`으로
   잘림을 숨기지 않는다.
5. 작은 브라우저 창에서도 같은 검사를 수행할 필요는 없다. 기존 고정 캔버스
   회귀 테스트가 전체 캔버스의 균일 축소를 담당하고, 이 containment 검사는 공식
   1920×1080에서 수행한다.

### 실제 화면 검증

공식 1920×1080 캔버스의 실제 캠페인 진행 화면과 `/u5-test`에서 확인한다.

1. 콘솔 진입 시 활성 모드가 가장 먼저 구분된다.
2. 상황 지문이 카드와 분리된 정보 박스로 보이되 카드보다 과하게 크지 않다.
3. 한 줄과 두 줄 상황 문구 모두 잘리거나 겹치지 않는다.
4. 카드 세 장의 높이, 내부 구분선과 내용 배치는 변경 전과 같다.
5. 진행 기록 전환 후 `[전체] [단서] [전투] [생태]` 필터 외형이 회귀하지 않는다.
6. 작은 브라우저 창에서는 고정 캔버스 전체가 균일 축소되며 내부 레이아웃이 재배치되지 않는다.
7. 공식 corpus에서 가장 긴 상황 문구를 선택 전과 선택 후에 각각 표시해도 패널,
   카드와 결과가 콘솔 밖으로 나가거나 내부에서 잘리지 않는다.

## 9. 공식 문서 영향

이번 변경은 이미 `SCREEN_LAYOUT.md`가 정한 다음 계약을 더 잘 보이게 만드는 표현 변경이다.

- 행동/조언과 진행 기록 두 모드
- 상황 묘사를 조언보다 먼저 표시
- 같은 디자인의 조언 세 장

게임 규칙, 정보 공개 범위와 화면 비율은 바뀌지 않으므로 `GAME_PRINCIPLES.md`, 시스템 문서와 경험 문서 본문은 수정하지 않는다.

`docs/README.md`에는 승인된 이 spec과 이후 plan을 찾을 수 있도록 색인을 추가한다.
이는 공식 게임 규칙 변경이 아니라 문서 탐색 경로 갱신이다.

## 10. 범위 밖

- 조언 카드의 높이, 실루엣, 리벳, 구분선과 내부 간격 변경
- 카드 숫자 또는 다른 순서 표식 추가
- 상황 문구의 콘텐츠나 생성 규칙 변경
- `SituationEvent.description`의 글자 수 제한 추가
- 상황 패널 또는 행동/조언 모드에 새 세로 스크롤 UI 추가
- `Outcome` 마크업과 `.u5-outcome*` 조형 규칙 변경
- 진행 기록 필터의 기능·내용 변경
- 파티 상태, 전투 재생, 우측 CTA와 장면 슬롯 변경
- 새로운 공용 UI 컴포넌트, 이미지 자산, 아이콘 또는 의존성 추가
- 모바일·별도 반응형 레이아웃 도입

## 11. 완료 기준

- `행동 / 조언`과 `진행 기록`이 승인 시안처럼 작고 명확한 두 모드 버튼으로 보인다.
- 현재 모드가 색, 테두리, 바탕과 `aria-pressed`로 구분된다.
- 상황 지문이 `현재 상황` 제목을 가진 독립 패널 안에서 2안 수준의 본문 크기로 표시된다.
- 상황 패널은 조언 또는 결과보다 먼저 읽힌다.
- 공식 `SituationEvent` corpus에서 가장 긴 상황 문구도 선택 전·선택 후 모두
  말줄임, 잘림과 내부 스크롤 없이 읽힌다.
- 선택 후 결과 세 구역은 상황 패널 추가 뒤에도 콘솔 안에서 모두 보인다.
- 현재 승인된 숫자 없는 조언 카드와 내부 구분선 배치는 변하지 않는다.
- 진행 기록 필터와 기존 화면 동작이 회귀하지 않는다.
- 관련 렌더·CSS·브라우저 상호작용 테스트와 1920×1080 실제 화면 검증이 통과한다.
