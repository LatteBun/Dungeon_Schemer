# 일러스트 통합 메인 메뉴 설계

작성자: sbh3821  
작성 도구: Codex

## 1. 목적

루트 메인 메뉴 `/`를 사용자가 제공한 「용사님, 이쪽입니다」 완성 일러스트로
교체한다. 일러스트의 제목·고블린·작전판 구도를 그대로 살리면서, 이미지에 그려진
중앙 버튼 세 개는 장식으로 남기지 않고 실제 웹 컨트롤로 덮어 캠페인·업적·설정에
진입할 수 있게 한다.

## 2. 승인된 방향

- 원본 1536 × 1024 이미지의 하단을 잘라 16:9 장면으로 만든다.
- 크롭은 아래쪽만 제거한다. 좌하단 왕관·책·톱니 아이콘과 우하단 버전 문구는
  최종 이미지에 남기지 않는다.
- 이미지에 그려진 중앙 버튼 영역은 같은 계열의 불투명한 실제 버튼 세 개로
  정확히 덮는다. 투명 클릭 영역은 사용하지 않는다.
- 실제 버튼은 `캠페인 시작`, `업적`, `설정` 순서다.
- 메인 화면에서 기존 우상단 전역 퀵 메뉴 버튼은 중복 노출하지 않는다.

## 3. 이미지 계약

### 3.1 원본과 결과물

- 원본은 사용자가 이 작업 대화에 제공한 1536 × 1024 일러스트다.
- 결과물은 원본의 좌·우·상단을 보존하고 아래쪽 160px을 제거한 1536 × 864
  16:9 이미지다.
- 생성형 보정, 새 오브젝트 추가, 제목 재작성, 인물·조명·색감 변경은 하지 않는다.
- 최종 정적 자산은 `public/assets/main-menu/hero-this-way-main-menu.webp`에 둔다.
- 원본 PNG를 보존해야 할 경우 같은 폴더에 source 표기를 붙여 두되, 런타임에서는
  최적화한 WebP 하나만 사용한다.

### 3.2 화면 맞춤

- 메인 화면의 이미지 캔버스는 16:9를 유지하고 사용 가능한 화면 안에 온전히
  들어간다.
- 화면 비율이 16:9와 다르면 이미지를 확대해 일부를 버리지 않고 letterbox를
  허용한다. 인물·제목·버튼 좌표가 서로 어긋나는 것보다 빈 여백을 우선한다.
- 버튼 레이어는 이미지 캔버스와 같은 좌표계를 사용한다. 브라우저 viewport가
  아니라 이미지 캔버스에 대한 백분율로 배치한다.

## 4. 실제 메뉴 컨트롤

중앙의 이미지 버튼 세 개를 다음 실제 컨트롤이 덮는다.

| 버튼 | 동작 | 계약 |
| --- | --- | --- |
| 캠페인 시작 | `/campaign`으로 이동 | `prefetch={false}`를 유지해 실제 진입 시 새 시드를 만든다. |
| 업적 | `/achievements?returnTo=/`로 이동 | 독립 업적 route와 안전한 복귀 경로를 유지한다. |
| 설정 | 전역 퀵 메뉴를 연다 | route를 바꾸지 않고 기존 BGM·효과음·전투 속도 설정을 그대로 사용한다. |

버튼은 이미지 속 검은 금속 명패를 완전히 가리는 불투명 표면을 사용한다. 기본
상태는 원본과 최대한 같은 어두운 갈색·금색 테두리로 맞추고, hover·active에는
밝기와 미세 이동만 더한다. 포커스 상태에는 금색 바깥선이 분명하게 나타나야 한다.

업적 달성 수는 이미지와 새 버튼의 구도를 흐리지 않도록 메인 버튼에 표시하지
않는다. 업적 데이터와 업적 화면 자체는 변경하지 않는다.

## 5. 설정 메뉴 연결

`AppFrame`이 전역 퀵 메뉴의 open 상태를 계속 소유한다. 메인 메뉴는 문서 전역
이벤트나 DOM 탐색으로 다른 버튼을 대신 클릭하지 않는다. 작은 전용 context를 통해
`openQuickMenu()`를 받아 설정 버튼에서 호출한다.

같은 context는 `AppFrame` 내부에서만 실제 함수를 제공하고, 순수
`MainMenuScreen`은 테스트 가능한 `onOpenSettings` prop만 받는다. 이 경계로 화면
컴포넌트가 오디오 store나 전역 메뉴 구현을 직접 알지 않게 한다.

메인 route에서는 `GlobalQuickMenu`의 우상단 trigger를 시각적으로 숨기되 메뉴
패널과 설정 기능은 그대로 사용한다. 캠페인 화면에서는 기존 trigger를 계속
표시한다.

## 6. 접근성

- 메뉴 묶음은 `nav aria-label="메인 메뉴"`를 유지한다.
- 세 컨트롤은 실제 `<a>` 또는 `<button>`이며 키보드 Tab 순서는 화면의 위에서
  아래 순서와 같다.
- 이미지에 제목 글자가 들어 있어도 문서에는 `용사님, 이쪽입니다`라는 접근 가능한
  `<h1>`을 둔다. 시각적으로는 숨겨 이미지의 글자와 중복되지 않게 한다.
- 배경 이미지에는 별도 읽기 텍스트를 중복 제공하지 않는다.
- 설정 버튼은 `aria-haspopup="menu"`와 현재 전역 메뉴의 focus 복귀 계약을 따른다.

## 7. 반응형 동작

- 데스크톱 기준 1536 × 864에서 실제 버튼은 원본 중앙 버튼의 위치와 크기를 덮는다.
- 16:9 모바일 가로 화면에서는 같은 비율로 축소한다.
- 글자와 최소 터치 높이는 이미지 축소에 무조건 종속시키지 않는다. 버튼 높이는
  최소 44 CSS px을 지키며, 그 때문에 원본 영역보다 커질 때는 세 버튼 묶음을
  균등하게 확장한다.
- 세로 화면 처리는 기존 `ScreenFit`의 가로 전환 안내를 유지한다.

## 9. 테스트와 검증

1. 정적 렌더 테스트에서 캠페인·업적 링크와 설정 버튼, 접근 가능한 제목을 확인한다.
2. 설정 context 테스트에서 메인 설정 버튼이 기존 전역 퀵 메뉴를 열고 닫은 뒤
   trigger로 포커스를 돌려주는지 확인한다.
3. 기존 캠페인 링크의 `prefetch={false}`와 업적 `returnTo=/` 계약을 회귀
   검증한다.
4. Playwright로 1536 × 864와 대표 모바일 가로 viewport를 캡처한다.
5. 각 viewport에서 실제 버튼 경계가 이미지에 그려진 버튼 영역을 완전히 덮는지,
   좌하단 아이콘과 버전 문구가 보이지 않는지 확인한다.
6. 세 버튼을 실제로 눌러 캠페인 route, 업적 route, 전역 설정 메뉴가 각각 열리는지
   확인한다.
7. 전체 Vitest, TypeScript, lint, production build를 실행한다.

## 10. 완료 기준

- 메인 화면이 승인된 일러스트를 사용한다.
- 하단 아이콘과 버전 문구가 어느 지원 viewport에서도 노출되지 않는다.
- 이미지 속 중앙 버튼은 실제 버튼 세 개로 자연스럽게 덮인다.
- 캠페인·업적·설정 동작이 기존 데이터와 설정 상태를 훼손하지 않는다.
- 키보드와 터치 입력 모두에서 세 메뉴를 사용할 수 있다.
- 데스크톱과 모바일 가로 캡처에서 버튼과 배경의 좌표가 맞는다.
