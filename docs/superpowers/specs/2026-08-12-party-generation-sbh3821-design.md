# R1 파티 생성 규칙 설계

- 작성일: 2026-08-12
- 작성자: sbh3821
- 상태: 승인됨 (2026-08-12)
- 관련 작업: [프로토타입 작업 배정표](../../technical/PROTOTYPE_WORK_ASSIGNMENT.md)의 R1

## 목적

시드로 3~5명 파티의 직업·성격·초기 신뢰를 결정하고, 같은 시드가 같은 파티를 재현하는 순수 로직을 만든다. UI는 포함하지 않는다.

## 완료 기준 (배정표 기준)

시드로 3~5명의 직업·성격·초기 신뢰가 결정되고 재현되는 테스트 통과.

## 합의된 설계 결정

브레인스토밍(2026-08-12)에서 다음을 합의했다.

1. **직업 중복 불허**: 한 파티 안에서 같은 직업이 두 번 나오지 않는다.
2. **성격 중복 불허**: 한 파티 안에서 같은 성격이 두 번 나오지 않는다. 성격은 5종 고정이고 파티 최대 인원이 5명이므로 항상 가능하다.
3. **초기 신뢰 = 성격별 기본값 + 소폭 랜덤**: 성격이 시작 시점부터 체감되도록 한다.

## 초기 신뢰 잠정값

아래 수치는 **프로토타입 잠정값**이다. 공식 문서([파티와 신뢰](../../systems/PARTY_AND_TRUST.md))의 "초기값 미확정" 상태를 바꾸지 않으며, 밸런스 확정 전까지 코드 상수로만 관리한다.

| 성격 | 기본값 | 랜덤 폭 |
| --- | --- | --- |
| 의심 많음 `suspicious` | 35 | ±5 |
| 신중함 `prudent` | 45 | ±5 |
| 탐욕스러움 `greedy` | 50 | ±5 |
| 정의로움 `righteous` | 55 | ±5 |
| 충동적 `impulsive` | 60 | ±5 |

근거: 의심 많음은 높은 신뢰에 도달하기 어렵다는 시스템 문서의 방향을 시작값에도 반영한다. 충동적은 쉽게 믿는 성격으로 두어 대비를 만든다. 결과는 항상 `TRUST_MIN`~`TRUST_MAX`로 자른다.

## 인터페이스

```ts
// lib/rules/party.ts
export function generateParty(rng: Rng): PartyMember[];
```

- 재현성 규약에 따라 `Rng`를 인자로 받는다. 함수 안에서 `createRng`를 부르지 않는다.
- 호출 예: `generateParty(createRng(seed).derive("party"))`
- 반환된 파티원은 모두 `alive: true`.

## 생성 절차

1. 인원: `rng.int(PARTY_SIZE_MIN, PARTY_SIZE_MAX)` → 3~5명.
2. 직업: 직업 풀을 `rng.shuffle`한 뒤 앞에서 인원수만큼 사용. 풀 크기가 인원보다 작으면 오류를 던진다.
3. 성격: `PERSONALITIES`를 `rng.shuffle`한 뒤 앞에서 인원수만큼 사용.
4. 이름: 이름 풀을 `rng.shuffle`한 뒤 앞에서 인원수만큼 사용(중복 불허).
5. 초기 신뢰: 성격별 기본값 + `rng.int(-5, +5)`, `TRUST_MIN`~`TRUST_MAX`로 클램프.
6. `MemberId`: `member-1`부터 순번으로 부여. 시드가 같으면 전체 결과가 같으므로 순번으로 충분하다.

## 콘텐츠 데이터

직업은 열린 목록이므로 규칙과 분리해 데이터 파일로 둔다. Q1(콘텐츠 데이터 채우기)의 선행 작업을 겸한다.

- `lib/content/classes.ts`: 초기 직업 5종(전사·궁수·성직자·마법사·도적)의 `ClassDef` 배열
- `lib/content/names.ts`: 파티원 이름 풀(잠정 12개 이상, 한국어 표기)

성격별 기본 신뢰 상수는 규칙의 일부이므로 `lib/rules/party.ts`에 둔다.

## 테스트 계획

`lib/rules/party.test.ts`에 Vitest로 작성한다.

1. 같은 시드 → 두 번 생성한 파티가 깊은 비교로 동일하다.
2. 다른 시드 → 파티가 다르다(대표 시드 2~3쌍).
3. 인원이 항상 3~5명이다(여러 시드 반복).
4. 직업·성격·이름에 중복이 없다.
5. 초기 신뢰가 성격별 기본값 ±5 범위이고 `TRUST_MIN`~`TRUST_MAX` 안이다.
6. 모든 파티원이 `alive: true`다.
7. 직업 풀이 인원보다 작으면 오류를 던진다.

## 범위 밖

- 신뢰 증감 판정(R2), 정보 카드(R3), UI 연결(U1)

## 공식 문서 갱신

같은 변경 단위에서 [파티와 신뢰](../../systems/PARTY_AND_TRUST.md)의 파티 생성 절에 "한 파티 안에서 직업과 성격은 중복되지 않는다" 규칙을 추가한다. 잠정 수치는 공식 문서에 넣지 않는다.
