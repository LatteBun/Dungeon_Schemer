# F3-3 사막·묘지 조언 콘텐츠 설계

## 문서 목적

이 문서는 F3-3 사막·묘지 조언 콘텐츠의 최종 설계 원본이다. 구현 단계에서는 여기 적힌 40개 사건을 다시 창작하지 않고, ID·상황·조언·결과·source·연계·보스 정보를 그대로 데이터로 옮긴다.

F3-3은 원래 작업표의 테마당 16개 계약을 F3-2에서 확정한 대표 테마 계약과 맞춘다.

- 사막 일반 사건 12개: `monster`
- 사막 보스 정보 사건 8개: `special`
- 묘지 일반 사건 12개: `monster`
- 묘지 보스 정보 사건 8개: `special`
- 총 40개
- 각 테마는 F3-5에서 최종 30개로 확장할 때 10개를 추가한다.

F3-3은 새 조언 시스템을 만들지 않는다. F3-2가 만든 `AdviceSource`, `BossRule`, `targetBossId`, 테마 검증과 보스 정보 검증 계약을 그대로 재사용한다. 이번 작업에서 새로 만드는 것은 사막·묘지의 보스 특징과 전용 사건 데이터다.

플레이어에게는 `RuleId`, `BossRuleId`, `AdviceSource`, 도움·방해·중립 유형을 노출하지 않는다.

# 1. 설계 원칙

## 1.1 F3-2와 같은 사건 계약

모든 사건은 다음 구조를 따른다.

1. 상황에서 눈으로 확인할 수 있는 사실을 보여준다.
2. 고블린이 조언 3개를 제시한다.
3. 내부적으로 도움·방해·중립이 정확히 하나씩 존재한다.
4. 도움은 `consistent`, 방해는 `contradictory`, 중립은 `unrelated`다.
5. 도움·방해에는 source가 있고 중립에는 source가 없다.
6. 한 명이라도 조언을 수용하면 실행된다.
7. 아무도 수용하지 않으면 사건별 기본 결과로 넘어간다.

상황은 규칙의 정답을 직접 말하지 않는다. `모래도마뱀은 열을 좋아한다`가 아니라 `구름이 해를 가리자 바위 위 도마뱀의 움직임이 느려진다`처럼 관찰 장면으로 보여준다.

일반 사건의 기본 effect tag는 F3-2와 같은 패턴을 따른다.

- 도움: `support`
- 방해: `sabotage`
- 중립: `observe`

보스 정보 사건은 F3-2처럼 도움·중립에 `information`, 방해에 `sabotage`를 사용한다.

## 1.2 두 테마의 추론 정체성

### 사막 — 환경 변화와 흔적 해석

사막은 열기·물기·건조함·발자국·바람처럼 **환경이 계속 흔적을 바꾸는 테마**다.

- 그늘은 코브라에게 유리하지만 뜨거운 바위는 모래도마뱀에게 유리하다.
- 물기는 전갈의 굴을 암시하지만 완전히 마른 곳은 모래정령의 영역이 된다.
- 발자국이 없다고 안전하지 않다. 미이라는 원래 흔적을 남기지 않고 바람도 흔적을 지운다.

플레이어가 `어떤 환경인가`와 `흔적을 믿어도 되는가`를 함께 판단하게 한다.

### 묘지 — 감각의 반전과 대상 식별

묘지는 같은 행동이 어떤 언데드를 상대하느냐에 따라 반대로 작동하는 테마다.

- 작은 소리는 좀비에게는 큰 의미가 없지만 구울에게는 충분한 신호다.
- 빛은 해골 마법사를 끌어들이지만 스켈레톤 궁수는 그림자 속으로 숨게 만든다.
- 부장품은 경비의 존재를 암시하고, 그것을 훔치는 행위 자체가 수호자를 더 사납게 만든다.

플레이어가 `소리/빛/매장물`만 보는 것이 아니라 **지금 누구를 상대하는지까지 식별**하게 한다.

## 1.3 일반 사건 수량과 공급량

각 테마의 생태 규칙 6개는 기본 조언에서 정확히 다음 공급량을 가진다.

- 도움 2개 이상
- 방해 2개 이상

이번 12개 설계는 각 규칙이 도움 2개·방해 2개를 정확히 공급하도록 잡는다. 일부 후반 사건은 도움과 방해가 서로 다른 규칙을 참조하는 교차 추론 사건이다. 이런 사건은 E3에서 **참조된 모든 생태 규칙이 활성일 때만** 배치한다.

난이도는 새 데이터 필드로 만들지 않는다. 콘텐츠 작성 원칙으로만 기본 학습 → 예외/반전 → 복합 추론의 흐름을 둔다.

## 1.4 연계 콘텐츠

각 테마는 F3-2와 같은 연계 수량을 가진다.

- 약한 연계 1세트: 앞 사건의 `revealsClue`가 뒤 사건의 같은 outcome 슬롯을 더 구체적인 조언으로 교체한다.
- 강한 연계 2세트: 앞 사건이 단서를 주고 뒤 사건이 `requiresClue`로 그 단서를 요구한다.

강화판은 원래 슬롯의 outcome을 바꾸지 않는다.

## 1.5 보스 정보 사건

각 테마의 보스 4종은 보스마다 자유로운 성격의 BossRule 2개를 가진다. `공격 전조 + 약점` 같은 고정 카테고리는 만들지 않는다. 중요한 것은 두 특징 모두 **관찰 가능한 장면**으로 보여줄 수 있고 서로 다른 정보 가치를 갖는 것이다.

각 BossRule에는 보스 정보 사건 하나가 대응한다.

- 보스 4종 × BossRule 2개 = 테마당 8개
- 모두 `kind: "special"`
- 모두 `targetBossId` 필수
- 도움·방해는 대상 보스가 소유한 `boss` source만 참조
- 중립은 source 없음
- 모두 지연형
- 세 조언 모두 `bossDamageModifier`를 가짐
  - 도움: `-0.20`
  - 중립: `-0.10`
  - 방해: `+0.25`

보스별 퍼즐 내용은 달라도 전투 엔진은 분기하지 않는다.

# 2. 데이터 구조와 구현 경계

F3-3은 새 도메인 타입을 만들지 않는다. F3-2에서 이미 존재하는 아래 계약을 그대로 소비한다.

```ts
export type AdviceSource =
  | { kind: "ecology"; ruleId: RuleId }
  | { kind: "boss"; bossRuleId: BossRuleId };

export interface BossRule {
  id: BossRuleId;
  text: string;
}
```

사막·묘지 보스의 현재 `rules: []`를 이 문서의 BossRule 2개씩으로 채운다. 구현에서는 `DESERT_THEME`, `GRAVEYARD_THEME`를 테마 검증 호출에 사용할 수 있도록 export해야 한다. `THEMES`는 같은 객체를 계속 사용한다.

사건 데이터는 다음 위치를 기본으로 한다.

- `lib/content/events/desert-events.ts`
- `lib/content/events/graveyard-events.ts`

F3-2의 `spider-events.ts` 구조를 따르되, 단순히 helper 중복을 줄이기 위한 공용 리팩터링은 F3-3의 필수 목표가 아니다.

F3-3 범위 밖:

- 활성 생태 규칙 추첨과 조언 수용·의심·적발 판정 → E2
- 사건 중복 방지와 지도 배치, 교차 사건의 활성 규칙 필터, 연계 배치 → E3
- 보스 피해 modifier 실제 산술과 누적 상하한 → E4
- 보스별 AI·상태이상·전용 전투 엔진
- 화면 표현 → U5
- 공용 사건 확장 → F3-4
- 테마당 30개 확장 → F3-5

# 3. 사막 BossRule 8개

## 3.1 거대 전갈 자카르 — `boss-desert-1`

### `boss-zakar-burrow-trace`

**자카르가 숨어 있는 모래 위에는 꼬리 끝이 지나간 가느다란 홈이 남는다.**

플레이어에게는 평평한 모래 한가운데 뱀이 지나간 듯한 선이 이어지고 선 끝의 모래가 조금씩 들썩이는 장면으로 보여준다.

### `boss-zakar-emerge-gap`

**자카르는 모래에서 튀어나온 직후 몸을 다시 가다듬느라 잠깐 움직임이 멈춘다.**

모래를 뚫고 솟구친 뒤 집게와 다리를 크게 벌린 채 잠깐 굳는 장면으로 보여준다.

## 3.2 샌드웜 카르둠 — `boss-desert-2`

### `boss-kardum-sand-ridge`

**카르둠이 땅속에서 이동하면 실제 몸보다 조금 앞쪽의 모래가 먼저 솟아오른다.**

거대한 몸이 지나오기 직전 몇 걸음 앞의 모래가 먼저 길게 부풀어 오르는 장면으로 보여준다.

### `boss-kardum-landing-pause`

**카르둠은 모래 밖으로 크게 뛰쳐나온 뒤 다시 파고들기까지 잠깐 시간이 걸린다.**

몸이 바닥에 떨어진 뒤 몇 번 꿈틀거리지만 곧바로 모래 속으로 들어가지 못하는 장면으로 보여준다.

## 3.3 모래거신 오벨론 — `boss-desert-3`

### `boss-obelon-leg-collapse`

**오벨론은 다리의 돌 배열이 흐트러지면 거대한 몸의 균형을 쉽게 잃는다.**

발목 쪽 작은 돌 몇 개가 빠지자 상체가 크게 기울고 손으로 바닥을 짚는 장면으로 보여준다.

### `boss-obelon-rebuild-stones`

**몸에서 떨어져 나온 돌들은 잠시 뒤 다시 오벨론 쪽으로 끌려간다.**

바닥에 멈춘 돌조각들이 떨리기 시작한 뒤 몸 쪽으로 굴러가는 장면으로 보여준다.

## 3.4 스핑크스 네프리스 — `boss-desert-4`

### `boss-nephris-question-still`

**네프리스는 질문을 던진 뒤 답을 들을 때까지 먼저 움직이지 않는다.**

수수께끼를 던진 뒤 앞의 생물이 움직여도 대답이 나오기 전까지 앞발 하나 움직이지 않는 장면으로 보여준다.

### `boss-nephris-wrong-answer-tell`

**틀린 답을 들으면 공격하기 직전에 목의 장식과 눈이 먼저 빛난다.**

대답을 들은 뒤 고개를 기울이고 목의 금빛 장식과 두 눈이 동시에 번쩍인 다음 앞발을 드는 장면으로 보여준다.

# 4. 사막 일반 사건 12개

## DS01 — 움직이는 그늘

- ID: `desert-heat-moving-shadow`
- kind: `monster`
- theme: `desert`
- 난이도 역할: 기본 학습
- 도움/방해 source: `ecology / desert-heat`
- revealsClue: `clue-desert-cobra-shade`

**상황**

한낮의 햇빛이 폐허를 달구고 있다. 무너진 기둥 아래 좁은 그늘 속에서 가느다란 비늘 자국이 움직이다가 햇빛이 닿는 경계 바로 앞에서 멈춘다.

**도움**
- 선택지: `그늘을 피해 햇빛이 드는 쪽으로 돌아가세요.`
- 대사: `저 자국, 밝은 쪽으로는 안 나오네요. 조금 덥더라도 밖으로 돌아가죠.`
- 결과: `파티가 뜨거운 모래로 돌아가는 동안 그늘 속 코브라는 모습을 드러내지 않는다.`

**방해**
- 선택지: `그늘을 따라 빠르게 지나가세요.`
- 대사: `햇빛보다는 저쪽이 걷기 편하겠어요.`
- 결과: `파티가 그늘로 들어서자 돌 틈에서 코브라들이 몸을 일으킨다.`

**중립**
- 선택지: `방패를 낮게 들고 천천히 움직이세요.`
- 대사: `뭐가 튀어나올지 모르니 발밑부터 보죠.`
- 결과: `파티가 주변을 확인하며 큰 충돌 없이 폐허를 지난다.`

**아무도 믿지 않았을 때**

파티가 그늘과 거리를 두며 조심스럽게 폐허를 지나간다.

## DS02 — 천막 아래의 흔적

- ID: `desert-heat-torn-canopy`
- kind: `monster`
- theme: `desert`
- 난이도 역할: 규칙 재확인
- 도움/방해 source: `ecology / desert-heat`
- 약한 연계: `clue-desert-cobra-shade`가 있으면 도움 슬롯 강화

**상황**

찢어진 천막 하나가 바람에 흔들린다. 천막이 만든 그늘 안쪽에는 길게 끌린 자국이 여러 개 있지만, 바로 옆 햇빛 아래의 모래는 깨끗하다.

**도움**
- 선택지: `천막에서 떨어진 밝은 쪽으로 지나가세요.`
- 대사: `저 흔적이 전부 그늘 안에만 있어요. 가까이 갈 이유가 없어요.`
- 결과: `파티가 햇빛 아래로 크게 돌아 코브라의 영역을 피한다.`

**강화된 도움**
- 선택지: `천막 자체를 피해 햇빛 쪽 바위 능선으로 돌아가세요.`
- 대사: `아까도 비늘 자국이 그늘 끝에서 멈췄어요. 이번에도 그늘 자체를 피하죠.`
- source: `ecology / desert-heat`
- 결과: `파티가 코브라가 숨을 만한 그늘을 완전히 벗어난 바위 능선으로 안전하게 우회한다.`

**방해**
- 선택지: `천막 밑에서 잠깐 쉬었다 가세요.`
- 대사: `여기만큼 시원한 곳도 없잖아요.`
- 결과: `파티가 그늘에 들어서자 천막 아래 모래에서 코브라가 튀어나온다.`

**중립**
- 선택지: `천막을 걷어내고 주변부터 살펴보세요.`
- 대사: `가려진 게 많으니 그냥 치워버리죠.`
- 결과: `파티가 천막을 걷어내느라 시간을 쓰지만 주변 시야는 넓어진다.`

**아무도 믿지 않았을 때**

파티가 천막 주변을 멀찍이 돌아간다.

## DS03 — 달궈진 바위

- ID: `desert-lizard-heated-rock`
- kind: `monster`
- theme: `desert`
- 난이도 역할: 예외 학습
- 도움/방해 source: `ecology / desert-lizard-heat`

**상황**

햇볕에 달궈진 검은 바위 위에서 모래도마뱀 몇 마리가 몸을 납작하게 붙이고 있다. 구름이 해를 가리자 녀석들의 움직임이 눈에 띄게 느려진다.

**도움**
- 선택지: `구름이 해를 가린 사이 지나가세요.`

- 결과: `도마뱀들이 둔해진 사이 파티가 바위 지대를 빠져나간다.`

**방해**
- 선택지: `햇빛이 강한 바위 위로 바로 올라가세요.`

# 6. 묘지 BossRule 8개

## 6.1 스켈레톤 장군 바르칸 — `boss-graveyard-1`

### `boss-barkan-command-blade`

# 12. 검증과 완료 기준

F3-3 구현은 F3-2의 범용 검증기를 그대로 사용한다. 새로운 검증 의미를 추가하기보다 사막·묘지가 기존 계약을 모두 통과하는지가 핵심이다.

필수 테스트:

1. `DESERT_EVENTS`가 정확히 20개다.
   - `monster` 12
   - `special` 8
   - 모두 `theme === "desert"`
2. `GRAVEYARD_EVENTS`가 정확히 20개다.
   - `monster` 12
   - `special` 8
   - 모두 `theme === "graveyard"`
3. 사막·묘지 각각 4보스 모두 정보 사건이 정확히 2개다.
4. 사막·묘지 각각 6개 생태 규칙이 기본 조언에서 도움 2개·방해 2개 이상을 공급한다.
5. 사막·묘지 각각 약한 연계 1세트와 `requiresClue` 강한 연계 2세트가 존재한다.
6. 모든 보스 정보 사건은 도움 `-0.20`, 중립 `-0.10`, 방해 `+0.25` modifier를 가진다.
7. `validateSituationEvents(DESERT_EVENTS, DESERT_THEME)`가 통과한다.
8. `validateSituationEvents(GRAVEYARD_EVENTS, GRAVEYARD_THEME)`가 통과한다.
9. 테마 밖 ecology source와 다른 보스의 BossRule source는 기존 검증기에 의해 거부된다.
10. 기존 `SPIDER_EVENTS`, `SHARED_EVENTS` 테스트가 회귀 없이 통과한다.
11. 사막·묘지 보스의 `rules`가 보스마다 정확히 2개이며 ID 중복·빈 문구가 없다.

작업 배정표의 F3-3 완료 기준은 구현 시 다음 최신 계약으로 갱신한다.

> 사막·묘지 전용 사건이 각각 20개(일반 `monster` 12 + 보스 정보 `special` 8)이며, 각 생태 규칙이 도움 2개·방해 2개 이상을 공급하고 각 보스가 전용 정보 2개를 가진다. 테마별 약한 연계 1세트와 강한 연계 2세트가 존재하며 기존 테마·보스 source 검증을 통과한다.

`반드시 새로 만드는 것` 절에 남아 있는 `테마당 16개` 표현도 구현 커밋에서 20개 대표 콘텐츠 계약으로 맞춘다.

# 13. 최종 범위 요약

F3-3이 끝나면 세 테마는 동일한 대표 콘텐츠 계약을 갖는다.

| 테마 | 일반 사건 | 보스 정보 | 합계 | BossRule | 약한 연계 | 강한 연계 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 거미굴 | 12 | 8 | 20 | 8 | 1세트 | 2세트 |
| 사막 | 12 | 8 | 20 | 8 | 1세트 | 2세트 |
| 묘지 | 12 | 8 | 20 | 8 | 1세트 | 2세트 |

세 테마는 같은 도메인·검증·전투 modifier 계약을 사용하지만 플레이 감각은 다르다.

- 거미굴: 거미 습성의 직접 관찰과 예외
- 사막: 환경 변화와 흔적의 신뢰성 해석
- 묘지: 감각 정보의 반전과 대상 식별

이 차이는 콘텐츠에서만 만든다. E2/E3/E4에 테마별 전용 엔진을 추가하지 않는다.
