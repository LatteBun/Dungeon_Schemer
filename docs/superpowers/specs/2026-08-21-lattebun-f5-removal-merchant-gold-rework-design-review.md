# F5 제거·상인 골드 개입 Spec 자기검토 보정

이 문서는 `2026-08-21-lattebun-f5-removal-merchant-gold-rework-design.md`의 자기검토 결과를 고정한다. 충돌 시 이 문서의 결정이 우선한다.

## 1. 범위 검토

- 독립 아이템 시스템은 제거한다.
- merchant는 별도 상점/인벤토리 화면이 아니라 공용 사건의 한 종류다.
- 정보 판매는 merchant에서 제외한다.
- 지도 구조, 생태 규칙, 신뢰 반응 계약은 변경하지 않는다.
- 골드 승급 비용과 위험도별 계약 보상은 이 작업에서 변경하지 않는다.
- merchant 가격의 최종 미세조정은 B1 대상이지만, 구현 시작값도 outcome 편향이 없도록 아래 보정값을 사용한다.

## 2. 가격 편향 자기검토

원본 Spec 10절의 초안 가격을 그대로 세면 `harm`이 더 싼 사건이 과도하게 많아진다. 개별 사건만 보면 문제없지만, 30개 전체를 반복해서 보면 “싼 쪽이 방해일 가능성이 높다”는 메타 패턴이 생길 수 있다.

따라서 **가격은 정답을 직접 뜻하지 않지만, 전체 풀에서도 outcome과 가격의 상관을 최소화한다.**

따라서 가격만으로 outcome을 안정적으로 추측하기 어렵다.

B1에서 가격을 바꿀 때도 다음 가드를 유지한다.

- H가 더 싼 사건 수와 X가 더 싼 사건 수의 차이 `<= 4`
- H/X 평균 가격 차이 `<= 1G`
- 특정 가격대가 한 outcome에만 몰리지 않음

효과 강도가 이 기준과 충돌하면 효과 강도를 우선하되, 다른 사건 가격을 조정해 전체 편향을 상쇄한다.

## 3. 다음 전투형 효과 중첩 처리 고정

원본 Spec은 중첩 금지를 선언했지만, 이미 예약 효과가 있을 때의 처리 방식이 모호했다. 아래로 고정한다.

### 3.1 단일 슬롯

원정 상태에는 최대 하나의 `pendingMerchantEffect`만 존재한다.

- 즉시형 효과는 슬롯을 사용하지 않는다.
- 다음 전투형 효과는 슬롯을 사용한다.
- 즉시 + 다음 전투 복합 효과도 다음 전투 성분이 있으므로 슬롯을 사용한다.
- 슬롯은 다음 `monster` 사건 또는 보스전 1회 적용 후 즉시 비운다.
- 던전 종료 시 남아 있으면 폐기한다.

### 3.2 이미 슬롯이 차 있을 때

기존 효과를 새 효과로 교체하지 않는다.

- 다음 전투 성분이 있는 merchant H/X 선택지는 화면에 표시하지만 `효과 중복 불가`로 실행 불가 처리한다.
- 즉시형 H/X와 neutral은 그대로 사용할 수 있다.
- 다음 전투 성분이 있는 선택지를 숨기거나 다른 조언으로 교체하지 않는다.

### 3.3 merchant 사건 배치

`pendingMerchantEffect`가 존재할 때 E3는 **H/X 둘 다 다음 전투 성분만 가진 merchant 사건을 신규 배치 후보에서 제외**한다.

목적은 상인을 만났는데 유료 선택 두 개가 모두 시스템적으로 막혀 neutral밖에 고를 수 없는 죽은 사건을 줄이는 것이다.

H/X 중 하나라도 즉시형이면 사건은 배치 가능하다. 골드 부족 때문에 실제로 neutral만 가능해지는 것은 자원 부족의 결과이므로 허용한다.

## 4. 복합 효과 허용 범위

원본 Spec의 `M12 농축 영양식`처럼 하나의 선택이 `즉시 효과 + 다음 전투 1회 효과`를 함께 가질 수 있다.

따라서 merchant effect는 구현상 다음 세 형태를 표현할 수 있어야 한다.

1. 즉시형만
2. 다음 전투형만
3. 즉시형 + 다음 전투형

세 번째 형태도 장기 상태를 늘리는 것은 아니다. 다음 전투 성분은 동일한 단일 슬롯을 사용하고 1회 후 제거된다.

## 5. 결제 시점 검토

결제는 **플레이어가 조언 버튼을 누른 시점이 아니라 조언이 실제 실행된 시점**이다.

현재 조언 계약과 맞춰 다음처럼 처리한다.

- H/X 선택 → 가격 확인
- 골드 충분 → 파티원 반응 판정 진행
- 한 명 이상 수용 → 거래 실행 → 골드 차감 → 효과 적용
- 전원 의심 → 기본 결과 → 골드 차감 없음
- 방해 적발 → 거래 실행 안 됨 → 골드 차감 없음

이 원칙을 지켜야 길잡이가 직접 물건을 사서 강제로 먹이는 캐릭터로 바뀌지 않는다.

## 6. neutral 계약 검토

merchant의 neutral은 다른 공용 사건의 일반 neutral과 달리 **의도적으로 효과 없음**으로 좁힌다.

- 비용 `0G`
- 거래하지 않음
- merchant 고유 효과 없음
- 즉시 신뢰 변화 없음

단, 조언 시스템 자체의 수용/의심 흐름과 기본 결과 계약은 유지한다.

## 7. 기존 merchant 재작성 검토 기준

30개를 새로 쓸 때 기존 제목을 보존하는 것이 목표가 아니다. 아래 우선순위를 따른다.

1. 새 merchant 정체성에 맞는가
2. H/X가 실제로 플레이어 골드를 사용해 파티 결과를 바꾸는가
3. N이 구매하지 않기로 자연스럽게 읽히는가
4. 인벤토리나 장기 아이템 상태를 암시하지 않는가
5. 다른 merchant와 효과·상황이 중복되지 않는가
6. 기존 제목/소재를 살릴 수 있으면 그때 재사용한다

`저울`, `거스름돈`, `묶음 할인`처럼 계산·사기 판별 자체가 핵심인 기존 사건은 이 기준을 만족하지 않으면 교체한다.

## 8. 테스트 가드 추가

구현 테스트에는 원본 Spec의 수용 기준과 함께 다음을 추가한다.

- merchant 30개 H/X 가격 분포가 outcome 편향 가드를 만족함
- `neutral.goldCost === 0` 30건
- H/X `goldCost > 0` 60건
- 골드 부족 H/X 실행 거절
- 전원 의심 시 골드 변화 없음
- 방해 적발 시 골드 변화 없음
- 수용 실행 시 정확히 한 번만 골드 차감
- pending merchant effect 최대 1개
- 다음 전투 1회 후 pending effect 제거
- pending 상태에서 delayed H/X 비활성화
- pending 상태에서 H/X 둘 다 delayed-only인 merchant가 배치 후보에서 제외됨
- 던전 종료 시 pending effect 폐기

## 9. 최종 구현 입력

구현 Plan은 원본 Spec과 이 보정 문서를 함께 입력으로 사용한다.

핵심은 다음과 같다.

```text
F5 삭제

merchant = 골드를 써서 현재 파티에 개입하는 사건

H = 유료 도움
X = 유료 방해
N = 무료 비구매

인벤토리 없음
정보 판매 없음
즉시 또는 다음 전투 1회만
가격은 효과 강도 기반 + 전체 풀 outcome 편향 방지
```
