# 지도 우선 탐험 시작 설계

## 메타데이터

- 작성자: LatteBun
- 작성 도구: Codex
- 상태: 승인된 설계

## 문제

공고에서 계약을 수락하면 캠페인 전이가 입구 노드의 사건을 자동 처리해
`/play/encounter`로 이동한다. 그러나 공식 게임 루프는 계약 확인 뒤 공개된
지도를 먼저 보고 길잡이가 다음 지점을 선택하는 흐름을 정의한다. 입구 사건을
자동 발생시키는 현재 구현은 설정집과 화면 경험을 어긋나게 한다.

## 목표와 비목표

목표:

- 계약 수락 직후 캠페인 단계를 `map`으로 유지한다.
- 입구를 지도에 표시하되 사건·정보 전달 기회를 발생시키지 않는 탐색 시작점으로 만든다.
- 첫 갈래 노드를 선택했을 때부터 정보 기회 또는 사건 처리를 시작한다.
- 지도 구조, 시드 재현성, 두 갈래 대칭성은 유지한다.
- 정보 기회 수는 등급별 C/B/A/S `2/3/4/5`를 유지한다.
- 실제 경로 일반 사건 수는 입구 사건 제외로 `3/4/5/6`으로 명시한다.

비목표:

- 새로운 캠페인 단계나 저장 포맷을 추가하지 않는다.
- 입구의 시각적 노드, 전체 지도 공개, 보스 자동전투 규칙을 변경하지 않는다.
- 사건 콘텐츠 자체와 개인별 반응 계산을 변경하지 않는다.

## 상태 전이

```text
campaignBoard
  --acceptContract--> map (currentNodeId = node-entry)
  --selectNode(first branch node)--> infoOpportunity | event
  --resolve event/info--> map
  --selectNode(...)--> ...
```

`acceptContract`는 지도 생성과 원정 초기화만 수행한다. 입구를 `arriveAt`에
통과시키지 않으며, `visitedNodeIds`는 비워 둔다. `selectNode`만 실제 도착을
기록하고 기존 정보·사건·보스 분기를 사용한다. 입구를 직접 선택하는 액션은
기존처럼 거부한다.

## 지도·콘텐츠 계약

- 지도 전체 지점 수는 기존 `2 * branchLength + 3`을 유지한다.
- 입구에는 기존 타입 호환을 위해 사건 콘텐츠 ID를 보관할 수 있지만 플레이 중
  해당 사건을 자동 실행하지 않는다.
- 정보 슬롯은 입구를 제외한 각 깊이와 합류 지점에서 선택한다. 따라서 등급별
  정보 기회 수 `branchLength`를 유지하면서 도달 불가능한 입구 정보가 생기지
  않는다.
- 경로의 `regularEventCount`는 보스방과 입구를 제외한 실제 사건 지점 수로
  계산한다. 기대값은 `branchLength + 1`이다.
- 사건 풀 용량 검사는 입구용 사건을 더 이상 소비하지 않으므로 경로당 필요한
  일반 사건 수를 `2 * branchLength + 1`로 계산한다.

## 화면 계약

`phase-route`는 계약 수락 직후 `/play/map`을 선택한다. 지도 화면은 현재
지점이 입구임을 표시하고 첫 갈래 노드 선택을 활성화한다. 사용자가 노드를
선택하면 기존 `infoOpportunity`/`event` 화면과 결과 후 지도 복귀가 그대로
동작한다.

## 오류·재현성

- 입구 자동 도착을 제거해도 지도 생성 RNG 소비 순서는 유지한다.
- 같은 캠페인 시드와 같은 첫 노드 선택은 같은 사건·정보 결과를 만든다.
- 잘못된 노드 선택, 중복 계약, 콘텐츠 부족은 기존 `RuleError` 계약을 따른다.

## 검증 기준

- `acceptContract` 직후 `phase === "map"`, `currentNodeId === entryNodeId`,
  `visitedNodeIds`·pending 상태가 비어 있다.
- 첫 갈래 선택 시 해당 노드의 정보 또는 사건 단계에 도달한다.
- C/B/A/S 지도 생성·검증과 E1 스냅샷이 새 사건 수를 반영한다.
- 동일 시드 백테스트와 기존 캠페인/정보/정산 테스트가 통과한다.
- lint, typecheck, 전체 테스트, Next build가 통과한다.
