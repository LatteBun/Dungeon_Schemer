## 1. 문서의 지위

이 문서는 [B1-B 캠페인 생존 밸런스 재설계](2026-08-24-lattebun-b1-balance-redesign-design.md)를
보강한다. 기존 B1-B의 실제 Store driver, 세 전략, 추론 정확도, 조언 압력,
완주율·전멸 gate와 calibration/holdout 분리는 유지한다.

다만 기존 설계에는 위험도별 던전 클리어율 목표가 없고, 보스 배율 조정 범위
`0.75~0.85`가 모든 위험도에 동일하게 적용되어 현재 확인된 ★3~5 병목을 해소하기
어렵다. 이 문서는 다음 항목을 추가하거나 대체한다.

- B1-B 설계 5장의 보스 배율 calibration 범위
- B1-B 설계 10장의 calibration 판정 절차
- B1-B 설계 11장의 위험도별 지표
- B1-B 설계 13.4의 백테스트 gate

그 밖의 B1-B 규칙과 완료 조건은 그대로 유효하다.

## 2. 배경과 최종 검토

사용자 플레이와 600캠페인 진단에서 ★3 이상 보스가 진행을 거의 막는 현상이
확인됐다. 최신 B1-B 50시드 구조 보고서도 같은 방향을 보인다.

기회주의적 균형·정확도 0.7의 보스 진입 HP 비율은 평균 `0.9081`이다. 위험도별
보스 결과는 다음과 같다. 이 값은 재도전을 포함한 보스 진입 기준 진단값이며 새
합격선 자체는 아니다.

| 초기 위험도 | 보스 클리어/진입 | 보스 진입 후 클리어율 |
| --- | ---: | ---: |
| ★1 | 109/109 | 100.0% |
| ★2 | 194/241 | 80.5% |
| ★3 | 83/308 | 26.9% |
| ★4 | 1/114 | 0.9% |
| ★5 | 0/3 | 0.0% |

보스 진입 시점에 파티 HP가 대부분 남아 있는데 ★3부터 승률이 급락하므로, 현재
우선 원인은 일반 구간의 누적 피해보다 보스 전투력이다. 따라서 첫 calibration은
일반 몬스터, 월드턴, 조언 압력, 회복 경제를 동시에 바꾸지 않고 초기 위험도별
보스 공통 배율만 조정한다.

또한 보스는 현재 위험도가 아니라 던전의 초기 위험도로 정해진다. 재도전 뒤 표시
위험도만 오른 시도를 원래부터 높은 위험도의 던전과 섞으면 난이도 곡선의 의미가
흐려진다. 주지표는 던전별 첫 시도와 초기 위험도를 사용하고, 모든 재도전과 현재
위험도 기준 값은 보조 진단으로 분리한다.

## 3. 목표와 비목표

### 3.1 목표

- 저위험 던전은 대부분 통과하지만 자동 성공은 아닌 구간으로 만든다.
- 초기 위험도가 높아질수록 첫 시도 클리어율이 단계적으로 낮아지게 한다.
- 던전 시작, 보스 진입, 보스 결과를 분리해 실패가 일반 구간과 보스 중 어디서
  발생했는지 측정한다.
- 같은 revision과 시드에서 같은 결과를 재현하며 calibration 결과를 이전 값과
  비교할 수 있게 한다.
- 기존 캠페인 완주율·전멸·전략 차이 gate와 위험도별 곡선을 함께 만족시킨다.

### 3.2 비목표

- 파티 능력 성장, 새 장비, 부활, 후퇴, 난이도 선택 UI를 추가하지 않는다.
- 보스별·테마별 전용 보정값을 추가하지 않는다.
- 보스의 고유 규칙, 표적 성향, 보스 정보 효과와 전투 연출을 바꾸지 않는다.
- 이번 첫 calibration에서 일반 몬스터, 월드턴, 조언 압력, 상인·회복 경제,
  승급·보상·엔딩 수치를 바꾸지 않는다.
- 자동 플레이 전략이 숨은 조언 정답이나 미공개 상태를 읽게 하지 않는다.

## 4. 지표 정의

### 4.1 원정 attempt

`attemptNumber`는 한 캠페인에서 같은 `dungeonId`에 시작한 원정을 1부터 세는
값이다. 첫 계약은 1이고 전멸 뒤 같은 던전에 다시 들어가면 2 이상이다.

각 원정 trace는 다음 값을 기록한다.

- `initialRiskLevel`: 캠페인 생성 때 고정된 던전 위험도
- `currentRiskLevel`: 해당 원정을 시작할 때 게시판에 표시된 현재 위험도
- `attemptNumber`: 같은 던전의 1부터 시작하는 시도 번호
- `bossEntry`: 기존 생존 인원·현재 HP·최대 HP·조언 압력
- `result`: `cleared`, `wiped`, 또는 원정 중 캠페인 종료를 나타내는 `interrupted`

원정 도중 불신 등으로 캠페인이 즉시 종료되어 정산하지 못한 경우를 누락하거나
클리어로 보지 않는다. `interrupted`로 집계하고 클리어율 분모에는 포함한다.

### 4.2 주지표

`firstAttemptClearRateByInitialRisk`는 다음과 같이 계산한다.

```text
초기 위험도 R 던전의 attemptNumber === 1인 cleared 수
------------------------------------------------------
초기 위험도 R 던전의 attemptNumber === 1인 시작 수
```

한 캠페인에서 같은 던전의 재도전은 이 지표에 한 번도 추가되지 않는다. 캠페인
종료 전에 한 번도 선택하지 않은 던전도 분모에 넣지 않는다.

기준 조합은 코드의 `opportunist@0.7`, 문서 표현으로 기회주의적 균형·추론
정확도 0.7이다. 공개 정보를 비교적 잘 활용하는 일반 플레이 기준으로 사용한다.

### 4.3 보조지표

- 초기 위험도별 첫 시도 보스 도달률: `boss entries / starts`
- 초기 위험도별 첫 시도 보스 전환율: `clears / boss entries`
- 초기 위험도별 첫 시도 보스 진입 HP 비율과 생존 인원
- 현재 위험도별 전체 시도 클리어율: 재도전의 정보 감소 영향을 포함
- 초기 위험도별 최종 통과율: 한 번 이상 시도한 고유 던전 중 캠페인 종료 전
  결국 클리어한 비율
- 초기 위험도·테마별 시작, 보스 진입, 클리어, 전멸, 중단
- 전략·정확도별 위험도 곡선과 표본 수

각 위험도에서 실패를 다음 두 몫으로 함께 표시한다.

```text
보스 전 실패 몫 = (시작 - 보스 진입) / 시작
보스 실패 몫    = (보스 진입 - 클리어) / 시작
```

이를 통해 던전 클리어율 저하를 보스 수치로 조정할지, 별도 일반 구간 설계가
필요한지 판단한다.

## 5. 위험도별 목표 곡선

최종 calibration과 holdout에서 `opportunist@0.7`의 주지표는 다음 포함 구간을
만족해야 한다.

| 초기 위험도 | 첫 시도 던전 클리어율 목표 |
| --- | ---: |
| ★1 | 80~90% |
| ★2 | 65~75% |
| ★3 | 50~60% |
| ★4 | 35~45% |
| ★5 | 20~30% |

구간이 겹치지 않으므로 모든 gate를 통과하면 위험도가 높아질수록 클리어율이
낮아지는 단조 곡선도 자동으로 만족한다. 관측값이 구간 안에 있더라도 위험도 간
역전이 발생하면 표본·집계 오류로 보고 gate를 실패시킨다.

다른 전략과 정확도의 위험도별 값은 우선 관찰 지표다. 기존 B1-B의 전략별 캠페인
완주율, 완료 캠페인 전멸 평균, 정확도 적중률, 배신 완주 가능성 gate는 대체하지
않고 모두 함께 적용한다.

## 6. 표본과 판정

### 6.1 단계별 사용

- 조합당 50시드 구조 검증: 지표 누락·오류·극단값을 확인하며 목표 곡선은 판정하지
  않는다.
- 조합당 100시드 1차 보정: 후보 배율의 방향을 정하는 관찰값으로 사용한다.
- 조합당 200시드 최종 calibration: 위험도별 목표와 기존 B1-B gate를 판정한다.
- 조합당 2,000시드 holdout: 동결된 수치와 gate를 한 번 최종 판정한다.

최종 calibration에서 위험도별 첫 시도 표본이 30개 미만이면 해당 gate는 통과가
아니라 `insufficient-evidence`로 실패한다. holdout에서는 300개 미만을 같은 방식으로
실패 처리한다. 표본이 부족하다고 다른 전략이나 재도전 표본을 합쳐 분모를 늘리지
않는다.

비율 gate는 관측 비율 자체로 판정하고 Wilson 95% 구간을 불확실성 설명으로 함께
보고한다. 기존 정확도 적중률의 Wilson 99.9% 판정은 그대로 유지한다.

### 6.2 calibration과 holdout 격리

현재 `b1b-calibration-v1`은 수치 탐색용으로 계속 사용할 수 있다. 이 문서의
지표와 gate는 holdout을 보기 전에 확정되므로 데이터 누출이 아니다.

`B1B_HOLDOUT_APPROVED`는 최종 calibration 결과와 설정 revision을 사용자가 승인할
때까지 `false`로 유지한다. holdout 결과를 본 뒤 어떤 수치나 합격선을 바꾸면
`b1b-holdout-v1`을 폐기하고 새 namespace를 사용한다.

## 7. 보스 배율 calibration

초기 위험도별 보스 배율은 현재처럼 보스 원본 HP와 기본 피해에 함께 한 번만
적용한다. 현재 위험도, 재도전 횟수, 테마에 따른 추가 배율은 만들지 않는다.

첫 탐색은 현재 설정에서 시작하고 위험도 하나씩 낮은 단계부터 조정한다. 후보값은
`0.20~1.20` 범위의 `0.025` 단위만 사용한다. 범위는 탐색 안전선이지 최종값이
아니며, 최종 설정에는 실제로 선택한 다섯 값만 남긴다.

조정 규칙은 다음과 같다.

1. 현재 설정으로 새 주지표 기준선을 생성한다.
2. ★1부터 순서대로 목표보다 높으면 해당 위험도 배율을 높이고, 낮으면 내린다.
3. 50시드에서 실행 무결성을 확인하고 100시드에서 방향과 실패 위치를 확인한다.
4. 목표 구간에 들어온 낮은 위험도는 잠그고 다음 위험도를 조정한다.
5. 다섯 단계를 잠근 후보만 200시드 최종 calibration으로 보낸다.
6. 기존 캠페인 완주율·전멸 gate가 깨지면 위험도 곡선만 맞았다고 승인하지 않는다.

클리어율이 목표보다 낮더라도 보스 전 실패 몫이 보스 실패 몫보다 크거나 평균 보스
진입 HP 비율이 `0.70` 미만이면 보스 배율로 원인을 덮지 않는다. 해당 위험도 조정을
중단하고 일반 구간·회복 경제를 별도 설계 대상으로 보고한다. 이번 spec은 그 후속
규칙 변경을 자동 승인하지 않는다.

특정 테마만 다른 결과를 보이더라도 테마별 배율을 추가하지 않는다. 원본 보스
정의나 고유 규칙의 이상 여부를 대표 시드로 먼저 조사하고, 콘텐츠 수정이
필요하면 별도 설계 승인을 받는다.

## 8. 데이터 흐름과 책임

```text
실제 Campaign Store 실행
→ 원정 시작 시 초기/현재 위험도와 attemptNumber 기록
→ 보스 진입 상태와 원정 결과 기록
→ 위험도·전략·정확도별 집계
→ 목표 곡선 및 기존 B1-B gate 판정
→ 결정적 Markdown 보고서 생성
```

- `campaign-driver`는 실제 플레이 전이와 원시 trace만 소유한다.
- `metrics`는 분모·분자, Wilson 구간, 실패 위치를 계산한다.
- `acceptance`는 승인된 목표와 최소 표본을 판정한다.
- `report`는 원시 trace를 다시 해석하지 않고 집계 결과를 표시한다.
- 프로덕션 보스 규칙은 공통 밸런스 설정만 읽고 백테스트 목표를 import하지 않는다.

## 9. 오류 처리

- `attemptNumber`가 양의 정수가 아니거나 같은 캠페인·던전에서 연속되지 않으면
  집계 오류로 중단한다.
- 위험도 1~5 키, 시작 수, 결과 수가 맞지 않으면 조용히 누락하지 않는다.
- `cleared + wiped + interrupted`가 시작 수와 다르면 집계 오류로 중단한다.
- 보스 진입 수가 시작 수보다 많거나 클리어 수가 보스 진입 수보다 많으면 중단한다.
- 분모 0과 최소 표본 미달은 0%로 표시하지 않고 근거 부족으로 판정한다.
- 배율은 유한한 양수이고 `0.20~1.20`, `0.025` 격자를 만족해야 한다.
- 오류가 난 캠페인은 다른 시드로 대체하지 않으며 대표 시드와 오류 종류를 보고한다.

## 10. 테스트 전략

### 10.1 trace와 집계 단위 테스트

- 같은 던전의 첫 시도·재도전 `attemptNumber` 증가와 다른 던전의 1 초기화
- 원정 시작 시점의 초기·현재 위험도 보존
- 클리어·전멸·중단이 분모에서 누락되지 않음
- 손계산 fixture의 첫 시도 클리어율, 전체 시도율, 최종 통과율
- 보스 전 실패 몫과 보스 실패 몫
- 위험도·테마 drill-down과 Wilson 구간
- 잘못된 분모, 누락 결과, 불연속 attempt의 명시적 실패

### 10.2 acceptance 단위 테스트

- 각 목표 구간의 하한·상한 포함
- 목표 밖, 위험도 역전, 최소 표본 미달의 실패
- 새 gate와 기존 완주율·전멸 gate가 함께 반환됨
- 50·100시드는 관찰 전용이고 200·2,000시드만 판정함

### 10.3 규칙과 통합 테스트

- 위험도별 보스 배율이 HP·기본 피해에 한 번만 적용됨
- 현재 위험도·재도전 횟수에 따라 보스 원형이 다시 커지지 않음
- 테마가 달라도 같은 초기 위험도에는 같은 공통 배율 적용
- 보스 고유 특징·targetWeight·정보·상인·조언 압력 합성 보존
- 같은 revision·시드·전략·정확도의 trace와 보고서 결정성
- 3전략 × 2정확도 전체 Store 실행의 무결성

## 12. 완료 조건

- 위험도별 첫 시도·전체 시도·최종 통과 지표가 결정적으로 생성됨
- 일반 구간과 보스에서 발생한 실패를 분리해 보고함
- `opportunist@0.7`의 ★1~5 첫 시도 클리어율이 승인된 목표 구간과 최소 표본을
  만족함
- 기존 B1-B의 완주율·전멸·정확도·배신·무결성 gate도 모두 만족함
- 최종 다섯 보스 배율과 balance revision이 코드·spec·공식 문서에 동결됨
- 사용자 승인 전 holdout 실행이 계속 차단됨
- 승인된 설정으로 조합당 2,000시드 holdout이 모든 gate를 통과함
- lint, typecheck, 전체 test, build가 통과함
- 최종 보고서가 revision, namespace, 표본 수, 위험도별 결과와 대표 실패 시드를
  포함함
