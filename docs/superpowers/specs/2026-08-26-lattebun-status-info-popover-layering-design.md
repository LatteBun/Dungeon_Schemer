# 상단 상태 정보 팝오버 레이어 수정 설계

## 문서 정보

- 작성자: LatteBun
- 작성 도구: Codex + Superpowers Brainstorming
- 작성일: 2026-08-26
- 대상: `의심 인원`, `남은 용사` 공용 상태 정보 팝오버

## 문제

U4 지도에서 상태 정보 팝오버를 열면 지도 패널 헤더가 팝오버 본문 위에 그려진다. 팝오버는 상태 바 내부에서 `z-index: 20`을 사용하지만, 부모 상태 바가 `z-index: 10`인 스태킹 컨텍스트를 만들기 때문에 그 밖의 지도 헤더 `z-index: 20`보다 위로 올라갈 수 없다.

현재 브라우저 회귀는 팝오버가 트리거 아래에서 가운데 정렬되는지만 검사한다. 따라서 팝오버와 지도 헤더의 실제 겹침 지점에서 어느 요소가 최상단에 그려지는지는 검증하지 못한다.

## 목표

- `의심 인원`과 `남은 용사` 팝오버를 모든 화면 콘텐츠 위에 표시한다.
- 팝오버의 트리거 기준 위치와 기존 상호작용·접근성 계약은 유지한다.
- 전역 퀵 메뉴는 상태 바와 열린 팝오버보다 계속 위에 둔다.
- U4 지도 헤더가 팝오버를 다시 가리지 못하도록 브라우저 회귀를 추가한다.

## 레이어 계약

공통 화면 레이어 순서는 다음과 같다.

1. 개별 화면 콘텐츠와 화면 내부 오버레이
2. 공통 상단 상태 바와 상태 정보 팝오버
3. 전역 퀵 메뉴
4. 화면 맞춤 안내처럼 별도 계약을 가진 최상위 시스템 UI

`app/globals.css`의 공통 `.game-shell__status-bar`가 화면 콘텐츠보다 높은 스태킹 컨텍스트를 소유한다. `.game-shell__status-info-popover`는 그 안에서 기존 로컬 순서를 유지한다. 전역 퀵 메뉴의 레이어 값은 변경하지 않는다.

화면별 CSS에서 `의심 인원` 또는 `남은 용사` 팝오버의 `z-index`를 따로 덮어쓰지 않는다. 지도 헤더의 레이어를 낮추는 방식도 사용하지 않는다. 문제는 U4만의 헤더가 아니라 공통 상태 팝오버와 모든 화면 콘텐츠 사이의 계약이기 때문이다.

## 위치와 상호작용

- 팝오버는 계속 누른 칩 바로 아래에서 칩의 가로 중심에 맞춰 열린다.
- 팝오버 크기, 문구, 색상과 여백은 바꾸지 않는다.
- 두 팝오버 중 하나만 열 수 있다.
- 바깥 클릭, `Escape`, `닫기`로 닫고 필요한 경우 트리거로 초점을 돌리는 기존 동작을 유지한다.
- 비모달 `role="dialog"`와 접근 가능한 이름을 유지한다.

## 구현 범위

- `app/globals.css`: 공통 상태 바의 레이어를 화면 콘텐츠보다 높고 전역 퀵 메뉴보다 낮게 조정한다.
- `e2e/canvas-layout.spec.ts`: U4 지도에서 각 팝오버를 열고 지도 헤더와 겹치는 내부 지점의 최상단 요소가 팝오버 자신인지 검증한다.
- `docs/experience/SCREEN_LAYOUT.md`: 공통 레이어 순서를 공식 화면 계약에 기록한다.
- `docs/technical/SCREEN_ADAPTER_CONTRACT.md`: 화면 어댑터가 팝오버 레이어를 재정의하지 않는 경계를 기록한다.

컴포넌트 구조, 상태 View, 캠페인 규칙, 문구와 자산은 변경하지 않는다.

## 테스트 우선 검증

1. U4 지도에서 `의심 인원` 팝오버의 지도 헤더 겹침 지점이 팝오버 최상단이기를 기대하는 Playwright 검사를 추가하고 현재 CSS에서 실패함을 확인한다.
2. 같은 검사를 `남은 용사` 팝오버에도 적용해 현재 CSS에서 실패함을 확인한다.
3. 공통 상태 바 레이어만 최소 변경해 두 검사를 통과시킨다.
4. 기존 FHD·HD·5:4 상태 칩 한 줄, 앵커 위치, 닫기·초점 복귀, 퀵 메뉴 비겹침 회귀를 함께 실행한다.
5. 관련 단위 테스트와 production build를 실행한다.

## 완료 조건

- U4 지도에서 두 팝오버의 글과 배경이 지도 패널 헤더에 가려지지 않는다.
- 팝오버는 여전히 해당 칩 아래 중앙에 열린다.
- 전역 퀵 메뉴는 상태 바 및 팝오버와 충돌하지 않는다.
- 화면별 팝오버 CSS 재정의가 추가되지 않는다.
- 새 회귀와 기존 관련 검증이 모두 통과한다.
