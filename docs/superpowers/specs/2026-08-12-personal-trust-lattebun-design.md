# R2 개인 신뢰 판정 설계

**작성자:** LatteBun  
**작성 도구:** Codex

## 목적

같은 행동이 파티원의 성격에 따라 서로 다른 신뢰 변화를 만들고, 변화량과
사유 및 정체 발각 여부를 재현 가능하게 반환하는 범용 신뢰 판정을 만든다.

이 작업은 [프로토타입 작업 배정표](../../technical/PROTOTYPE_WORK_ASSIGNMENT.md)의
`R2`다. 완료되면 `R3` 정보 카드 판정, `R5` 결과 정산, `U1` 파티·개인 신뢰
패널이 신뢰 변화 규칙을 전제로 작업할 수 있다.

## 설계 원칙

### 사건의 출처가 아니라 행동의 의미를 판정한다

R2는 정보 카드, 던전 이벤트, 상태 스토어를 직접 알지 않는다. 상위 시스템이
사건을 공통 행동으로 해석하고, R2는 대상 파티원의 성격에 따른 반응만 계산한다.
따라서 정보 카드에서 들킨 거짓말과 상인에게 친 사기가 모두 `기만 적발`이라는
같은 규칙을 재사용할 수 있다.

### 성격 차이가 중심이고 난수는 작은 변동만 만든다

성격×행동 표의 기본 변화량이 판정의 중심이다. 난수는 기본값 절댓값의 약 20%
범위에서만 결과를 흔들며 부호를 뒤집지 않는다. 같은 시드와 같은 판정 순서는
같은 결과를 만든다.

### 정체 발각과 게임 종료를 분리한다

신뢰 0은 `exposed`로 알리지만 R2가 런을 종료하지 않는다. 즉시 처형, 증언,
구제 기회 같은 전체 흐름은 후속 상태 머신의 책임이다. 다만 이미 0인 신뢰는
일반 판정으로 회복시키지 않는다.

## 공개 계약

### 공통 행동

행동은 닫힌 유니온 `TrustAction`으로 둔다.

```ts
export type TrustAction =
  | "actHonestly"
  | "deceptionExposed"
  | "protectAlly"
  | "betrayAlly"
  | "secureReward"
  | "denyReward"
  | "takeRisk"
  | "avoidRisk";
```

각 행동의 의미는 다음과 같다.

| 행동 | 의미 |
| --- | --- |
| `actHonestly` | 사실을 말하거나 약속을 지킴 |
| `deceptionExposed` | 거짓말, 사기, 은밀한 방해가 드러남 |
| `protectAlly` | 다른 파티원을 구하거나 보호함 |
| `betrayAlly` | 다른 파티원을 희생시키거나 배신함 |
| `secureReward` | 판정 대상 파티원에게 이익을 줌 |
| `denyReward` | 판정 대상 파티원의 이익을 빼앗거나 포기시킴 |
| `takeRisk` | 위험을 받아들이고 즉시 행동함 |
| `avoidRisk` | 안전을 우선해 위험을 피함 |

한 사건에 의미가 여럿이면 상위 시스템이 핵심 행동 하나를 고른다. 복합 판정을
자동 합산하지 않는다. 필요하면 사건을 별도 결정으로 나누어 각각 판정하고
사유를 남긴다. 이는 중복 계산과 과도한 신뢰 변화를 막는다.

### 판정 함수와 결과

```ts
export interface TrustEvaluation {
  member: PartyMember;
  change: TrustChange;
  exposed: boolean;
}

export function evaluateTrust(
  member: PartyMember,
  action: TrustAction,
  rng: Rng,
): TrustEvaluation;
```

함수는 입력 객체를 수정하지 않고 새 `PartyMember`를 반환한다. `change.delta`는
범위 제한 전에 뽑힌 값이 아니라 실제로 적용된 차이다. 예를 들어 신뢰 98에서
판정값 `+8`이 나오면 새 신뢰는 100이고 `delta`는 `+2`다.

호출자는 `createRng(seed).derive("trust")`를 전달한다. 함수 안에서 시드를 만들거나
`Math.random`을 호출하지 않는다.

## 성격별 판정표

판정표는 `Record<Personality, Record<TrustAction, TrustRule>>` 형태로 정의한다.
성격 또는 행동이 추가됐는데 규칙이 빠지면 타입 검사가 실패해야 한다.

| 행동 | 의심 많음 | 정의로움 | 탐욕스러움 | 신중함 | 충동적 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `actHonestly` | +8 | +12 | 0 | +5 | +3 |
| `deceptionExposed` | -14 | -16 | -6 | -10 | -7 |
| `protectAlly` | +3 | +12 | 0 | +7 | +8 |
| `betrayAlly` | -8 | -16 | -4 | -10 | -10 |
| `secureReward` | +3 | +4 | +14 | +5 | +7 |
| `denyReward` | -5 | -6 | -16 | -7 | -8 |
| `takeRisk` | -5 | -3 | +3 | -12 | +12 |
| `avoidRisk` | +7 | +3 | 0 | +12 | -10 |

`TrustRule`은 기본 변화량과 표준 사유를 가진다. 사유는 호출자가 넘기지 않는다.
예시는 다음과 같다.

- `정의로운 성격: 정직한 정보를 높이 평가함`
- `의심 많은 성격: 기만이 드러나 경계함`
- `탐욕스러운 성격: 보상을 확보해 만족함`

구체적인 사건은 `DecisionRecord.summary`가 설명하고, 신뢰 변화의 `reason`은
그 성격이 행동에 반응한 이유를 설명한다.

## 판정 절차

1. 입력 신뢰가 0~100의 정수인지 검사한다.
2. 입력 신뢰가 이미 0이면 난수를 소비하지 않고 `delta: 0`, `exposed: true`를
   반환한다.
3. 성격과 행동으로 기본 변화량과 표준 사유를 찾는다.
4. 기본값이 0이면 난수를 소비하지 않고 `delta: 0`을 반환한다.
5. 기본값 절댓값의 20%를 반올림하고 최소 1을 적용해 변동 폭을 구한다.
6. `rng.int(-변동폭, 변동폭)`으로 정수 변동을 뽑아 기본값에 더한다.
7. 예상치 못한 작은 기본값에서도 부호가 뒤집히지 않도록 양수는 최소 1,
   음수는 최대 -1로 제한한다.
8. 기존 신뢰에 적용하고 결과를 0~100으로 제한한다.
9. 실제 적용된 차이를 `TrustChange.delta`에 담고, 새 신뢰가 0인지 `exposed`로
   반환한다.

같은 시드와 같은 호출 순서는 같은 결과를 만든다. 기본값 0과 이미 신뢰 0인
경우 난수를 소비하지 않는 성질도 계약의 일부다.

## 입력 오류와 경계값

- 입력 신뢰가 소수, `NaN`, 무한대 또는 0~100 밖이면 `RangeError`를 던진다.
- 행동과 성격의 유효성은 닫힌 TypeScript 유니온과 완전한 판정표로 막는다.
- 결과 신뢰는 항상 `TRUST_MIN`과 `TRUST_MAX` 사이의 정수다.
- 이미 0인 파티원은 일반 신뢰 판정으로 회복하지 않는다. 향후 구제 규칙은
  R2가 아니라 별도 게임 흐름으로 추가한다.
- 원본 `PartyMember`는 변경하지 않는다.

## 파일 구조

| 파일 | 책임 |
| --- | --- |
| `lib/rules/trust.ts` | 행동 타입, 성격별 판정표, 판정 함수 |
| `lib/rules/trust.test.ts` | 성격 차이, 난수, 경계값, 오류, 불변성 테스트 |
| `docs/systems/PARTY_AND_TRUST.md` | 프로토타입 신뢰 판정의 공식 규칙 |

R2는 작고 응집된 규칙이므로 별도 데이터 파일로 나누지 않는다. 판정표는 콘텐츠가
아니라 닫힌 게임 규칙이며 `trust.ts`가 직접 소유한다.

## 테스트

### 성격과 행동

- 같은 행동에서 성격에 따른 의미 있는 기본 반응 차이가 나타난다.
- 모든 성격×행동 조합이 빠짐없이 정의된다.
- 기본값 0인 조합은 정확히 0을 반환하고 난수를 소비하지 않는다.
- 모든 결과의 표준 사유가 비어 있지 않다.

### 난수와 재현성

- 같은 시드와 같은 입력 순서는 같은 변화량과 사유를 반환한다.
- 결과가 기본값의 약 20% 범위를 벗어나지 않는다.
- 긍정 규칙은 음수가 되지 않고 부정 규칙은 양수가 되지 않는다.

### 범위와 실패 상태

- 신뢰 상승은 100에서 멈추고 실제 적용량을 기록한다.
- 신뢰 하락은 0에서 멈추고 실제 적용량을 기록한다.
- 새 신뢰가 0이면 `exposed: true`다.
- 이미 신뢰 0이면 회복되지 않고 계속 `exposed: true`다.
- 정상적인 1~100 결과는 `exposed: false`다.

### 오류와 불변성

- 소수, `NaN`, 무한대, 범위 밖 신뢰는 `RangeError`를 던진다.
- 원본 `PartyMember` 객체를 변경하지 않는다.

전체 검증은 `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` 넷이다.

## 제외 범위

- 정보의 수용·의심·적발을 정하는 R3 확률 판정
- 여러 행동의 신뢰 변화를 자동으로 합산하는 복합 판정
- 신뢰 구간에 따른 수용률, 감시, 보상 규칙
- 신뢰 0 이후 즉시 처형, 증언 또는 구제 기회
- 상태 스토어와 `RunState.log` 갱신
- UI 표시와 애니메이션
- 초기 신뢰 결정과 파티 생성

## 후속 작업에 남기는 계약

- `R3`은 정보 결과를 공통 행동으로 바꾸고 `evaluateTrust`를 호출한다.
- 던전 이벤트 규칙도 같은 공통 행동을 사용해 신뢰 변화를 계산할 수 있다.
- `R5`와 `U1`은 `TrustChange.delta`가 실제 적용량이고 `reason`이 항상 존재한다고
  전제할 수 있다.
- 상태 머신은 `exposed`를 받아 처형이나 구제 여부를 결정한다.
