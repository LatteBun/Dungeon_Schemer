# PR 88 문서 무결성 검증 복구 설계

## 작성 정보

- 작성자: LatteBun
- 작성 도구: Codex
- 대상: PR 88 `U5-2 자동 전투 연출` 문서 변경으로 실패한 검증

## 문제

PR 88은 Mermaid 그래프에서 식별자 `U5_2`를, 배정표 표에서는 `U5-2`를 사용한다. 두 표기는 같은 작업을 뜻하지만 문서 무결성 검사가 표기 차이를 정규화하지 않아 그래프에서 해당 노드와 간선을 읽지 못한다. 그 결과 그래프와 배정표의 ID·나가는 간선·선행 작업 비교가 실패한다.

현재 `main`에는 별도로 `design/CORE_GAME_LOOP.md`의 필수 용어 앵커 `방문한 사건`이 빠져 문서 용어 검증도 실패한다.

## 범위

### 포함

- Mermaid 작업 식별자의 밑줄(`_`) 표기를 배정표의 하이픈(`-`) 표기로 정규화하는 문서 무결성 검사 수정
- `U5_2`/`U5-2` 변환을 재발 방지하는 테스트 추가
- 핵심 게임 루프 문서에 필수 앵커 `방문한 사건` 복원
- lint, typecheck, test, build 검증

### 제외

- PR 88의 자동 전투 연출 규칙·의존성 자체 변경
- 배정표의 작업 상태·담당자·의존성 구조 변경
- 기존 이미지 최적화 lint 경고 해소

## 설계

문서 무결성 검사에는 Mermaid 토큰을 배정표의 정식 ID로 변환하는 작은 정규화 함수를 둔다. Mermaid 노드 선언과 간선 양쪽을 이 함수를 거쳐 읽어, `U5_2`는 `U5-2`로 비교한다. 배정표 내부 ID는 기존 형식을 그대로 유지한다.

테스트는 실제 배정표를 대상으로 하므로 PR 88이 추가한 `U5-2` 노드와 모든 연결이 정상 비교되는 결과로 보호한다. 필요하면 정규화 함수의 동작을 독립적으로 확인하는 단위 테스트도 추가한다.

`CORE_GAME_LOOP.md`에는 E3가 실제 사건을 정하는 시점을 설명하는 기존 문장에 `방문한 사건`이라는 용어를 자연스럽게 포함해, 용어 감시 테스트의 문서 계약을 복원한다.

## 검증 기준

- `pnpm lint`가 오류 없이 완료된다.
- `pnpm typecheck`가 완료된다.
- `pnpm test`가 전체 통과하며, 배정표 그래프·표 무결성 테스트와 문서 용어 테스트가 통과한다.
- `pnpm build`가 성공한다.
