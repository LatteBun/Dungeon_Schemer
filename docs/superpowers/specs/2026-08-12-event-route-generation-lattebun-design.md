# R4 이벤트·경로 생성 설계

**작성자:** LatteBun
**작성 도구:** Codex

## 목적

같은 시드에서 같은 분기 경로와 이벤트 배치를 재현하고, 모든 경로가 같은 길이로
보스 전에 합류하며, 일반 경로에서 네 이벤트 분류를 모두 경험하게 한다.

이 작업은 [프로토타입 작업 배정표](../../technical/PROTOTYPE_WORK_ASSIGNMENT.md)의
`R4`다. 완료되면 `R5` 결과 정산, `P1` 게임 상태 머신, `U3` 던전 분기 지도,
`Q1` 콘텐츠 데이터 작업의 선행 조건을 해소한다.

## 설계 원칙

### 유효한 구조를 처음부터 생성한다

노드와 간선을 무작위로 만든 뒤 실패할 때까지 재시도하지 않는다. 허용된 경로
형태 안에서 시드로 갈래 수와 깊이를 고르고, 구조적 위치에 따라 노드와 간선을
만든다. 모든 노드의 도달 가능성, 동일한 경로 길이, 보스 전 합류를 생성 방식
자체가 보장한다.

### 콘텐츠와 생성 규칙을 분리한다

생성기는 이벤트 제목, 설명, 선택지 문구를 만들지 않는다. 분류별 콘텐츠 풀에서
완성된 `DungeonEvent`를 중복 없이 선택한다. 새 이벤트는 콘텐츠 파일에 추가하며
생성 로직을 수정하지 않는다.

### 재현 가능한 난수만 사용한다

호출자가 `createRng(seed).derive("dungeon")`을 주입한다. 생성 함수 안에서 시드를
만들거나 `Math.random`을 호출하지 않는다. 실패 시 재시도하지 않으므로 난수 소비
순서도 명확하다.

## 공개 계약

```ts
export interface DungeonEventPools {
  readonly regular: Readonly<
    Record<EventKind, readonly DungeonEvent[]>
  >;
  readonly boss: readonly DungeonEvent[];
}

export interface GenerateDungeonOptions {
  readonly eventPools?: DungeonEventPools;
}

export interface GeneratedDungeon {
  readonly dungeon: DungeonState;
  readonly events: DungeonEvent[];
}

export function generateDungeon(
  rng: Rng,
  options?: GenerateDungeonOptions,
): GeneratedDungeon;
```

기본 호출은 다음과 같다.

```ts
generateDungeon(createRng(seed).derive("dungeon"));
```

`eventPools`를 생략하면 `lib/content/events.ts`의 기본 풀을 사용한다. 테스트와 향후
콘텐츠 조합 실험은 별도 풀을 주입할 수 있다.

반환된 `events`에는 이번 던전이 실제 사용하는 이벤트만 들어간다. 모든 노드의
`eventId`는 이 목록의 정확히 한 이벤트를 가리킨다. 입력 풀과 이벤트 객체는
변경하지 않는다.

## 경로 구조

시드는 다음 세 형태 중 하나를 결정한다.

| 갈래 수 | 갈래별 중간 노드 | 총 노드 |
| ---: | ---: | ---: |
| 2 | 2 | 7 |
| 3 | 2 | 9 |
| 2 | 3 | 9 |

총 노드 수는 `입구 1 + 갈래별 중간 노드 + 합류 1 + 보스방 1`이다.

```text
입구
→ 2~3갈래
→ 갈래마다 같은 수의 중간 노드
→ 보스 직전 공통 합류 노드
→ 보스방
```

그래프는 다음 불변 조건을 만족한다.

- 입구와 보스방은 각각 하나이며 모두 `nodes`에 포함된다.
- 입구는 2~3개의 첫 갈래 노드를 가리킨다.
- 갈래 사이에는 교차 간선이 없다.
- 각 갈래의 마지막 노드는 같은 공통 합류 노드를 가리킨다.
- 합류 노드는 보스방만 가리킨다.
- 보스방만 `nextNodeIds`가 비어 있다.
- 모든 간선은 더 큰 `depth`의 노드를 가리킨다.
- 모든 노드는 입구에서 도달 가능하다.
- 모든 입구→보스 경로의 노드 수가 같다.

깊이는 입구 0, 갈래 노드 1~N, 합류 `N + 1`, 보스방 `N + 2`다.

노드 ID는 구조적 위치를 드러낸다.

```text
node-entry
node-path-1-depth-1
node-path-2-depth-1
node-merge
node-boss
```

같은 시드에서 형태, 이벤트 선택과 배치, ID가 모두 같다.

## 이벤트 콘텐츠 풀

`lib/content/events.ts`는 기본 `DungeonEventPools`를 내보낸다.

- `regular.monster`: 몬스터 이벤트 2개
- `regular.rest`: 휴식 이벤트 2개
- `regular.merchant`: 상인 이벤트 2개
- `regular.special`: 일반 특수 사건 2개
- `boss`: `special` 보스 조우 이벤트 1개 이상

분류별 2개는 허용된 가장 큰 일반 경로에서도 중복 없이 배치할 수 있는 최소
콘텐츠 양이다. 정확한 사건 문구는 게임 원칙의 지원·방해·개인 이익·관망 선택을
드러내되, R4는 선택 결과 계산을 구현하지 않는다.

정적 이벤트 선택지의 `target`은 없거나 `{ kind: "boss" }`다. 특정 `MemberId`는
R1 파티와 R4 던전 생성을 결합하므로 사용하지 않는다. 개인 대상 선택지는 실제
파티를 아는 후속 흐름이 구체화한다.

## 이벤트 분류와 배치

보스방을 제외한 모든 노드를 일반 노드로 본다.

1. 일반 노드 수만큼 분류 목록을 만든다.
2. `monster`, `rest`, `merchant`, `special`을 한 번씩 넣는다.
3. 일반 노드가 6개면 네 분류를 섞어 앞의 서로 다른 두 분류를 한 번씩 더 넣는다.
4. 일반 노드가 8개면 네 분류를 한 번씩 더 넣는다.
5. 완성된 분류 목록을 다시 섞어 입구·갈래·합류 노드 순서에 배치한다.
6. 각 분류 풀을 섞고 필요한 수만큼 잘라 이벤트를 중복 없이 고른다.
7. 보스 풀에서 하나를 골라 보스방에 배치한다.

따라서 모든 판의 일반 경로에 네 분류가 최소 한 번 등장한다. 일반 노드가 6개면
두 분류가 두 번씩, 8개면 네 분류가 두 번씩 등장한다. 보스방의 `special`은 일반
경로의 분류 보장에 포함하지 않는다.

반환 `events`의 순서는 노드 순서와 맞춘다. `events[index]`는 `nodes[index]`가
가리키는 이벤트다. 이 순서는 별도 탐색 없이 결과를 검사하기 위한 편의이며,
노드와 이벤트의 공식 연결 기준은 여전히 `eventId`다.

## 생성 절차

1. 전체 이벤트 풀의 정적 계약을 검증한다.
2. 시드로 허용된 경로 형태 하나를 고른다.
3. 구조적 ID와 깊이로 노드 골격을 만든다.
4. 일반 이벤트 분류 목록을 만들고 섞는다.
5. 분류별 필요 개수를 세고 콘텐츠가 충분한지 검사한다.
6. 각 분류에서 이벤트를 중복 없이 선택한다.
7. 보스 조우를 선택한다.
8. 노드에 `eventId`를 연결해 `dungeon`과 사용 이벤트를 반환한다.

## 콘텐츠 오류 처리

잘못된 개발용 콘텐츠나 입력 풀은 자동으로 보정하거나 재생성하지 않고 `Error`를
던진다. 오류 메시지는 문제의 ID, 분류 또는 필요·보유 개수를 포함한다.

- `regular` 이벤트의 `kind`가 소속 풀과 다름
- 보스 이벤트의 `kind`가 `special`이 아님
- 전체 풀에서 이벤트 ID가 중복됨
- 전체 풀에서 선택지 ID가 중복됨
- 선택지가 없는 이벤트
- `expectedGain` 또는 `knownRisk`가 빈 선택지
- 특정 파티원을 대상으로 하는 선택지
- 실제 배치에 필요한 이벤트보다 작은 분류 풀
- 비어 있는 보스 풀

검증은 난수를 소비하기 전에 실행한다. 잘못된 풀을 고친 뒤 같은 시드로 다시
호출했을 때 오류 검증 때문에 생성 결과의 난수 위치가 달라지지 않는다.

## 테스트

### 경로와 재현성

- 같은 시드가 동일한 `dungeon`과 `events`를 만든다.
- 여러 고정 시드에서 총 노드가 7~10개다.
- 허용된 세 경로 형태가 고정 시드 집합에서 모두 생성된다.
- 입구와 보스방이 각각 하나이고 노드 목록에 존재한다.
- 입구가 2~3개 갈래로 분기한다.
- 보스방만 막다른 길이다.
- 모든 노드가 입구에서 도달 가능하다.
- 모든 간선이 더 큰 `depth`로 이동한다.
- 보스 전에 진입 차수 2 이상인 합류 노드가 하나 있다.
- 모든 입구→보스 경로 길이가 같다.

### 이벤트 배치

- 일반 노드에 네 이벤트 분류가 모두 최소 한 번 등장한다.
- 일반 노드가 6개면 두 분류만 두 번, 8개면 모든 분류가 두 번 등장한다.
- 보스방은 `special` 보스 조우 이벤트다.
- 모든 노드의 `eventId`가 반환 이벤트에 존재한다.
- 노드와 반환 이벤트의 순서가 대응한다.
- 반환 이벤트와 선택지 ID가 중복되지 않는다.
- 같은 이벤트를 한 던전에서 재사용하지 않는다.
- 모든 이벤트에 선택지가 하나 이상 있다.
- 모든 선택지에 예상 이득과 알려진 위험이 있다.
- 특정 파티원 대상 선택지가 없다.
- 입력 풀 배열과 이벤트 객체를 변경하지 않는다.

### 오류

- 분류와 `kind`가 다른 이벤트를 거부한다.
- `special`이 아닌 보스 이벤트를 거부한다.
- 중복 이벤트 ID와 중복 선택지 ID를 각각 거부한다.
- 빈 선택지 배열을 거부한다.
- 빈 예상 이득과 빈 알려진 위험을 각각 거부한다.
- 특정 파티원 대상을 거부한다.
- 필요한 수보다 작은 분류 풀을 거부한다.
- 빈 보스 풀을 거부한다.

검사는 고정 시드를 사용하며 확률에 따라 통과 여부가 달라지지 않는다. 전체 완료
검증은 `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` 넷이다.

## 제외 범위

- 이벤트 선택 결과, 전투, 자원과 신뢰 변화 계산
- 파티원에 맞춘 선택지 구체화
- 현재 위치, 방문 경로, 선택 가능한 노드를 관리하는 상태 머신
- 보스전 처리와 종료 조건
- 지도 UI와 애니메이션
- 장기 던전 상태와 이전 탐험 결과 반영
- 완전 무작위 그래프, 지름길, 서로 다른 경로 길이, 갈래 간 교차 연결
- 콘텐츠 현지화 체계와 대규모 콘텐츠 확장

## 후속 작업 계약

- `P1`은 `GeneratedDungeon.dungeon`을 받아 유효한 다음 노드 전이를 관리한다.
- `U3`는 노드의 `depth`와 `nextNodeIds`로 분기 지도를 그린다.
- `R5`는 방문한 노드와 이벤트 결과를 정산에 사용한다.
- `Q1`은 `lib/content/events.ts`의 풀에 이벤트를 추가하며 생성 코드를 고치지 않는다.
- 보스방은 `nodes`에 포함되고 보스 조우 `eventId`를 가지므로 `P2`가 해당 노드에서
  실제 보스전 흐름을 시작할 수 있다.
