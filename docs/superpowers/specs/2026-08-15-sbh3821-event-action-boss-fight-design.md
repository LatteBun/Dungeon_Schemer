## 문제

`E2`까지 오면 지도가 있고 정보 기회가 있고 개인별 반응이 기록된다. 그러나 그
기록이 아무 데도 쓰이지 않고, 사건 지점에 도착해도 할 수 있는 일이 없다. 두 가지
공백이 있다.

**사건 선택지가 전부 `observe`다.** `lib/content/events.ts`의 선택지 27개가 모두
기본 태그 하나만 달고 있다. 라벨은 `우회로를 알려준다`, `보스의 소문을 산다`처럼
다르지만 태그가 같아 어떤 선택도 상태를 바꾸지 않는다. F2 spec이 `효과 태그를
실제 수치와 RNG 소비로 해석하는 작업은 Task 6~7에서 별도로 정한다`고 넘겨 둔
부분이다.

**지금 수치로는 전멸이 불가능하다.** 파티원 최대 HP는 100이고 보스 기본 피해는
C 8부터 S 24까지다. 최대 보정 +50%를 받아도 36이다. 사건이 HP를 깎지 않으면
파티는 만피로 보스방에 도착해 모든 던전을 클리어한다. 전멸 정산, 던전 등급 상승,
사망자 유품 골드가 전부 실행되지 않는 코드가 된다.

## 사건 효과 수치

효과는 **사건 분류의 기본값**과 **선택한 행동의 보정**을 더한 뒤 **던전 등급
배율**을 곱해 정한다.

```text
hpDelta = round((분류 기본 + 행동 보정) × 등급 배율)
```

분류 기본값을 두는 이유는 아무것도 하지 않는 것이 안전한 선택이 되지 않게 하려는
것이다. 길잡이가 개입하지 않으면 파티는 서서히 깎여 나간다. 관망은 `개입하지
않는다`는 선택이지 `아무 일도 없다`가 아니다.

| 사건 분류 | 기본 HP |
| --- | ---: |
| 몬스터 | -20 |
| 휴식 | +8 |
| 상인 | 0 |
| 특수 사건 | -12 |

| 행동 태그 | 보정 HP | 설명 |
| --- | ---: | --- |
| `support` | +12 | 용사를 돕는다 |
| `sabotage` | -14 | 위험을 키운다 |
| `rest` | +10 | 회복을 돕는다 |
| `item` | +8 | 물자를 쓴다 |
| `information` | +4 | 단서를 얻어 덜 다친다 |
| `trade` | 0 | 골드로 상품을 산다 |
| `observe` | 0 | 개입하지 않는다 |

`information`을 0으로 두지 않은 이유가 있다. 0이면 `observe`와 결과가 완전히
같아지고, 두 선택지가 그 조합인 `봉인된 계약서`는 **선택이 없는 사건**이 된다.
[핵심 게임 루프](../../design/CORE_GAME_LOOP.md)의 `모든 주요 단계에서 최소 하나의
의미 있는 플레이어 결정` 제약을 만족하지 못한다. 던전의 의도를 읽으면 파티가 조금
덜 다치는 것으로 해석한다.

상품은 사는 즉시 쓴다. 소지품 목록이 없기 때문이다.

| 상품 효과 태그 | 보정 HP |
| --- | ---: |
| `restoreHp` | +20 |
| `dealDamage` | +12 |
| `lureMonster` | +10 |
| `restoreFood` | +6 |
| `revealInformation` | +4 |

독과 미끼가 파티 HP를 올리는 것처럼 보이지만, 위협을 줄여 파티가 덜 다친다는
뜻이다. 상품 효과도 같은 등급 배율을 지난다. 등급마다 다른 배율을 쓰면 같은
가격의 상품이 등급별로 다른 값을 갖게 되고 조정할 상수가 두 벌이 된다.

| 등급 | 배율 |
| --- | ---: |
| C | 1.0 |
| B | 1.3 |
| A | 1.6 |
| S | 2.0 |

등급 배율을 쓰는 이유는 상위 등급 경로가 더 길기도 하지만, 길이만으로는 난이도
차이가 충분히 벌어지지 않기 때문이다. C 경로의 일반 사건은 4개, S는 7개로 1.75배
차이인데 보스 피해는 3배 차이다. 사건 쪽도 함께 올려야 보스방 도착 HP가 등급별로
갈린다.

### 결과 예상

만피 100에서 한 경로를 끝까지 걷고 보스전까지 마쳤을 때 남는 HP다.

C급 경로는 일반 사건이 4개이고 네 분류가 정확히 한 번씩이므로 **시드와 무관하게
같은 값**이 나온다.

| C급 | 사건 합계 | 보스 | 남는 HP |
| --- | ---: | ---: | ---: |
| 전원 관망 | -24 | -8 | 68 |
| 전원 지원 | +24 (상한) | -6 | 94 |
| 전원 방해 | -80 | -10 | 10 |

S급은 일반 사건이 7개인데 그중 3칸이 시드로 정해지므로 갈래마다 구성이 다르다.
몬스터가 몰린 갈래와 상인이 몰린 갈래의 폭이 크다.

| S급 | 사건 합계 | 남는 HP |
| --- | ---: | --- |
| 전원 관망 · 상인이 몰린 갈래 | -56 | 보스 뒤 20 생존 |
| 전원 관망 · 몬스터가 몰린 갈래 | -112 | **보스방 도착 전 전멸** |
| 전원 지원 | 상한 | 보스 뒤 83 생존 |
| 전원 방해 | -308 | 확실한 전멸 |

**갈래에 따른 이 편차는 없애지 않는다.** 지도는 입장 전에 사건 제목과 분류를
공개하므로 플레이어는 어느 갈래가 더 위험한지 보고 고를 수 있다. 두 갈래가 같은
위험이면 갈래 선택이 의미를 잃는다. `E1`이 일반 사건 수와 정보 횟수만 대칭으로
맞추고 분류 구성은 맞추지 않은 이유이기도 하다.

C급은 개입하지 않아도 살아 돌아오고 S급은 개입하지 않으면 죽을 수 있다. 이 값들은
백테스트 이전의 프로토타입 상수이며 `C4` 보고서를 본 뒤 별도 커밋으로 조정한다.
상위 plan이 `수치가 목표와 다르면 코드를 임의로 맞추지 말고 보고서를 먼저 남긴
뒤`라고 정한 절차를 따른다.

## 선택지 태그 재부여

`lib/content/events.ts`의 선택지 27개에 라벨의 의도에 맞는 태그를 붙인다. F2가
쓴 라벨과 예상 이득·알려진 위험을 그대로 두고 태그만 더한다.

| 사건 | 선택지 | 태그 |
| --- | --- | --- |
| 고블린 매복 | 우회로를 알려준다 / 돌파한다 | `support` / `sabotage` |
| 거미 둥지 | 안전한 통로를 만든다 / 거미줄을 태운다 | `support` / `sabotage` |
| 무너진 다리 | 다리를 건넌다 / 우회로를 찾는다 | `sabotage` / `support` |
| 꺼져 가는 모닥불 | 식량을 나눈다 / 정보를 나눈다 | `rest` / `information` |
| 버려진 야영지 | 야영지를 조사한다 / 경계하고 잠든다 | `item` / `rest` |
| 부상당한 정찰병 | 정찰병을 돌본다 / 지나간다 | `rest` / `observe` |
| 그림자 행상인 | 소문을 산다 / 관찰한다 | `trade` / `observe` |
| 지도 장수 | 지도를 거래한다 / 직접 살핀다 | `trade` / `observe` |
| 약초 수레 | 치료 약초를 산다 / 성질만 묻는다 | `trade` / `information` |
| 봉인된 계약서 | 조건을 읽는다 / 봉인한 채 지나간다 | `information` / `observe` |
| 속삭이는 문 | 질문에 답한다 / 문을 연다 | `information` / `sabotage` |
| 불안정한 룬 | 룬을 안정시킨다 / 변화를 기록한다 | `support` / `information` |
| 보스의 알현실 | 보스 앞에 나아간다 / 방어를 정비한다 | `observe` / `support` |

라벨을 다시 쓰지 않는 이유는 F2가 승인받은 콘텐츠이기 때문이다. 태그가 라벨의
의도와 어긋나 보이면 라벨이 아니라 태그를 고칠 자리다.

## 거래

`trade` 태그가 붙은 선택지는 `itemId`로 상품을 가리킨다. 구매하면 현재 골드가
상품 가격만큼 줄고 그 상품의 효과가 **즉시** 적용된다.

소지품 목록을 만들지 않는 이유는 `ExpeditionState`에 넣을 자리가 없고, 사 두고
나중에 쓰는 선택은 이번 프로토타입의 결정 축이 아니기 때문이다. 상위 spec도
보스전 입력으로 `사용한 아이템`이라고만 적어 두었다.

잔액보다 비싼 구매는 `RuleError("INSUFFICIENT_GOLD")`를 던지고 **아무것도 바꾸지
않는다**. 골드만 빠지고 효과가 안 들어가는 중간 상태를 만들지 않는다.

구매는 현재 골드만 줄이고 누적 획득 골드는 줄이지 않는다.

## 사건 결과

```ts
resolveEventChoice(input: {
  campaign: CampaignState;
  expedition: ExpeditionState;
  event: DungeonEvent;
  choiceId: ChoiceId;
  grade: Grade;
  rng: Rng;
}): EventResolution
```

`EventResolution`은 갱신된 파티원, 갱신된 현재 골드, 탐험 로그 항목, 전멸 여부를
담는다. HP 변화는 살아 있는 출전 파티원 전원에게 같이 적용한다. 개인별로 다르게
적용하지 않는 이유는 사건이 파티 전체가 겪는 상황이기 때문이다. 개인차는 정보
카드 반응이 만든다.

HP가 0 이하가 되면 그 파티원은 사망한다. 전원이 죽으면 남은 지점과 보스전을
건너뛰고 실패 정산으로 간다.

신뢰는 `support`가 `protectAlly`, `sabotage`가 `betrayAlly`를 만든다. 나머지
태그는 즉시 신뢰를 바꾸지 않는다. 사건 행동으로 얻거나 잃는 신뢰까지 태그마다
따로 두면 조정할 상수가 두 배가 된다.

## 자동 보스전

```ts
resolveBossFight(input: {
  boss: BossDef;
  members: readonly CampaignMember[];
  infoRecords: readonly InfoRecord[];
  rng: Rng;
}): BossResolution
```

파티원마다 다음을 계산한다.

1. 그 파티원의 `infoRecords` 중 보스 주제인 것의 `modifier`를 합산한다
2. 합계를 `-0.3 ~ +0.5`로 자른다
3. `피해 = round(보스 기본 피해 × (1 + 보정))`
4. `남은 HP = max(0, 현재 HP - 피해)`

보정은 파티원마다 독립이고 기본 피해에 **한 번만** 적용한다. 한 명 이상 살아
남으면 `clear`, 전멸하면 `wipe`다.

이번 구현은 난수를 쓰지 않는다. 입력이 모두 정해지면 결과가 하나로 정해진다.
`rng`를 받아 두는 이유는 사후 검증의 신뢰 변동이 `evaluateTrust`를 통해 난수를
쓰기 때문이다.

## 사후 검증

보스전 뒤 미검증 기록을 검증해 신뢰를 움직이고 사람이 읽을 이유를 남긴다.

| 기록 | 검증 결과 |
| --- | --- |
| 수용한 거짓 | `deceptionExposed` |
| 의심했는데 거짓이었다 | `suspicionWasCorrect` |
| 의심했는데 진실·중립이었다 | `suspicionWasCostly` |

중립을 손해로 보는 이유는 수용했다면 보스 피해 `-10%`를 받았을 것이기 때문이다.
의심은 그 이득을 스스로 버린 선택이다.

죽은 파티원은 검증하지 않는다. 신뢰가 움직여도 갈 곳이 없다.

### 프로토타입 이후 방향: 턴제 보스전

지금 보스전은 파티원별로 피해를 한 번 계산하고 끝난다. 프로토타입을 마친 뒤
다음 방향으로 바꾸기로 했다.

- 용사 파티원과 보스가 턴제로 서로 공격한다
- 보스는 파티원의 직업과 전투 방식에 따라 **다른 확률로 공격 대상을 고른다**

이렇게 되면 직업 구성이 생존에 직접 영향을 주고, 길잡이가 어떤 파티를 어떤
던전에 보내는지가 더 중요한 결정이 된다. 지금 계약에서 바뀌는 것은
`resolveBossFight`의 내부와 `BossResolution`에 턴 기록이 붙는 정도이며,
입력 계약과 정보 보정 규칙은 그대로 쓸 수 있다.

## 테스트 목록

- 분류 기본값과 행동 보정이 등급 배율까지 반영해 계산된다
- 관망도 분류 기본값만큼 HP를 바꾼다
- 잔액 부족 거래는 오류를 던지고 상태를 바꾸지 않는다
- 거래는 현재 골드만 줄이고 누적 골드는 건드리지 않는다
- HP가 0 이하인 파티원은 사망하고 전원 사망이면 전멸이다
- `support`와 `sabotage`만 즉시 신뢰를 바꾼다
- 보스 보정 합산이 `-30%~+50%`로 잘린다
- 보정은 파티원마다 독립이고 기본 피해에 한 번만 적용된다
- 한 명이라도 살면 `clear`, 전원 사망이면 `wipe`
- 수용한 거짓·의심이 표대로 검증되고 죽은 사람은 검증하지 않는다
- 같은 입력과 시드가 같은 결과를 낸다
