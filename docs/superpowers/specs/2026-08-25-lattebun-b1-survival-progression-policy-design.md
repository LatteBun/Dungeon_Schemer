# B1 생존형 진행 정책 교정 설계

> 작성자: LatteBun  
> 작성 도구: Codex  
> 대상 작업: `B1` 후속 진단  
> 상태: 사용자 설계 승인 완료 · 구현 계획 작성 전

## 1. 문제와 결정

현행 백테스트의 생존형 전략은 진입 가능한 공고 중 위험도가 가장 낮은 던전을
항상 먼저 고른다. 이 정책은 개별 원정의 생존에는 유리하지만, 현재 명성 승급
구조가 전제하는 진행 순서와 충돌한다. 낮은 위험도 보상만 먼저 소비하면 다음
승급에 필요한 명성을 모으기 전에 낮은 위험도 던전이 바닥나고, 살아 있는
캐릭터와 편성 가능한 파티가 남아 있어도 모든 잔여 공고가 등급 제한에 걸려
`실직`으로 끝날 수 있다.

PR #161 이후의 B1 결과에서도 보스 사망이 큰 손실 원인이었지만, 별도 진단에서는
전투 손실만으로 설명되지 않는 진행 정지가 확인되었다. 폐기할 보스 배율 후보로
실행한 50시드 구조 진단에서 `survival@0.7`은 완료 5건, 실직 35건, 인력 소진
10건이었다. 실직 35건은 모두 편성 인력 부족이 아니라, 현재 등급보다 높은
위험도의 공고만 남고 승급 자원이 부족한 상태였다. 이 수치는 정식 calibration
결과나 밸런스 채택 근거로 사용하지 않고 정책 결함을 재현한 진단 증거로만 둔다.

이번 변경은 게임의 보상·승급·전투 규칙을 바꾸지 않는다. 백테스트 생존형의 공고
선택을 **진행 잠금이 보이는 동안에는 현재 접근 가능한 최고 위험도를 먼저
공략하는 정책**으로 교정한다. 같은 위험도에서는 파티 생존 여건을 우선한다.
진행 잠금이 없으면 기존의 낮은 위험도 우선 정책으로 돌아간다.

## 2. 목표와 비목표

### 목표

- 생존형이 공개된 등급 잠금을 보고 다음 명성 승급까지 진행할 수 있는 공고를
  선택하게 한다.
- 같은 위험도의 공고 사이에서는 파티 최소 HP 비율과 최소 신뢰가 높은 쪽을
  선택해 생존형의 정체성을 유지한다.
- 생존형과 생존형으로 복귀한 선별적 배신형이 같은 정책을 결정적으로 공유한다.
- 교정 전후를 같은 시드와 현행 게임 설정으로 비교해 실직·인력 소진·완주·승급
  분포가 어떻게 변했는지 분리해서 보고한다.

### 비목표

- 보스·일반 몬스터·월드턴·보상·승급 요구치·던전 분포를 바꾸지 않는다.
- 사용자가 승인한 새 위험도별 첫 시도 목표 구간이나 보스 배율 후보를 이번
  변경에 적용하지 않는다.
- 기회주의형과 선별적 배신형의 배신 후보 판정·경로·조언·승급 정책을 재설계하지
  않는다.
- 숨은 미래 공고, 조언 정답, 전투 결과 또는 비공개 캠페인 상태를 전략에 노출하지
  않는다.
- B1 holdout을 실행하거나 승인 상태를 변경하지 않는다.

## 3. 생존형 공고 선택 계약

### 3.1 진행 잠금 판정

게시판의 공개 `BoardDecisionView`만 사용해 다음 조건을 모두 만족하면
`progressionLocked`로 판정한다.

1. 현재 등급이 S가 아니어서 `promotion` 정보가 존재한다.
2. 게시판에 `lockReason === "rankTooLow"`인 공고가 하나 이상 있다.
3. 그 공고의 위험도가 `promotion.newlyUnlockedRiskLevel` 이상이다.

이 판정은 이미 공개된 공고와 승급 안내만 읽는다. 아직 게시판에 나오지 않은
던전의 순서·보상·위험도를 미리 읽거나 남은 보상의 합계를 추정하지 않는다.

생존형의 기존 승급 결정은 공고 선택보다 먼저 적용한다. 명성 승급이 가능하면
즉시 승급하고, 골드 승급은 기존의 보수적 조건을 그대로 따른다. 승급을 하지 않은
채 공고를 골라야 할 때만 아래 정렬을 사용한다.

### 3.2 진행 잠금이 있을 때

진입 가능한 공고를 다음 순서로 정렬해 첫 공고를 선택한다.

1. 현재 위험도 내림차순
2. 파티 최소 HP 비율 내림차순
3. 파티 최소 신뢰 내림차순
4. 공고 ID 오름차순의 결정적 동률 해소

명성이나 골드 보상 자체는 비교 항목에 넣지 않는다. 따라서 이 정책은 보상이 가장
큰 공고를 고르는 기회주의형이 아니라, 공식 기준 진행처럼 현재 등급에서 감당해야
할 위험도 구간을 먼저 소진하되 같은 위험도에서는 더 건강하고 신뢰가 높은 파티를
선택하는 생존형이다.

### 3.3 진행 잠금이 없을 때

기존 정렬을 유지한다.

1. 현재 위험도 오름차순
2. 파티 최소 HP 비율 내림차순
3. 파티 최소 신뢰 내림차순
4. 공고 ID 오름차순의 결정적 동률 해소

S등급에서는 `promotion`이 없으므로 항상 이 경로를 사용한다. 하위 등급이라도 현재
게시판에 등급 잠금 공고가 없다면 낮은 위험도 우선 정책을 유지한다.

## 4. 다른 전략과의 경계

기회주의형은 계속 위험도 내림차순 뒤 명성 보상·골드 보상을 차례로 비교한다.
생존형은 진행 잠금 구간에서 위험도 방향만 같고, 같은 위험도에서는 보상이 아니라
파티의 최소 HP와 신뢰를 우선한다. 경로 category, 상인 reserve, 조언 의도와 골드
승급 조건도 기존 차이를 유지한다.

선별적 배신형은 기존처럼 공개된 인력 capacity와 파티 소지 골드로 배신 후보를
먼저 찾는다. 배신 후보가 있으면 기존 선택을 유지한다. 후보가 없어 생존형으로
복귀할 때는 교정된 생존형 공고 정책을 그대로 사용한다. 이는 새로운 배신 행동이
아니라 기존 설계의 “비배신 모드는 생존형” 계약을 일관되게 적용하는 것이다.

## 5. 구현 경계

- 공고 정렬 변경은 `lib/backtest/strategies.ts`의 전략 계층에만 둔다.
- `BoardDecisionView`에는 판정에 필요한 공개 정보가 이미 있으므로 필드를 추가하지
  않는다.
- 프로덕션 Store, 캠페인 전이, 게시판 생성, 승급 및 엔딩 판정은 변경하지 않는다.
- 기존 B1-A 설계의 7.1 생존형 공고 정렬은 이 문서가 후속 교정으로 대체한다. 그
  밖의 생존형 경로·조언·승급 규칙은 기존 설계를 유지한다.
- 선택 가능한 공고가 하나도 없는 경우의 기존 오류 처리를 완화하지 않는다.
  정상적인 `실직` 판정과 잘못 호출된 전략 결정을 숨기지 않아야 한다.

## 6. 테스트 설계

### 6.1 단위 테스트

- 등급 잠금 공고가 있으면 진입 가능한 공고 중 최고 위험도를 고른다.
- 최고 위험도가 같은 공고는 파티 최소 HP 비율, 최소 신뢰, 공고 ID 순으로 고른다.
- 명성·골드 보상이 더 크더라도 위험도와 파티 안전성 우선순위를 뒤집지 않는다.
- 등급 잠금 공고가 없으면 기존처럼 최저 위험도를 고른다.
- S등급에서는 최저 위험도 정책을 사용한다.
- 명성 승급 가능 시 기존 승급 결정이 공고 선택보다 우선한다.
- 골드 승급의 기존 진입 가능 공고 수와 merchant reserve 조건은 변하지 않는다.
- 선별적 배신형은 후보가 없을 때 교정된 생존형 선택을 사용하고, 후보가 있으면
  기존 배신 선택을 유지한다.
- 동일한 view는 반복 실행해 같은 결정을 반환한다.

### 6.2 실제 Store 진단

게임 설정과 시드 namespace를 고정하고 교정 전후를 비교한다.

1. 조합당 50시드로 3전략 × 2정확도의 전이 오류·결정성·종료 사유를 확인한다.
2. 구조 문제가 없으면 조합당 200시드 calibration을 실행한다.
3. 전략·정확도별 완주, 실직, 인력 소진, 불신, 고발, run error와 최종 등급을
   보고한다.
4. 승급별 도달률과 승급 시점, 종료 시 남은 던전의 위험도 분포를 함께 기록해
   실직 감소가 실제 진행 개선인지 확인한다.
5. 같은 시드의 교정 전후 차이를 보고하되, 개선 폭을 맞추기 위해 전략 조건이나
   프로덕션 수치를 추가로 튜닝하지 않는다.

이번 변경의 합격 조건은 정책 단위 테스트, 공개 정보 경계, 결정성, run error 0과
교정 전후 진단 보고의 완전성이다. B1-B 완주율 gate 또는 위험도별 클리어율 목표를
통과하지 못해도 이 변경을 실패로 숨기지 않는다. 남은 차이는 다음 밸런스 설계의
입력으로 사용한다.

## 7. 후속 밸런스와 holdout 경계

사용자가 별도로 승인한 다음 위험도별 첫 시도 목표는 이번 구현에서 acceptance
상수로 옮기지 않는다.

| 초기 위험도 | 후속 목표 구간 |
| --- | ---: |
| ★1 | 85~90% |
| ★2 | 78~85% |
| ★3 | 70~78% |
| ★4 | 62~70% |
| ★5 | 55~65% |

생존형 정책 교정의 200시드 결과를 먼저 검토한 뒤, 위 구간과 엄격한 위험도
내림차순을 채택하는 별도 밸런스 spec에서 acceptance 상수, 보스 배율, 공식 문서
갱신 범위를 정한다. 그 단계에서도 한 번에 한 밸런스 축만 조정한다.

새 목표와 수치가 동결되고 사용자 승인을 받기 전에는 기존 holdout을 실행하지
않는다. calibration 결과를 보고 수치를 바꾸면 새 revision과 새 holdout seed
namespace를 사용한다.

## 8. 문서 영향

이번 설계는 플레이어가 사용하는 게임 규칙을 바꾸지 않으므로
`GAME_PRINCIPLES.md`와 `PROGRESSION_AND_ENDINGS.md`의 보상·승급·엔딩 규칙은
수정하지 않는다. `docs/README.md`에는 이 후속 설계를 B1 문서 목록에 추가한다.
구현 결과와 진단 수치는 생성 보고서에 기록하고, 수치가 확정되기 전 공식 규칙처럼
문서화하지 않는다.

## 9. 완료 기준

다음이 모두 충족되어야 이번 생존형 진행 정책 교정을 완료로 판단한다.

1. 진행 잠금 유무에 따른 두 공고 정렬이 단위 테스트로 고정된다.
2. 전략은 기존 `BoardDecisionView` 밖의 비공개 정보를 읽지 않는다.
3. 기존 승급 정책과 기회주의형·배신 후보 정책에 의도하지 않은 변경이 없다.
4. 50시드와 200시드 실제 Store 실행이 오류 없이 결정적으로 끝난다.
5. 교정 전후의 종료 사유·승급·완주·최종 등급 변화가 같은 시드 기준으로 보고된다.
6. 후속 보스 밸런스와 새 위험도별 목표는 별도 승인 전까지 코드에 적용되지 않는다.
