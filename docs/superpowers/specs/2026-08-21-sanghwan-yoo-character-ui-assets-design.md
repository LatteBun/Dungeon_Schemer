# 캐릭터 UI 에셋 패키지 설계

작성 도구: Codex

## 목적

직업별 캐릭터 UI 에셋의 생존·사망 상태와 변형을 저장소에 추가하고, 향후 파티 카드·상태 패널·결과 UI가 게임 상태에 맞는 이미지를 재사용할 수 있도록 자산 카탈로그와 공식 문서 연결을 만든다.

## 범위

- `public/assets/characters/`의 캐릭터 PNG 20개를 추가한다.
- `docs/experience/CHARACTER_UI_ASSETS.md`에 경로 규칙, 실제 해상도, 상태별 사용 조건, UI 재사용 규칙을 기록한다.
- `docs/systems/CHARACTERS_AND_TRUST.md`의 관련 문서 목록에 위 카탈로그를 연결한다.
- 캐릭터 ID별 초상 매핑, UI 컴포넌트, 게임 상태·신뢰 규칙, 이미지 변환·리사이즈는 변경하지 않는다.

## 에셋 계약

캐릭터 파일은 아래 고정 패턴을 따른다.

```text
public/assets/characters/{live|dead}/{archer|cleric|mage|rogue|warrior}/{class}_{a|b}.png
```

각 상태에 궁수·성직자·마법사·도적·전사의 `a`, `b` 변형이 하나씩 있어 총 20개다.

| 직업 디렉터리 | 표시 직업 | 변형 | `live`·`dead` 원본 해상도 |
| --- | --- | --- | --- |
| `archer` | 궁수 | `archer_a`, `archer_b` | 1024×1536 |
| `cleric` | 성직자 | `cleric_a`, `cleric_b` | 1024×1536 |
| `mage` | 마법사 | `mage_a`, `mage_b` | 1024×1536 |
| `rogue` | 도적 | `rogue_a`, `rogue_b` | 1024×1536 |
| `warrior` | 전사 | `warrior_a`, `warrior_b` | 1086×1448 |

모든 경로는 `/assets/characters/<상태>/<직업>/<파일명>.png`으로 정적 제공된다. `a`·`b`는 시각 변형일 뿐 성격, 신뢰, 고유 캐릭터 ID, 능력치를 뜻하지 않는다.

## 상태와 UI 재사용 규칙

- `live`는 도메인에서 생존으로 판정된 캐릭터의 파티 카드, 우측 상태 패널, 게시판 계약 상세, 진행 화면에 사용한다.
- `dead`는 실제 사망이 확정된 캐릭터의 정산·사망 결과·기록 UI에만 사용한다.
- 신뢰 0, 중상, 현재 미출전, 잠시 출전 불가 상태는 사망이 아니므로 `dead` 에셋을 사용하지 않는다.
- 캐릭터 ID별로 `a`·`b` 중 어느 변형을 쓸지 정하는 작업은 별도 UI·도메인 매핑 설계로 분리한다. 그때 같은 캐릭터가 화면·세션 사이에서 무작위로 바뀌지 않게 안정적인 매핑을 정의한다.
- 세로 초상은 표시 슬롯에서 비율을 왜곡하지 않고 `object-fit: contain`을 기본으로 한다. 의도된 crop은 해당 UI 작업 문서가 승인해야 한다.

## 문서 구조

```text
docs/systems/CHARACTERS_AND_TRUST.md
└─ 캐릭터 UI 에셋 카탈로그 링크

docs/experience/CHARACTER_UI_ASSETS.md
└─ 경로 패턴 · 직업/변형 목록 · 생존/사망 사용 조건 · UI 재사용 규칙
```

시스템 문서는 캐릭터 생존·신뢰의 의미를 계속 소유하고, 카탈로그는 그것을 어떤 자산으로 표시할지 안내한다. 카탈로그는 신뢰·HP·출전 가능 규칙을 새로 정의하지 않는다.

## 오류 방지와 검증

- 추가하는 20개 파일이 모두 PNG이고, 상태·직업·변형 조합이 빠짐없이 존재하는지 확인한다.
- 카탈로그의 직업 이름이 공식 캐릭터 문서의 5직업과 일치하는지 확인한다.
- `dead`가 신뢰 0과 구분된다는 문서 규칙을 검토한다.
- Markdown 링크가 실제 파일을 가리키는지 문서 검증 테스트로 확인한다.
- 코드 변경이 없으므로 자산·문서 변경 후 기존 typecheck와 test를 실행한다.

## 완료 조건

- 생존·사망 상태 각각에 5직업 × 2변형 자산이 한 PR에만 포함된다.
- 향후 UI 작업자가 상태별 사용 조건과 안정적 변형 매핑의 필요성을 문서에서 확인할 수 있다.
- 사막·거미굴 몬스터 자산 및 UI 컴포넌트는 이 PR에 포함하지 않는다.
