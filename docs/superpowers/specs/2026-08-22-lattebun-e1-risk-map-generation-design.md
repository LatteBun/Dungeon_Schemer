# E1 위험도별 지도 생성 설계

## 이 문서의 지위

이 문서는 캠페인 개편 작업의 `E1 | 위험도별 지도 생성`을 구현하기 위한 정식 설계다.

현재 공식 문서인 `docs/systems/DUNGEON_EVENTS_AND_BOSSES.md`와 `docs/technical/CAMPAIGN_REWORK_WORK_ASSIGNMENT.md`에는 E1 브레인스토밍 이전 규칙인 `6~8 일반 지점 = 지도 전체 일반 노드 수`와 `강한 연계용 전 경로 공통 지점`이 남아 있다. 이번 설계에서는 두 규칙을 아래처럼 교체한다.

- `6~8`은 지도 전체 노드 수가 아니라 **어떤 경로를 선택해도 실제로 통과하는 일반 Depth 수**다.
- 공통 일반 지점은 강제하지 않는다. 강한 연계는 E3가 **서로 다른 Depth를 연계 슬롯으로 선택**해서 보장한다.

이 설계가 승인된 뒤 E1 구현에서 관련 공식 문서와 완료 기준을 함께 갱신한다. 옛 C/B/A/S 지도 생성 설계는 알고리즘 참고 자료일 뿐 현재 요구사항의 근거로 사용하지 않는다.

---

## 1. 목표

E1은 플레이어가 입구에서 보스까지 이동할 **재현 가능한 논리 던전 그래프**를 생성한다.

합격하는 지도는 다음 성질을 동시에 가진다.

1. 던전처럼 여러 갈래가 존재한다.
2. 역주행과 같은 층 이동이 없다.
3. 지도에 존재하는 모든 노드는 입구에서 도달할 수 있다.
4. 지도에 존재하는 모든 노드는 최종적으로 보스에게 도달한다.
5. 어느 길을 골라도 같은 수의 일반 Depth를 경험한다.
6. 한 노드의 진입·진출 경로가 지나치게 몰리지 않는다.
7. 실패 후 재도전하면 논리 지도가 다시 생성되지만 초기 위험도 기반 규모와 보스는 유지된다.
8. 동일한 입력은 항상 동일한 논리 지도를 만든다.

E1은 사건 내용, 몬스터, 상인, 강한 연계 사건, 화면 좌표를 생성하지 않는다.

---

## 2. 지도 모델

### 2-1. 층형 DAG

지도는 `Entry -> Depth 1 -> ... -> Depth N -> Boss` 형태의 층형 DAG다.

```text
Entry
  ↓
Depth 1
  ↓
Depth 2
  ↓
...
  ↓
Depth N
  ↓
Boss
```

모든 일반 간선은 오직 `Depth N -> Depth N+1`로 향한다.

- 역주행 없음
- 같은 Depth 내 간선 없음
- Depth 건너뛰기 없음
- 순환 없음

따라서 정상 경로는 Entry에서 시작해 각 일반 Depth에서 정확히 노드 하나를 지나고 Boss에 도착한다.

### 2-2. 초기 위험도별 Depth

| 초기 위험도 | 일반 Depth 수 |
| --- | ---: |
| ★1 | 6 |
| ★2 | 6 |
| ★3 | 7 |
| ★4 | 8 |
| ★5 | 8 |

Entry와 Boss는 일반 Depth에 포함하지 않는다.

`initialRiskLevel`이 지도 깊이와 템플릿 풀을 정한다. 실패로 `riskLevel`이 올라가도 이 값은 바뀌지 않는다.

### 2-3. Depth 폭

각 일반 Depth에는 **1~5개**의 일반 노드가 존재할 수 있다.

추가 제약은 다음과 같다.

- Depth 1의 노드 수는 최대 2개다.
- 마지막 Depth의 노드 수는 최대 2개다.
- 중간 Depth는 최대 5개다.
- 인접 Depth의 폭은 서로 최대 2배까지만 증가하거나 감소할 수 있다.

마지막 조건은 진입·진출 최대 2개 계약 아래에서 모든 노드를 살릴 수 있는 필요 조건이기도 하다.

허용 예:

```text
2 -> 4
4 -> 2
3 -> 5
5 -> 3
```

금지 예:

```text
1 -> 3
2 -> 5
5 -> 2
4 -> 1
```

### 2-4. 노드 차수

일반 노드는 다음 범위를 만족한다.

- incoming: 1~2
- outgoing: 1~2

예외:

- Entry는 incoming 0, outgoing 1~2
- Boss는 incoming 1~2, outgoing 0

이 제한으로 `4개 방 -> 1개 방`처럼 심한 깔때기 모양을 금지한다.

```text
허용
○ ○ ○ ○
 ╲╱ ╲╱
 ○   ○

금지
○ ○ ○ ○
 ╲│╱╱
   ○
```

### 2-5. 공통 지점은 요구하지 않는다

이전 설계의 `모든 경로가 반드시 지나는 일반 지점` 계약은 제거한다.

분기는 중간에 합류할 수 있고 다시 갈라질 수 있지만, 특정 일반 노드로 모든 경로를 강제로 모으지 않는다. 모든 경로가 마지막에 Boss로 수렴하는 것만 보장한다.

강한 연계 사건의 도달성은 E3가 노드가 아니라 **Depth 단위**로 해결한다.

---

## 3. 위험도별 폭 성격

위험도가 높을수록 같은 Depth에서 볼 수 있는 경로의 밀도가 높아진다.

| 초기 위험도 | Depth | 목표 평균 폭 |
| --- | ---: | ---: |
| ★1 | 6 | 1.5~2.0 |
| ★2 | 6 | 2.0~2.5 |
| ★3 | 7 | 2.5~3.0 |
| ★4 | 8 | 3.0~3.5 |
| ★5 | 8 | 3.5~4.0 |

`5개`는 상한이지 매 Depth의 목표값이 아니다. 폭은 일정한 격자보다 넓어졌다 좁아지는 리듬을 가진다.

## 4. 템플릿 시스템

### 4-1. 역할

템플릿은 실제 간선을 고정하지 않는다. 템플릿이 고정하는 것은 다음뿐이다.

- 템플릿 ID
- 대상 초기 위험도
- 각 Depth의 노드 수(`layerWidths`)

```ts
interface MapTemplate {
  id: string;
  riskLevel: RiskLevel;
  layerWidths: readonly number[];
}
```

실제 간선은 선택된 템플릿의 폭을 사용해 시드 기반으로 생성한다.

### 4-2. 위험도별 전용 풀

총 16개를 사용한다.

| 위험도 | 템플릿 수 |
| --- | ---: |
| ★1 | 3 |
| ★2 | 3 |
| ★3 | 3 |
| ★4 | 4 |
| ★5 | 3 |
| 합계 | 16 |

### 4-3. 확정 템플릿

아래 배열은 Depth 1부터 마지막 Depth까지의 노드 수다.

| ID | 초기 위험도 | `layerWidths` | 평균 폭 |
| --- | --- | --- | ---: |
| `risk1-a` | ★1 | `[1, 2, 2, 2, 2, 1]` | 1.67 |
| `risk1-b` | ★1 | `[2, 2, 3, 2, 1, 2]` | 2.00 |
| `risk1-c` | ★1 | `[1, 2, 3, 2, 2, 2]` | 2.00 |
| `risk2-a` | ★2 | `[2, 3, 3, 2, 3, 2]` | 2.50 |
| `risk2-b` | ★2 | `[2, 3, 2, 4, 2, 2]` | 2.50 |
| `risk2-c` | ★2 | `[2, 2, 3, 3, 2, 2]` | 2.33 |

## 5. 간선 생성

### 5-1. 목표

같은 템플릿이라도 재도전 시 연결 모양이 달라질 수 있다. 다만 무작위 간선을 만든 뒤 성공할 때까지 재추첨하는 방식은 사용하지 않는다.

각 인접 Depth 쌍에 대해 처음부터 유효한 이분 그래프를 만든다.

### 5-2. 단계

현재 Depth의 노드 집합을 `A`, 다음 Depth를 `B`라고 한다.

1. 모든 `B` 노드가 최소 incoming 1을 받도록 연결한다.
2. 모든 `A` 노드가 최소 outgoing 1을 갖도록 부족한 연결을 보완한다.
3. 양쪽의 남은 차수가 있을 때 시드 기반으로 추가 교차 간선을 넣어 분기 밀도를 만든다.
4. 중복 간선은 만들지 않는다.
5. 모든 노드의 incoming/outgoing이 2를 넘지 않는지 확인한다.

`max(|A|, |B|) <= 2 * min(|A|, |B|)`인 템플릿 폭만 허용하므로 최소 연결을 항상 구성할 수 있다.

추가 간선은 지도 다양성을 위한 선택 사항이며, 없어도 모든 노드의 도달성과 진행 가능성이 충족되어야 한다.

### 5-3. Entry와 Boss

- Entry는 Depth 1의 모든 노드에 연결한다. Depth 1이 최대 2개이므로 outgoing 최대 2를 만족한다.
- 마지막 Depth의 모든 노드는 Boss에 연결한다. 마지막 Depth가 최대 2개이므로 Boss incoming 최대 2를 만족한다.

## 6. 데이터 계약

현재 `DungeonNode`는 유지한다.

```ts
export interface DungeonNode {
  id: NodeId;
  kind: NodeKind;
  nextNodeIds: readonly NodeId[];
}
```

`GeneratedMap`에는 Depth를 명시하는 `layers`를 추가한다.

```ts
export interface DungeonLayer {
  depth: number;
  nodeIds: readonly NodeId[];
}

export interface GeneratedMap {
  entryNodeId: NodeId;
  bossNodeId: NodeId;
  layers: readonly DungeonLayer[];
  nodes: readonly DungeonNode[];
}
```

`layers[index].depth === index + 1`을 항상 만족한다.

각 일반 `NodeId`는 정확히 하나의 layer에만 속한다. Entry와 Boss는 `layers`에 포함하지 않는다.

`commonNodeIds` 또는 `isCommon`은 추가하지 않는다.

노드 ID는 같은 입력에서 재현 가능하고 한 지도 안에서 유일해야 한다. 구현 시 `dungeonId`, `attempt`, `depth`, layer 내 index를 포함하는 결정적 ID를 사용한다. 재도전 지도는 이전 attempt와 다른 NodeId 공간을 사용한다.

## 7. 생성 API와 재현성

E1의 순수 규칙 API는 다음 정보를 입력으로 받는다.

```ts
generateDungeonMap({
  campaignSeed,
  dungeonId,
  initialRiskLevel,
  attempt,
}): GeneratedMap
```

`riskLevel`과 `bossId`는 입력하지 않는다.

- 현재 위험도는 E1의 지도 구조를 바꾸지 않는다.
- 보스는 `CampaignDungeon.bossId`에 이미 고정되어 있으며 E1이 읽거나 변경할 이유가 없다.

### 7-1. 템플릿 순환

`campaignSeed + dungeonId`로 해당 던전의 위험도 전용 템플릿 풀을 한 번 결정적으로 shuffle한다.

예:

```text
★4 pool: A B C D
던전 전용 순서: C -> A -> D -> B

attempt 0: C
attempt 1: A
attempt 2: D
attempt 3: B
attempt 4: C
```

템플릿 풀이 최소 3개이므로 순환 경계에서도 직전 템플릿과 같은 항목이 연속될 수 없다.

별도 `previousTemplateId` 상태를 저장하지 않는다.

### 7-2. RNG 분리

현재 RNG의 `map` 스트림을 사용하되 템플릿 순서와 attempt별 간선 생성이 호출 순서에 영향을 주지 않도록 root seed 문자열을 분리한다.

권장 구성:

```text
createRng(`${campaignSeed}:${dungeonId}:template-order`).derive("map")
createRng(`${campaignSeed}:${dungeonId}:attempt:${attempt}`).derive("map")
```

같은 `campaignSeed + dungeonId + initialRiskLevel + attempt`는 항상 같은 템플릿, 같은 간선, 같은 NodeId를 생성해야 한다.

### 7-3. 재도전

실패 후 `attempt`가 증가하면:

변함:

- 선택되는 템플릿
- 실제 간선 구조
- E3에서 이후 배치될 사건

유지:

- `initialRiskLevel`
- 일반 Depth 수
- 위험도 전용 템플릿 풀
- 던전 테마와 활성 생태 규칙
- 보스

`riskLevel`이 ★5까지 상승하더라도 지도는 초기 위험도 풀을 계속 사용한다.

## 8. 강한 연계와 E3 경계

강한 연계를 위해 지도를 한 노드로 합류시키지 않는다.

E3는 E1의 `GeneratedMap.layers`를 사용해 연계 사건을 Depth 단위로 배치한다.

- ★1·★2: 강한 연계 없음
- ★3·★4: 강한 연계 1쌍 -> 서로 다른 Depth 2곳
- ★5: 강한 연계 2쌍 -> 서로 다른 Depth 4곳

한 연계쌍은 반드시 `선행 Depth < 후행 Depth`를 만족한다.

특정 Depth가 연계 슬롯이면 플레이어가 그 Depth에서 실제로 선택해 들어간 노드에서 해당 연계 사건이 발생한다. 따라서 경로가 넓게 유지되어도 플레이어는 연계 사건을 놓치지 않는다.

연계 Depth 선정, 사건 콘텐츠 선정, 단서 조건 판정은 E3 책임이며 E1은 알지 못한다.

---

## 9. U4 경계

E1은 논리 그래프만 만든다.

U4가 담당한다.

- X/Y 화면 좌표
- 같은 Depth 안 노드 간 간격
- 연결선 곡선
- 시각적 좌우 반전
- 불규칙한 던전 실루엣

따라서 좌우 반전은 별도 E1 템플릿이나 논리 지도 변형으로 계산하지 않는다. 같은 논리 그래프를 U4가 다른 시각 배치로 표현할 수 있다.

## 10. 오류 처리와 최종 검증

잘못된 생성 결과를 숨기기 위해 재추첨하지 않는다.

템플릿 또는 생성 결과가 계약을 깨면:

```ts
throw new RuleError("INVALID_GENERATION", message, details)
```

을 사용한다.

최종 검증기는 최소 다음을 확인한다.

1. 초기 위험도별 Depth 수가 `6 / 6 / 7 / 8 / 8`인지
2. 모든 Depth 폭이 1~5인지
3. 첫·마지막 Depth 폭이 최대 2인지
4. 인접 Depth 폭이 최대 2배 제약을 만족하는지
5. `layers[index].depth === index + 1`인지
6. 모든 일반 노드가 정확히 하나의 layer에 속하는지
7. 모든 간선이 Entry->D1, Dn->D(n+1), 마지막 Depth->Boss 중 하나인지
8. 일반 노드 incoming/outgoing이 1~2인지
9. Entry outgoing과 Boss incoming이 1~2인지
10. 중복 간선이 없는지
11. 존재하지 않는 NodeId를 참조하지 않는지
12. 모든 일반 노드가 Entry에서 도달 가능한지
13. 모든 일반 노드에서 Boss로 도달 가능한지
14. 모든 Entry->Boss 경로가 정확히 같은 일반 Depth 수를 거치는지
15. NodeId가 지도 안에서 유일한지

생성기가 구조적으로 보장하는 조건도 검증기에서 다시 확인한다. 검증기는 템플릿 오류와 구현 회귀를 조기에 드러내는 안전망이다.

## 11. 테스트 범위

### 템플릿 계약

- 16개 ID가 모두 유일하다.
- 위험도별 수가 `3 / 3 / 3 / 4 / 3`이다.
- 모든 배열 길이가 위험도별 Depth 계약과 일치한다.
- 모든 폭과 인접 폭 조건이 유효하다.
- 평균 폭이 위험도별 목표 범위에 들어온다.

### 생성 구조

각 위험도와 여러 seed에 대해:

- 모든 노드 도달성
- 모든 노드 Boss 도달성
- degree 1~2
- 최대 폭 5
- 다음 Depth 전용 간선
- 동일 경로 길이
- 막다른 길 없음
- 중복/유령 NodeId 없음

을 검사한다.

### 결정성

- 같은 seed/dungeon/attempt -> 완전히 같은 `GeneratedMap`
- 같은 dungeon의 attempt 증가 -> 직전과 다른 템플릿
- template pool 한 바퀴 뒤 -> 같은 순서가 재현됨
- 다른 dungeonId -> 독립적인 템플릿 순서/간선 결과

### 위험도 분리

- 현재 `riskLevel` 상승은 E1 결과에 영향을 주지 않는다.
- `initialRiskLevel`이 같으면 Depth 계약은 유지된다.
- E1은 `CampaignDungeon.bossId`를 수정하지 않는다.

### 오류

의도적으로 깨진 템플릿/그래프를 validator에 넣어 `RuleError("INVALID_GENERATION", ...)`를 확인한다.

## 13. 공식 문서 갱신 요구

E1 구현과 함께 다음 문서의 옛 규칙을 갱신한다.

### `docs/systems/DUNGEON_EVENTS_AND_BOSSES.md`

변경 전:

- 위험도별 `일반 지점 6~8`을 지도 전체 노드 수로 해석
- 모든 경로 공통 일반 지점 요구
- ★3·★4 공통 지점 2, ★5 공통 지점 4 보장

변경 후:

- 위험도별 `일반 Depth 6 / 6 / 7 / 8 / 8`
- 각 Depth에 일반 노드 1~5개
- 모든 경로가 같은 Depth 수를 통과
- 공통 일반 지점 강제 없음
- 강한 연계는 E3의 Depth 슬롯 계약으로 이동

### `docs/technical/CAMPAIGN_REWORK_WORK_ASSIGNMENT.md`

E1 완료 기준을 이 설계에 맞게 바꾼다. 핵심은 다음이다.

> 초기 위험도로 정해진 6~8 일반 Depth가 실패 뒤에도 고정되고, 각 Depth에 1~5개 노드가 있으며, 한 노드의 진입·진출이 각각 최대 2개이고 모든 노드가 Entry에서 도달 가능하며 Boss로 이어진다. 모든 경로 길이는 같고, 재도전 시 지도만 재생성되며 보스가 유지된다. 위험도별 전용 16개 폭 템플릿과 결정적 재도전 순환을 사용하고, 생성 불변식을 만족하지 못하면 `INVALID_GENERATION`으로 실패한다.

E3 완료 기준의 강한 연계 표현도 `공통 지점`에서 `서로 다른 Depth 슬롯`으로 바꾼다.

## 14. 완료 기준

E1은 다음이 모두 충족되면 완료다.

- 이 문서의 16개 위험도 전용 템플릿이 코드에 존재한다.
- `GeneratedMap.layers`가 공식 도메인 계약에 추가된다.
- 층형 DAG 생성기가 모든 구조 불변식을 만족한다.
- 최대 노드 폭 5, incoming/outgoing 최대 2를 지킨다.
- 모든 노드가 Entry에서 도달 가능하고 Boss로 이어진다.
- 모든 경로가 위험도별 6~8개의 일반 Depth를 동일하게 지난다.
- 재도전은 초기 위험도 풀을 유지하면서 직전과 다른 템플릿으로 결정적으로 순환한다.
- 동일 입력의 논리 지도가 완전히 재현된다.
- 공통 일반 지점 계약이 제거되고 E3가 사용할 Depth 계약이 제공된다.
- E1 관련 공식 문서가 새 계약으로 갱신된다.
- 전체 템플릿/구조/결정성/오류 테스트가 통과한다.
