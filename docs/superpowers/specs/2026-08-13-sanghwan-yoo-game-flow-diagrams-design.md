# 게임 흐름 다이어그램과 화면 와이어프레임 설계

> 상태: 사용자 승인됨
> 작성일: 2026-08-13
> 작성자: SangHwan Yoo
> 작성 도구: Codex

## 목적

최신 `Dungeon Schemer` 문서를 처음 읽는 사람도 캠페인 전체 흐름, 한 번의 던전
탐험, 허용된 상태 전이와 핵심 화면 구성을 빠르게 파악할 수 있는 시각 자료를
`docs/diagram`에 만든다.

자료는 Git에서 검토하고 수정할 수 있는 Markdown 원본과 확대 가능한 SVG, IDE와
Pull Request에서 바로 볼 수 있는 PNG를 함께 제공한다. 초기 화면 스케치인
`docs/initialization/proto_image.png`의 조우·지도·결과 구도를 살리되, 현재 공식
기준인 던전 15개 캠페인 구조로 다시 해석한다.

## 근거와 우선순위

시각 자료는 다음 문서를 우선순위대로 파생해 표현한다.

1. [게임 원칙](../../GAME_PRINCIPLES.md)
2. [게임 개요](../../design/GAME_OVERVIEW.md),
   [핵심 게임 루프](../../design/CORE_GAME_LOOP.md), `docs/systems`의 공식 규칙
3. [온보딩과 인터페이스](../../experience/ONBOARDING_AND_INTERFACE.md)
4. [게임 방향 개편 설계](2026-08-13-sanghwan-yoo-game-direction-rework-design.md)
5. `제품 요구사항 대체됨` 표시가 있는 과거 spec·plan과 초기 원본 자료

다이어그램과 공식 문서가 충돌하면 공식 문서가 기준이다. 시각 자료는 새 게임
규칙을 정의하지 않고 기존 규칙을 이해하기 쉽게 요약한다. 따라서 이번 작업은
`GAME_PRINCIPLES.md`나 시스템 규칙을 수정하지 않는다.

## 범위

### 포함

- 캠페인 시퀀스 다이어그램 1장
- 탐험 시퀀스 다이어그램 1장
- 캠페인 상태 전이 다이어그램 1장
- 탐험 상태 전이 다이어그램 1장
- 대표 화면 와이어프레임 5장
- 대표 화면 5장을 한눈에 보는 전체 모음 1장
- 각 시각 자료의 SVG와 PNG
- Mermaid 원본, 화면 설명과 근거 문서를 담은 Markdown
- `docs/README.md`의 시각 자료 인덱스 링크

### 제외

- 실제 React 화면과 게임 기능 구현
- 게임 규칙, 밸런스 수치, 상태 계약 변경
- 최종 아트, 일러스트, 애니메이션과 브랜드 디자인 확정
- 기존 `proto_image.png`와 역사 spec·plan 수정
- 영구적인 렌더링 도구나 새 런타임 의존성 추가

## 선택한 구성

### 대표 화면은 5개 화면군으로 묶는다

초기 스케치의 조우·지도·결과 3장만 그리면 게시판과 캠페인 정산이 빠진다. 반대로
공식 인터페이스의 8단계를 모두 독립 화면으로 만들면 공통 레이아웃이 반복된다.
따라서 다음 5개 대표 화면군을 사용한다.

1. 공고 게시판과 계약·파티 확인
2. 던전 분기 지도
3. 정보 전달과 사건 조우
4. 자동 보스전과 정산
5. 캠페인 엔딩

### 다이어그램은 캠페인과 탐험의 두 계층으로 나눈다

한 장에 전체 흐름과 개인별 카드 반응까지 넣지 않는다. 여러 탐험에 걸친
`CampaignState`와 한 계약 동안만 존재하는 `ExpeditionState` 경계를 따라 시퀀스와
상태 전이를 각각 두 장으로 분리한다.

담는다. `screen-wireframes.md`는 와이어프레임 5개의 구성 의도, 화면별 표시 정보와
SVG·PNG 링크를 담는다.

## 시퀀스 다이어그램

### 캠페인 시퀀스

참여자는 `플레이어`, `캠페인 화면`, `캠페인 흐름`, `캠페인 규칙`, `캠페인 상태`로
구분한다.

1. 캠페인 시드로 던전 15개, 완성 파티 15팀, 예비 인원 6명을 생성한다.
2. 남은 던전과 출전 가능한 파티를 최대 5개 공고로 연결한다.
3. 화면은 잠긴 공고를 포함해 지원 조건, 보상, 위험, 파티 상태를 보여준다.
4. 플레이어가 공고를 고르면 명성과 계약 가능 여부를 검증하고 탐험을 연다.
5. 탐험의 상세 상호작용은 탐험 시퀀스를 참조한다.
6. 탐험 결과를 캠페인 상태에 병합하고 보상·유품, 던전, 승급, 파티 유지와 회복을
   순서대로 처리한다.
7. 네 엔딩을 정해진 우선순위로 판정한다.
8. 계속 가능하면 다음 게시판을 만들고, 아니면 캠페인 엔딩을 표시한다.

게시판 화면 재진입은 공고를 다시 뽑거나 난수를 소비하지 않는다는 점을 주석으로
표시한다.

### 탐험 시퀀스

참여자는 `플레이어`, `탐험 화면`, `탐험 흐름`, `정보·신뢰 규칙`, `사건·보스 규칙`,
`개인·탐험 상태`로 구분한다.

1. 플레이어가 공개 지도에서 다음 지점을 고르고 경로 유효성을 검사한다.
2. 정보 전달 지점이면 진실·거짓·중립 카드 한 장을 고른다.
3. 살아 있는 파티원마다 수용·의심·적발을 독립 판정한다.
4. 개인별 효과, 즉시 신뢰 변화와 미검증 기억을 기록하고 반응 이유를 보여준다.
5. 정보 전달과 별도로 사건 행동을 고른다.
6. 사건 결과의 HP·신뢰·자원·아이템 변화와 원인을 기록한다.
7. 생존자가 있으면 지도 선택을 반복하고 전멸하면 남은 경로를 건너뛰어 정산한다.
8. 보스방에서는 새 카드나 직접 전투 개입 없이 누적 상태로 자동 전투한다.
9. 거짓과 의심을 사후 검증하고 클리어·전멸 정산 입력을 만든다.

## 상태 전이 다이어그램

### 캠페인 상태 전이

공식 식별자를 바꾸지 않고 다음 정상 흐름을 표시한다.

```text
캠페인 생성
→ campaignBoard
→ partyIntro
→ 탐험 상태 묶음
→ settlement
→ campaignBoard 또는 campaignEnded
```

`settlement` 뒤 엔딩 판정은 아래 우선순위를 번호와 함께 보여준다.

1. `불신의 대가`: 생존한 출전자가 있고 그들 전원의 신뢰가 0
2. `원정 종료`: 던전 15개를 모두 클리어
3. `길잡이 자격 박탈`: 생성된 모든 공고가 현재 명성 제한에 막힘
4. `용사들의 시대가 끝나다`: 완성 가능한 3인 파티가 없음

어느 조건도 성립하지 않으면 새 `campaignBoard`로 돌아간다. 정상 완주 C·B·A·S가
모두 유효한 결과라는 점을 `원정 종료` 주석에 표시한다.

### 탐험 상태 전이

아래 여덟 식별자와 조건부 분기를 명시한다.

```text
campaignBoard
→ partyIntro
→ pathChoice
→ infoOpportunity(정보 전달 지점만)
→ event
→ pathChoice 반복
→ bossFight
→ settlement
→ campaignBoard 또는 campaignEnded
```

- 정보 전달 기회가 없는 지점은 `pathChoice → event`로 간다.
- 정보 전달 기회가 있는 지점은 `pathChoice → infoOpportunity → event`로 간다.
- 일반 사건을 해결하면 다음 `pathChoice`로 돌아간다.
- 전멸하면 남은 사건과 보스전을 건너뛰고 `settlement`로 간다.
- `bossFight`는 누적 상태로 자동 해결한 뒤 `settlement`로 간다.
- 규칙에 없는 전이, 이미 처리한 사건과 중복 정산은 오류로 거부한다.

## 화면 와이어프레임

### 공통 캠페인 HUD

모든 대표 화면 상단에 다음 정보를 유지한다.

- 영구 길잡이 등급
- 현재 명성과 다음 공고 지원 상태
- 현재 골드와 누적 획득 골드
- 승급 점수와 다음 등급 기준
- 남은 던전 수

영구 등급과 현재 명성은 서로 다른 그룹과 라벨로 보여 강등되지 않는 등급과 공고를
제한하는 명성을 혼동하지 않게 한다.

### 1. 공고 게시판과 계약·파티 확인

- 왼쪽 넓은 영역에 최대 5개 공고를 비교한다.
- 오른쪽 상세 영역에 선택한 던전의 등급·지원 조건·보상·전체 지도 위험과 3인
  파티의 직업·성격·HP·개인 신뢰·소지 골드를 보여준다.
- 명성이 부족한 공고도 숨기지 않고 자물쇠, `지원 불가` 라벨과 부족한 명성 수치를
  함께 표시한다.

### 2. 던전 분기 지도

- `proto_image.png`처럼 입구를 아래, 보스방을 위에 둔다.
- 중앙의 지도를 가장 크게 두고 옆에 범례와 개인 파티 상태를 둔다.
- 전체 연결 구조, 사건 분류·위험, 정보 기회와 보스 위치를 공개한다.
- 현재 위치, 지나온 경로, 선택 가능한 다음 지점과 비활성 지점을 색 외에도 채움,
  테두리, 아이콘과 텍스트로 구분한다.

### 3. 정보 전달과 사건 조우

- 초기 스케치의 위 관람·아래 조작 구도를 유지하되 조작 영역을 더 크게 둔다.
- 위쪽은 용사 파티와 사건 상황을 보여주는 비조작 장면이다.
- 아래쪽은 진실·거짓·중립 카드와 사건 행동을 구분해 배치한다.
- 카드 선택 후 오른쪽 파티 영역에 개인별 수용·의심·적발, 효과, HP·신뢰 변화와
  사유를 표시한다.
- 진실·거짓·중립은 색뿐 아니라 `진실/거짓/중립` 텍스트, 기호와 서로 다른 테두리
  형태로 구분한다.

### 4. 자동 보스전과 정산

- 상단에서 자동 보스전의 생존·사망, 파티원별 피해와 원인을 보여준다.
- 하단에서 생존·신뢰, 보상·유품, 던전 제거·상승, 승급, 파티 유지·충원·재편·회복,
  다음 상태를 순서대로 보여준다.
- 단순 숫자 나열 대신 `선택 → 개인 반응 → 피해 → 보상·손실 → 캠페인 변화`의 원인
  사슬을 강조한다.

### 5. 캠페인 엔딩

- 엔딩 이름, 판정 원인과 최종 영구 등급을 가장 크게 표시한다.
- 생존시킨 파티, 전멸시킨 파티, 획득 명성·골드와 대표 정보 선택을 요약한다.
- 정상 완주와 세 조기 엔딩 모두 `S급 목표를 위해 어떤 선택을 했는가`에 답할 수
  있는 캠페인 회고 영역을 가진다.
- 같은 시드 확인과 새 캠페인 동작의 자리만 표시하고 실제 동작은 구현하지 않는다.

## 가시성과 시각 언어

가시성은 장식보다 우선한다.

- 개별 화면 와이어프레임은 `1920×1080` 16:9로 만든다.
- 다이어그램은 내용에 맞춰 최소 `2400×1600` 캔버스를 사용한다.
- 전체 화면 모음은 `3840×2160`의 3열 2행 그리드로 배치하고, 둘째 행의 두 화면은
  가운데에 정렬한다.
- 개별 이미지의 본문 글자는 24px 이상, 제목은 36px 이상으로 한다.
- 주요 선은 3px 이상, 상태 경계와 활성 연결은 4px 이상으로 한다.
- 문단을 이미지 안에 길게 넣지 않고 짧은 라벨과 번호를 사용한다.
- 기본 팔레트는 기존 화면 토큰의 어두운 잉크 배경, 밝은 양피지 글자, 음영 패널,
  신뢰 상승 녹색과 위험 적색을 사용한다.
- 색만으로 의미를 전달하지 않고 텍스트, 기호, 아이콘, 선 종류와 테두리 형태를
  함께 사용한다.
- 아이콘은 외부 이미지나 글꼴별 모양이 다른 이모지를 사용하지 않고 SVG 기본 도형과
  `✓`, `!`, `?`, `×` 같은 텍스트 기호로 만든다.
- 한국어 글꼴은 `Noto Sans KR`, `Noto Sans CJK KR`, `Malgun Gothic`, sans-serif
  순서의 폴백을 사용한다.
- SVG는 텍스트를 편집 가능한 상태로 유지하고 PNG는 원본 비율을 보존한다.
- 전체 모음은 탐색용이며 세부 내용을 읽을 때는 개별 이미지를 보도록 안내한다.

## 렌더링과 일관성

다이어그램 Markdown의 Mermaid 코드가 흐름 원본이다. SVG와 PNG는 같은 Mermaid
원본에서 렌더링하며 내용이 다른 별도 도식을 손으로 만들지 않는다.

화면은 SVG가 시각 원본이다. PNG는 같은 SVG를 래스터화한다. `screen-wireframes.md`는
화면 규칙을 설명하지만 픽셀 배치를 중복 정의하지 않는다.

렌더링에 필요한 도구가 저장소에 없으면 작업 중 일회성 도구를 사용하되
`package.json`과 잠금 파일에 영구 의존성을 추가하지 않는다. 새 도구 없이는 결과를
재생성할 수 없다고 판단되면 구현 전에 범위를 확장하지 않고 계획에서 대안을
선택한다.

## 오류와 문서 충돌 처리

- 존재하지 않는 상태, 문서에 없는 화면이나 보스 거래·직접 전투를 추가하지 않는다.
- `제품 요구사항 대체됨` 문서의 단일 탐험 흐름을 최신 캠페인 규칙처럼 표현하지
  않는다.
- Mermaid 렌더 실패, 잘린 글자, 누락된 이미지와 깨진 상대 링크는 완료로 보지 않는다.
- 공식 문서 사이에서 시각화에 영향을 주는 실제 충돌을 발견하면 임의로 하나를
  선택하지 않고 해당 충돌을 기록한다.

## 검증

### 내용 검증

- 공식 상태 식별자 여덟 개와 정상·조건부 전이를 대조한다.
- 정보 전달 뒤 사건 행동이 별도로 이어지는지 확인한다.
- 보스방에서 새 카드·보스 거래·직접 전투가 없는지 확인한다.
- 전멸 조기 정산과 네 엔딩 우선순위를 확인한다.
- 공통 HUD와 개인별 HP·신뢰·소지 골드가 화면에 반영됐는지 확인한다.

### 파일 검증

- Markdown 상대 링크와 이미지 경로가 모두 존재한다.
- Mermaid 원본 네 개가 파싱되고 SVG로 렌더링된다.
- SVG 열 개가 유효하며 PNG 열 개가 대응하는 이름과 비율을 가진다.
- PNG 해상도와 파일 형식을 확인한다.
- `git diff --check`가 통과한다.

### 시각 검증

- SVG와 PNG를 각각 열어 한국어가 깨지거나 잘리지 않는지 확인한다.
- 100% 배율에서 노드·상태·화면 제목과 주요 연결이 읽히는지 확인한다.
- 축소한 전체 모음에서도 화면 종류와 핵심 영역이 구분되는지 확인한다.
- 색을 보조 정보로만 사용했는지, 활성·비활성·위험 상태에 다른 단서가 있는지
  확인한다.

## 완료 기준

- `docs/diagram`에 Markdown 6개, SVG 10개, PNG 10개가 존재한다.
- 다이어그램 4장은 캠페인과 탐험 계층, 조건부 정보 흐름, 전멸 조기 정산과 엔딩
  우선순위를 정확히 보여준다.
- 화면 5장과 전체 모음은 최신 인터페이스 요구사항과 초기 스케치의 공간 구성을
  함께 반영한다.
- 개별 이미지가 가시성 기준을 충족하고 깨진 링크나 잘린 텍스트가 없다.
- `docs/README.md`에서 시각 자료 인덱스로 이동할 수 있다.
- 기존 공식 문서와 사용자 작업을 덮어쓰지 않는다.
