# 전체 캔버스 화면 루트 계약 설계

## 문서 정보

- 작성자: sbh3821
- 작성 도구: Codex
- 작성일: 2026-08-22
- 대상 작업: 기존·신규 UI의 최상위 화면 루트가 1920×1080 캔버스 전체를 점유하도록 기본 계약을 강제
- 기준 브랜치: `main` (`9545506`)

## 1. 문제와 목표

`game-canvas` 자체는 1920×1080으로 고정되어 있지만, 그 안에 들어가는 화면
루트의 높이는 화면별 구현에 맡겨져 있다. U2는 `.u2-preview`에 `height: 100%`를
직접 선언하지만 U3의 `.u3-preview`에는 같은 선언이 없다. 1920×1080에서 실측한
결과 U2는 캔버스 전체 1080px을 점유한 반면 U3는 949.41px만 점유해 하단
130.58px이 비었다. U1은 `min-h-screen`으로 브라우저 높이를 참조하므로 16:9가
아닌 창에서 캔버스 높이보다 커질 수 있다.

화면마다 `height: 100%`를 기억해서 추가하는 방식은 새 UI가 생길 때 같은 누락을
반복한다. 따라서 전체 점유를 화면별 선택이 아니라 고정 캔버스의 기본 계약으로
만든다.

완료 목표는 다음과 같다.

- 모든 일반 화면의 최상위 루트가 1920×1080 캔버스의 폭과 높이를 전부 점유한다.
- 화면 내부의 의도적인 여백, 패널 크기, 배경 구도는 화면별 설계를 유지한다.
- 브라우저 창 비율이 달라져도 화면 루트는 캔버스와 함께 균일하게 축소되고
  레터박스 안에서 정확히 같은 상대 크기를 유지한다.
- 앞으로 추가되는 화면에도 별도 높이 선언 없이 같은 계약이 자동 적용된다.
- 전체 점유를 하지 않는 화면은 명시적인 예외로만 허용하고 검색·검토할 수 있다.

## 2. 범위와 비범위

근거 문서는 다음과 같다.

- `docs/GAME_PRINCIPLES.md`
- `docs/experience/SCREEN_LAYOUT.md`
- `docs/experience/UI_IMPLEMENTATION_GUIDE.md`
- `docs/experience/UI_TASK_TEMPLATE.md`
- `docs/superpowers/specs/2026-08-22-sbh3821-fixed-aspect-canvas-design.md`

이번 변경은 캔버스의 직계 화면 루트가 차지하는 영역과 그 계약을 지키는 문서·
테스트만 다룬다. `GameShell`의 3:2 열 비율, 상태 바 높이, 개별 화면의 내부
패딩과 여백, 이미지 crop, 도메인 규칙, 게임 데이터는 변경하지 않는다.

현재 `main`에서 브라우저로 진입할 수 있는 `/`, `/u1-test`, `/u2-test`,
`/u3-test`를 기존 화면 검증 대상으로 삼는다. 아직 라우트에 연결되지 않은 U4~U6
화면은 구현될 때 공통 계약을 자동으로 상속한다.

## 3. 선택한 접근

### 3.1 채택: 캔버스 직계 자식의 전체 점유를 기본값으로 만든다

`app/layout.tsx`가 모든 라우트를 `.game-canvas` 안에 렌더링하므로, 공통 CSS가
예외가 아닌 직계 자식을 캔버스 크기로 확장한다.

```css
.game-canvas > :not([data-canvas-layout="intrinsic"]) {
  width: 100%;
  height: 100%;
  min-width: 0;
  min-height: 0;
}
```

이 규칙은 화면별 CSS나 특정 컴포넌트 이름을 알 필요가 없다. 새 페이지가 단일
최상위 DOM 요소를 반환하면 자동으로 전체 캔버스를 점유한다. `min-width: 0`과
`min-height: 0`은 그리드·플렉스 자식의 콘텐츠 최소 크기가 루트를 캔버스보다
밀어내지 못하게 한다.

### 3.2 제외한 대안

화면마다 `height: 100%`를 반복하는 방식은 U3 누락을 만든 현재 구조와 같아
제외한다. 모든 화면을 새 `ScreenRoot` React 컴포넌트로 감싸는 방식도 호출자가
래퍼를 빼먹으면 계약이 깨지고 기존 화면 마이그레이션만 늘어나므로 제외한다.

## 4. 명시적 예외 계약

전체 점유를 하지 않아야 할 특별한 화면은 최상위 DOM 요소에
`data-canvas-layout="intrinsic"`을 선언한다. 이 속성은 일반적인 레이아웃 도구가
아니며 다음 조건을 모두 만족할 때만 사용한다.

1. 해당 화면의 승인된 spec이 전체 점유를 하지 않는 이유와 기대 크기를 기록한다.
2. 화면별 테스트가 예외 속성과 기대 동작을 고정한다.
3. 고정 캔버스 회귀 테스트의 예외 허용 목록에 컴포넌트 경로를 추가한다.

현재 화면에는 승인된 예외가 없으므로 초기 허용 목록은 비어 있다. 내부 카드,
모달, 패널, 배경에 빈 공간이 있다는 이유로 이 예외를 사용하지 않는다. 예외는
오직 `.game-canvas`의 직계 화면 루트가 캔버스 전체를 점유하지 않아야 할 때만
사용한다.

## 5. 기존 화면 정리

### U1

`U1Preview`의 `min-h-screen`을 제거한다. 이 Tailwind 유틸리티는 캔버스가 아니라
브라우저 창의 `100vh`를 참조해 16:10·5:4 창에서 루트를 캔버스보다 크게 만든다.
U1 루트는 공통 직계 자식 규칙을 따라 정확히 100% 높이를 쓴다. 프리뷰 내 탐색
행과 `GameShell`은 남은 높이 안에 들어오도록 최소 높이 연결을 점검한다.

### U2

U2는 이미 전체 높이를 사용한다. `.u2-preview`에 중복으로 있는 폭·높이·최소 높이
선언은 공통 계약으로 옮기면서 제거한다. 내부
`.u2-intro-shell`과 인트로 구도는 바꾸지 않는다.

### U3

별도의 `.u3-preview { height: 100%; }` 보정은 추가하지 않는다. 공통 직계 자식
규칙이 누락된 높이 연결을 복구하고 `.u3-board-screen`부터 `GameShell`까지 이미
있는 `height: 100%` 연쇄가 캔버스 높이를 받는다.

### 기본 `/` 화면

현재 `min-h-full`과 공통 직계 자식 규칙이 충돌하지 않는지 확인한다. 게임 화면이
아닌 안내 내용이더라도 캔버스 안에 렌더링되는 이상 루트 전체 점유 계약을 따른다.

## 6. 공식 문서와 신규 화면 가이드

`docs/experience/SCREEN_LAYOUT.md`의 고정 캔버스 절에 다음 규칙을 추가한다.

- 고정 캔버스의 존재와 화면 루트의 전체 점유는 별개의 계약이다.
- 일반 화면 루트는 폭·높이 100%를 사용한다.
- 내부의 의도적인 여백은 허용한다.
- 전체 점유 예외는 승인된 spec과 명시적 속성·테스트가 필요하다.

`docs/experience/UI_IMPLEMENTATION_GUIDE.md`의 고정 캔버스 규칙과 구현 전후
체크리스트에는 단일 최상위 DOM 요소, 전체 점유 자동 상속, `min-h-screen`·
`100vh` 금지, 예외 승인 절차를 추가한다.

`docs/experience/UI_TASK_TEMPLATE.md`에는 화면 루트가 1920×1080 캔버스 전체를
점유하는지 네 viewport에서 확인하는 항목을 추가한다. 내부 여백을 없애라는 뜻이
아님을 함께 명시한다.

## 7. 테스트와 검증

### 자동 검증

`components/game/FixedCanvas.test.ts`를 확장해 다음을 고정한다.

- `.game-canvas`의 일반 직계 자식이 `width: 100%`, `height: 100%`,
  `min-width: 0`, `min-height: 0`을 받는다.
- 예외 선택자는 `data-canvas-layout="intrinsic"` 하나만 사용한다.
- 현재 화면 소스에는 승인되지 않은 `data-canvas-layout="intrinsic"`이 없다.
- `app/layout.tsx`를 제외한 캔버스 내부 화면 소스에는 `min-h-screen`이 없다.
- 기존 CSS의 `vw`·`vh`와 미디어 쿼리 금지 검사를 유지한다.

전체 검증 명령은 `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm build`다.
이번 변경은 rules와 backtest를 건드리지 않으므로 `pnpm backtest`는 실행하지
않는다.

### 브라우저 검증

`/`, `/u1-test`, `/u2-test`, `/u3-test`를 다음 창 크기에서 확인한다.

- 1920×1080
- 2560×1440
- 1440×900
- 1280×1024

각 라우트에서 `.game-canvas`와 직계 화면 루트의 `getBoundingClientRect()` 폭·높이가
같아야 한다. 1920×1080에서는 둘 다 1920×1080이고, 다른 창에서는 캔버스가
레터박스에 맞춰 축소된 실제 크기와 일치해야 한다. 가로·세로 스크롤, 콘텐츠
잘림, 콘솔 오류가 없어야 하며 네 viewport의 줄바꿈과 상대 배치는 같아야 한다.

사용자 확인을 위해 로컬 production build를 실행한 뒤 접근 링크를 제공한다.

## 8. 완료 조건

- 현재 네 라우트의 최상위 화면 루트가 캔버스와 같은 폭·높이를 가진다.
- U3의 1920×1080 하단 130.58px 공백이 사라진다.
- U1이 브라우저 `100vh` 대신 고정 캔버스 높이를 사용한다.
- U2의 인트로 내부 구도와 U3의 3:2 내부 레이아웃은 유지된다.
- 새 화면은 별도 화면별 높이 선언 없이 전체 캔버스를 점유한다.
- 예외는 명시적 속성, 승인된 spec, 테스트 허용 목록 없이는 추가할 수 없다.
- 공식 UI 문서와 작업 템플릿이 같은 규칙을 설명한다.
- 자동 검증과 production build가 통과하고 로컬 확인 링크가 제공된다.

## 9. 변경하지 않는 것

- 1920×1080 고정 캔버스의 크기와 레터박스 계산
- `GameShell`의 3:2(60:40) 열 비율
- 상태 바 높이와 상태 데이터
- 개별 화면 내부의 의도적인 여백과 배경 crop
- UI 이미지·아이콘·텍스트·CTA 디자인
- 도메인 규칙, 캠페인 상태, 보상 수치, 백테스트
