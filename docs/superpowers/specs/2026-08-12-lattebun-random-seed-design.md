# F3 랜덤 시드와 재현성 설계

**작성자:** LatteBun  
**작성 도구:** Claude Code

## 목적

같은 시드가 같은 결과를 만드는 난수 생성기를 만들고, `Math.random` 직접 호출을 eslint로 차단한다.

이 작업은 [프로토타입 작업 배정표](../../technical/PROTOTYPE_WORK_ASSIGNMENT.md)의 `F3`이다. 선행인 `F1`과 `F4`는 완료됐다. 이 작업이 끝나면 `R1`(파티 생성)과 `R4`(이벤트·경로 생성)가 풀린다.

## 완료 기준 수정

배정표의 현재 `F3` 완료 기준은 다음이다.

> 같은 시드가 같은 파티·경로·이벤트를 만드는 테스트 통과. `Math.random` 직접 호출 금지

**F3는 이 기준을 문자 그대로 만족시킬 수 없다.** 파티를 만드는 것은 `R1`, 경로와 이벤트를 만드는 것은 `R4`이며 둘 다 아직 없다. F3가 만드는 것은 그 둘이 올라탈 토대다.

기준을 다음으로 바꾼다.

> 같은 시드와 스트림 이름이 같은 수열을 만드는 테스트 통과. 파생 스트림이 호출 순서와 무관함을 검증. `Math.random` 직접 호출을 eslint로 차단

바꾸는 근거는 두 가지다.

- 위의 두 성질이 성립하면 `R1`·`R4`의 재현성은 자동으로 따라온다. F3가 증명할 수 있는 가장 강한 성질이다.
- `R1`과 `R4`의 완료 기준에 이미 "시드로 재현되는 테스트 통과"가 있다. 파티와 경로의 실제 재현성은 그쪽에서 검증된다. F3에서 중복을 덜어낸다.

## 설계 결정

### 1. 알고리즘을 직접 구현한다

mulberry32 생성기와 문자열 해시를 직접 구현한다. `pure-rand` 같은 라이브러리를 쓰지 않는다.

`F4`에서 의존성을 `vitest` 하나만 넣기로 한 기조와 맞춘다. 해시와 생성기 두 함수를 합쳐 30줄 미만이라 읽고 테스트할 수 있고, 이 작업 자체가 그 구현을 검증한다.

mulberry32는 32비트 상태를 쓰는 생성기로 게임용으로 널리 쓰인다. 암호용이 아니다. 파티 구성과 던전 배치에 쓸 목적이므로 충분하다. 시드를 예측 불가능하게 만들어야 하는 용도가 생기면 그때 다시 판단한다.

### 2. 이름으로 독립 스트림을 파생시킨다

단일 스트림을 모든 곳에서 공유하면 한 곳의 수정이 나머지 전부를 바꾼다. 파티 생성이 난수를 7번 뽑고 던전 생성이 그다음을 이어받는 구조라면, 나중에 파티 생성에 난수 하나를 더 쓰는 순간 같은 시드인데 던전 배치가 완전히 달라진다.

그러면 두 가지 문제가 생긴다.

- `R4`의 테스트가 `R1`의 수정 때문에 깨진다.
- 콘텐츠와 밸런스를 조정할 때마다 다른 시스템의 결과가 흔들린다.

`derive(stream)`으로 시스템마다 독립 스트림을 준다. `R1`은 `party` 스트림만, `R4`는 `dungeon` 스트림만 받는다.

**파생은 부모의 현재 상태가 아니라 부모의 시드 문자열에서 한다.** 부모 상태를 쓰면 호출 순서가 다시 결과에 영향을 주어 파생의 의미가 사라진다. 부모에서 난수를 100번 뽑은 뒤 파생해도 결과가 같아야 한다.

### 3. 스트림 이름을 닫힌 유니온으로 둔다

```ts
export type RngStream = "party" | "dungeon" | "card" | "trust";
```

문자열을 그대로 받으면 `derive("prty")` 같은 오타가 오류 없이 다른 스트림을 만든다. 예외도 경고도 없이 숫자만 달라지므로 발견하기 가장 어려운 종류의 버그다. 유니온으로 두면 컴파일 시점에 잡힌다.

`F1`이 "규칙이 분기하는 종류는 닫는다"로 정한 방식과 같다. 새 스트림 추가는 유니온 한 줄 수정이다.

각 이름의 소비자는 다음과 같다.

| 스트림 | 소비자 |
| --- | --- |
| `party` | `R1` 파티 생성 규칙 |
| `dungeon` | `R4` 이벤트·경로 생성 |
| `card` | `R3` 정보 카드 판정의 확률 |
| `trust` | `R2` 개인 신뢰 판정의 확률 |

### 4. `Math.random`을 eslint 오류로 차단한다

문서 규약만으로는 검사할 수단이 없다. `pnpm lint`가 이미 병합 전 검증 기준이므로 규칙을 추가하면 사람이 깜박해도 리뷰 전에 잡힌다.

경고가 아니라 오류로 둔다. 재현성이 깨진 버그는 나중에 재현 불가 버그로 남고, 경고는 시간이 지나면 배경이 된다.

시드 기반 생성기는 `Math.random`을 전혀 쓰지 않는다. 새 판을 시작할 때 필요한 무작위 시드도 `crypto.randomUUID()`로 만든다. 따라서 `lib/rng/` 자신을 포함해 **예외가 없다.**

### 5. 반환값은 새 배열로 준다

`shuffle`은 원본 배열을 바꾸지 않고 새 배열을 반환한다. `RunState`를 다루는 코드가 실수로 상태를 제자리에서 바꾸는 것을 막는다.

## 구현

### 문자열 시드를 32비트 정수로

```ts
function hashSeed(text: string): number {
  let h = 2166136261 >>> 0; // FNV-1a 초기값
  for (let i = 0; i < text.length; i += 1) {
    h ^= text.charCodeAt(i);
    h = Math.imul(h, 16777619);
  }
  // murmur3 최종 혼합. 이 단계가 없으면 "seed-1"과 "seed-2"처럼
  // 비슷한 문자열이 비슷한 시드가 되어 초기 수열이 닮는다.
  h ^= h >>> 16;
  h = Math.imul(h, 2246822507);
  h ^= h >>> 13;
  h = Math.imul(h, 3266489909);
  h ^= h >>> 16;
  return h >>> 0;
}
```

### mulberry32 생성기

```ts
function mulberry32(state: number): () => number {
  let a = state >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = a;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
```

### 공개 API

```ts
export type RngStream = "party" | "dungeon" | "card" | "trust";

export interface Rng {
  /** 이 생성기를 만든 시드 문자열. 파생의 기준이 된다. */
  readonly seed: string;
  /** 0 이상 1 미만 */
  float(): number;
  /** min 이상 max 이하 정수. 양끝을 포함한다. */
  int(min: number, max: number): number;
  pick<T>(items: readonly T[]): T;
  /** 새 배열을 반환한다. 원본을 바꾸지 않는다. */
  shuffle<T>(items: readonly T[]): T[];
  /** 이름마다 독립된 스트림. 부모의 호출 횟수와 무관하다. */
  derive(stream: RngStream): Rng;
}

export function createRng(seed: string): Rng;

/** 새 판에 쓸 무작위 시드. Math.random을 쓰지 않는다. */
export function createSeed(): string;
```

`createRng`는 클로저로 상태를 감춘다. `derive(stream)`은 부모 시드와 스트림 이름을 `/`로 이어 붙인 새 시드로 생성기를 만든다.

```ts
derive: (stream) => createRng(`${seed}/${stream}`)
```

`int`는 범위가 잘못되면 예외를 던진다. 정수가 아닌 값이나 `min > max`를 조용히 넘기면 `pick`과 `shuffle`이 배열 범위를 벗어난 값을 만든다. `pick`은 빈 배열에 대해 예외를 던진다.

`createSeed`는 전역 `crypto.randomUUID()`를 쓴다. 브라우저와 Node 모두에서 동작하며 `tsconfig.json`의 `lib`에 `dom`이 있어 타입도 잡힌다.

## 테스트

`lib/rng/index.test.ts`에 다음을 검증한다.

**재현성**

- 같은 시드는 같은 수열을 만든다.
- 다른 시드는 다른 수열을 만든다.
- 비슷한 시드(`"seed-1"`과 `"seed-2"`)도 다른 수열을 만든다.

**파생**

- 스트림 이름이 다르면 다른 수열을 만든다.
- 같은 시드와 같은 스트림 이름은 같은 수열을 만든다.
- **부모에서 난수를 여러 번 뽑은 뒤 파생해도 결과가 같다.** 이 설계의 핵심 성질이다.
- 파생한 생성기의 `seed`가 부모 시드와 스트림 이름을 담는다.

**범위와 동작**

- `int`는 최솟값과 최댓값을 모두 만들 수 있다.
- `int`는 `min`과 `max`가 같으면 그 값을 반환한다.
- `int`는 `min > max`일 때 예외를 던진다.
- `float`은 0 이상 1 미만이다.
- `pick`은 배열의 원소 중 하나를 반환한다.
- `pick`은 빈 배열에 대해 예외를 던진다.
- `shuffle`은 원본 배열을 변경하지 않는다.
- `shuffle`은 같은 원소를 모두 유지한다.
- `shuffle`은 같은 시드로 같은 순서를 만든다.

**시드 생성**

- `createSeed`는 호출마다 다른 값을 만든다.

`int`와 `float`의 범위 검증은 한 번 호출로는 부족하다. 반복 호출로 확인한다. 확률적 검사가 아니라 결정적 검사가 되도록 고정 시드를 쓴다.

## 문서 갱신

### `DEVELOPMENT_ENVIRONMENT.md`

`테스트 작성 규약` 절 뒤에 `난수와 재현성` 절을 추가한다. 내용은 다음이다.

- `Math.random`을 직접 호출하지 않는다. eslint가 오류로 막는다.
- 난수는 `@/lib/rng`의 `createRng(seed)`로 만든다.
- 시스템마다 `derive(스트림 이름)`으로 독립 스트림을 받는다. 한 시스템의 난수 호출 횟수가 바뀌어도 다른 시스템의 결과가 변하지 않는다.
- 새 스트림이 필요하면 `RngStream` 유니온에 이름을 추가한다.
- 새 판의 시드는 `createSeed()`로 만든다.

### `PROTOTYPE_WORK_ASSIGNMENT.md`

`F3` 행의 완료 기준을 이 문서의 「완료 기준 수정」 절에 적은 문구로 바꾸고, 담당자와 상태를 기록한다.

## 제외 범위

- `R1` 파티 생성, `R4` 이벤트·경로 생성 구현
- `RunState`에 시드를 넣고 관리하는 로직 (`F2` 스토어의 몫)
- 암호학적으로 안전한 난수
- 난수 품질 통계 검정 (dieharder 등)
- 시드를 URL이나 화면에 노출하는 기능
- `lib/domain/`의 타입과 상수 변경

## 후속 작업에 남기는 계약

이 작업이 끝나면 다음 작업이 아래를 전제할 수 있다.

| 작업 | 사용법 |
| --- | --- |
| `R1` 파티 생성 | `createRng(seed).derive("party")`를 받아 `pick`과 `int`로 파티를 만든다 |
| `R4` 이벤트·경로 | `createRng(seed).derive("dungeon")`을 받아 경로를 만든다 |
| `R3` 정보 카드 판정 | `derive("card")`로 확률을 굴린다 |
| `R2` 신뢰 판정 | 확률이 필요하면 `derive("trust")`를 쓴다 |
| `F2` 상태 스토어 | 새 판을 만들 때 `createSeed()`로 시드를 정해 `RunState.seed`에 넣는다 |

각 작업은 `Rng`를 인자로 받는다. 함수 안에서 `createRng`를 직접 부르지 않는다. 그래야 테스트가 고정 시드를 주입할 수 있다.
