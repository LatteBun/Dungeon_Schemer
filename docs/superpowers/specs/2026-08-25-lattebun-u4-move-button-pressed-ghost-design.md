# U4 지도 이동 버튼 눌림 잔상 수정 설계

- 작성자: LatteBun
- 작성 도구: Codex
- 작성일: 2026-08-25
- 상태: 사용자 설계 승인 완료, 서면 spec 검토 대기

## 1. 목적

던전 지도에서 `이 지점으로 이동` CTA를 누를 때 버튼 아래쪽에 눌림 이미지가
잔상처럼 나타나는 문제를 없앤다. 눌림 상태의 시각 피드백은 유지하되 CTA의 실제
경계 안에서만 표시한다.

## 2. 재현 증상

1. 캠페인 원정의 U4 던전 지도에서 이동 가능한 다음 지점을 선택한다.
2. 우측 하단의 `이 지점으로 이동` CTA를 누른다.
3. 누르는 동안 CTA의 눌림 이미지가 원래 버튼 아래쪽에 한 장 더 나타난다.

지도 지점 선택, `VISIT_NODE` dispatch, U5 진행 화면 전환 자체에는 문제가 없다.
증상은 CTA의 눌림 시각 상태에 한정된다.

## 3. 확인된 원인

`MoveButton`은 기본 판과 눌림 판을 같은 `.u4-move-button__skin` 안에 연속된
`img`로 렌더링한다. 기본 CSS는 눌림 판의 투명도만 0으로 두었다가 버튼의
`:active` 상태에서 1로 바꾼다.

후순위 보정 CSS는 skin을 `display: block`으로 바꾸고 두 center 이미지를 모두
`display: block; width: 100%; height: 100%`로 만든다. 이때 눌림 판에는 겹침
배치가 없으므로 기본 판 다음 행, 즉 버튼 아래에 놓인다. 버튼은
`overflow: visible`이라 그 두 번째 이미지가 잘리지 않으며, 클릭 중 투명도가
1이 되는 순간 잔상처럼 드러난다.

따라서 문제의 원인은 화면 전환이나 Store 상태가 아니라, 눌림 이미지를 기본
이미지와 겹치지 않은 채 투명도로만 감춘 CSS 배치다.

## 4. 승인된 수정

- `.u4-move-button__center--active`를 skin 기준의 절대 배치로 만든다.
- `inset: 0`으로 기본 center 이미지와 같은 영역을 차지하게 한다.
- 기존 `opacity` 전환과 `:active` 선택자는 유지해 눌림 피드백을 보존한다.
- 버튼 전체의 `overflow`를 바꿔 증상을 가리는 방식은 사용하지 않는다. 눌림 판의
  잘못된 배치 자체를 바로잡는다.

DOM 구조, 이미지 에셋, CTA 문구와 클릭 callback은 변경하지 않는다.

## 5. 구현 경계

### CSS

`app/u4-dungeon-map.css`에서 눌림 판이 기본 판 위에 겹쳐지도록 배치 계약을
추가한다. 후순위 `app/u4-dungeon-map-fixes.css`의 버튼 크기·skin 영역·기존
시각 보정은 변경하지 않는다.

### 회귀 테스트

`components/game/U4FixedCanvas.test.ts`에 다음 CSS 계약을 추가한다.

- 눌림 판이 `position: absolute`다.
- 눌림 판이 `inset: 0`으로 skin 안을 채운다.
- 기존 `:active` 상태가 눌림 판의 투명도를 1로 바꾼다.

이 검사는 눌림 이미지가 다시 일반 흐름으로 돌아가 버튼 아래에 배치되는 회귀를
막는다.

## 6. 유지할 동작

- 지도에서 선택 가능한 다음 지점과 `aria-pressed` 상태
- 선택 지점 정보와 CTA 활성·비활성 조건
- CTA가 선택한 NodeId를 `onMove`에 전달하는 동작
- `VISIT_NODE`와 보스방의 `ENTER_BOSS` dispatch 순서
- CTA의 기본·비활성·눌림 이미지와 눌림 피드백
- 우측 패널의 최하단 CTA 배치
- 1920×1080 고정 캔버스와 기존 viewport 축척

도메인 규칙, Store, 지도 topology, U5 진행 화면, 이미지 에셋은 변경하지 않는다.

## 7. 공식 문서 반영

- `docs/experience/U4_DUNGEON_MAP.md`의 사용자 행동/고정 캔버스 계약에 CTA 눌림
  피드백은 버튼 경계 안에서만 표시되어야 한다는 기준을 기록한다.
- 게임 규칙과 화면 정보 구조는 바뀌지 않으므로 `docs/GAME_PRINCIPLES.md`, 시스템
  문서, `docs/experience/SCREEN_LAYOUT.md`는 수정하지 않는다.

## 8. 검증

1. CSS 회귀 테스트를 먼저 실패시키고, 최소 CSS 수정 뒤 통과시킨다.
2. U4 컴포넌트 및 고정 캔버스 테스트를 실행한다.
3. 전체 단위 테스트, lint, typecheck를 실행한다.
4. 실제 캠페인 지도에서 목적지를 선택하고 CTA를 마우스로 눌러, 눌림 판이 버튼
   내부에서만 보이며 아래쪽 잔상이 없는지 확인한다.
5. Chromium E2E의 1280×720 viewport와 U4 공식 1920×1080 viewport에서 CTA
   clipping이나 새 스크롤이 없는지 확인한다.

인앱 브라우저 연결을 사용할 수 없으면 저장소의 Chromium E2E 환경으로 같은
클릭 흐름을 검증하고, 해당 제약을 결과에 명시한다.

## 9. 완료 조건

- CTA를 누르는 동안 버튼 아래에 눌림 이미지가 나타나지 않는다.
- 눌림 판은 기본 판과 같은 skin 영역에서만 보인다.
- 눌림 피드백과 이동 동작은 그대로 유지된다.
- 관련 자동 테스트와 실제 클릭 흐름 검증이 통과한다.
- 관련 공식 문서가 구현과 일치한다.
