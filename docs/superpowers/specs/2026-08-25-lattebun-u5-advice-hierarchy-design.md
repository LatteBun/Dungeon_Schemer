## 1. 목적

던전 진행 화면의 좌측 하단에서 플레이어가 다음 순서로 자연스럽게 읽도록 정보 위계를 정리한다.

```text
행동 / 조언 탭 확인
→ 현재 상황 읽기
→ 기존 조언 카드 3개 비교
```

이번 변경의 완료 목표는 다음과 같다.

- `행동 / 조언`과 `진행 기록` 탭을 승인된 참고 이미지처럼 작고 분명한 탭으로 정리한다.
- 평문으로 놓여 있는 상황 묘사를 `현재 상황` 라벨이 있는 독립 패널로 묶는다.
- 상황 본문은 이전 비교 시안의 2안 정도 크기로 유지해 카드 주 문장과 경쟁하지 않게 한다.
- 이미 확정된 **번호 없는 조언 카드 3개**의 외형과 내부 배치는 그대로 유지한다.

이번 변경은 표현 계층만 다룬다. 조언 내용, 조언 순서, 선택 결과, 비용, 잠금 조건, 진행 기록, 전투, 파티 상태와 캠페인 규칙은 바꾸지 않는다.

## 2. 근거와 현재 상태

### 2.1 공식 근거

- `docs/GAME_PRINCIPLES.md`는 현장 단서와 공개 정보를 조언 판단의 근거로 제공해야 한다고 정한다.
- `docs/experience/SCREEN_LAYOUT.md`는 `행동 / 조언` 모드에서 상황 묘사를 먼저 보여주고 같은 디자인의 조언 3개를 그 아래 둔다고 정한다.
- `docs/experience/UI_IMPLEMENTATION_GUIDE.md`는 고정 캔버스, 기존 다크 판타지 재질, `rem`·`cqw`·`cqh` 단위와 기존 컴포넌트 재사용을 요구한다.
- `docs/superpowers/specs/2026-08-25-lattebun-progress-screen-ux-design.md`는 낮은 금속 명패형 조언 카드와 동일 외형 계약을 정의한다.
- `docs/superpowers/specs/2026-08-25-lattebun-u5-advice-number-removal-design.md`는 시각적 카드 번호를 제거하되 내부 슬롯 선택 계약은 유지한다고 정한다.

### 2.2 현재 구현

현재 `main`에는 조언 카드 번호 제거가 병합되어 있다.

- `components/game/U5ProgressScreen.tsx`의 `AdviceOption`은 화면에 숫자를 렌더링하지 않는다.
- 카드 내부는 `조언 문장 → 구분선 → 근거 문장` 순서이며, 번호가 빠진 뒤 카드 내용이 자연스럽게 중앙 정렬된다.
- `slot`은 React key와 `onSelectAdvice(slot)` 연결에만 남아 있다.
- `app/u5-progress.css`의 금속 명패, 리벳, 카드 높이, 구분선과 동일 카드 규칙은 현재 승인 상태다.

반면 상황 묘사는 탭 아래의 `p.u5-situation` 한 줄로만 놓여 있다. 패널 경계와 구역 이름이 없어 콘솔 배경에 묻히고, 플레이어가 카드로 바로 시선을 넘기기 쉽다.

또한 현재 CSS는 `.u5-console__tabs`와 `.u5-log__filters`의 버튼 규칙을 일부 공유한다. 탭만 조정하면서 진행 기록 필터까지 함께 바뀌지 않도록 선택자를 분리하거나 탭 전용 덮어쓰기를 명시적으로 사용해야 한다.

## 3. 브레인스토밍 결과

### 접근 A. 의미 있는 상황 패널과 탭 정제 — 채택

탭 바로 아래에 `현재 상황` 제목과 상황 본문을 담은 의미 있는 패널을 추가한다. 탭은 같은 위치와 동작을 유지하면서 참고 이미지의 작고 각진 버튼 형태로 정리한다.

장점:

- 상황이 조언의 근거라는 위계가 가장 분명하다.
- 기존 U5 콘솔 구조와 40:60 화면 비율을 유지한다.
- 실제 제목과 구역 마크업을 사용하므로 접근성과 테스트가 명확하다.
- 조언 카드 코드를 건드리지 않고도 목적을 달성한다.

### 접근 B. 기존 문단에 CSS 가상 요소로 `현재 상황` 표시 — 제외

`p.u5-situation::before`로 라벨과 테두리를 붙이면 TSX 변경은 줄어든다. 그러나 가상 요소의 글자는 의미 있는 제목이 아니며 스크린 리더와 렌더 테스트의 계약이 불분명하다. 표시 텍스트를 CSS에 두는 것도 프로젝트의 기존 React 마크업 관례와 맞지 않는다.

### 접근 C. 상황 문장을 장면 이미지 위 자막으로 이동 — 제외

상황과 장면의 연결감은 강하지만 배경마다 대비가 달라지고, 공식 문서의 `하단 콘솔에서 상황을 먼저 읽고 조언한다`는 구조를 바꾼다. 전투 자막과 역할도 충돌할 수 있어 이번 범위보다 크다.

### 결론

접근 A를 채택한다. 다만 이전 1안에 포함됐던 `어떻게 조언할까?` 안내 문구는 추가하지 않는다. 사용자가 제공한 최종 참고 이미지처럼 **탭 → 현재 상황 패널 → 기존 카드 3개**만 유지한다.

## 4. 승인된 정보 구조

### 4.1 선택 전

```text
.u5-console
├─ 탭 행
│  ├─ 행동 / 조언
│  └─ 진행 기록
└─ 행동 / 조언 모드
   ├─ 현재 상황 패널
   │  ├─ 제목: 현재 상황
   │  └─ 본문: progress.situation
   └─ 기존 조언 카드 목록 3개
```

### 4.2 선택 뒤

```text
.u5-console
├─ 탭 행
└─ 행동 / 조언 모드
   ├─ 현재 상황 패널
   └─ 기존 결과 영역
      ├─ 파티원별 반응
      ├─ 사건 결과
      └─ 수치·신뢰 변화
```

상황 패널은 선택 전과 선택 뒤 모두 남아 사건의 맥락을 보존한다. `진행 기록` 모드로 전환하면 기존처럼 상황 패널과 조언·결과 영역을 렌더링하지 않고 기록 패널만 보여준다.

## 5. 탭 계약

### 5.1 구조와 동작

- 탭 문구는 `행동 / 조언`, `진행 기록`을 그대로 사용한다.
- 두 탭은 계속 실제 `button`이며 기존 `aria-pressed`와 수동 전환 동작을 유지한다.
- 기본 모드는 기존처럼 `행동 / 조언`이다.
- 탭은 콘솔 왼쪽에 내용 폭으로 나란히 놓고 전체 폭으로 늘리지 않는다.
- 아이콘, 밑줄형 탭 인디케이터, 숫자 배지와 새 애니메이션을 추가하지 않는다.

### 5.2 시각 상태

- 활성 탭은 얇은 금색 계열 테두리, 짙은 갈색 바탕과 밝은 양피지색 글자로 표시한다.
- 비활성 탭은 검은 갈색 바탕, 낮은 명도의 테두리와 muted 글자를 사용한다.
- 참고 이미지처럼 모서리는 작고 각진 사각형에 가깝게 유지한다. pill 형태로 만들지 않는다.
- 탭 높이와 좌우 padding은 현재보다 커지지 않으며, 상황 패널보다 먼저 보이되 화면 제목처럼 과하게 강조하지 않는다.
- hover는 선택 가능함을 알리는 정도로만 밝아지고, 활성 탭과 혼동되지 않아야 한다.
- `focus-visible`은 색 상태와 별개로 분명한 outline을 유지한다.

### 5.3 진행 기록 필터와의 분리

`app/u5-progress.css`에서 탭과 로그 필터가 공유하는 규칙 때문에 로그 필터가 함께 바뀌지 않도록 한다.

- 탭 전용 크기·모서리·간격 변경은 `.u5-console__tabs` 아래로 범위를 제한한다.
- `.u5-log__filters`의 배치, 크기, 활성 상태와 네 필터 문구는 유지한다.
- 공통 focus 규칙을 재사용할 수 있지만, 탭 시각 조정을 위해 로그 필터를 재설계하지 않는다.

## 6. 현재 상황 패널 계약

### 6.1 의미 구조

기존 `p.u5-situation`을 다음과 같은 독립 구역 안에 둔다.

```tsx
<section className="u5-situation-panel" aria-labelledby="u5-situation-title">
  <h3 id="u5-situation-title" className="u5-situation-panel__title">
    현재 상황
  </h3>
  <p className="u5-situation" data-testid="u5-situation">
    {progress.situation}
  </p>
</section>
```

- `현재 상황`은 CSS 가상 요소가 아니라 실제 텍스트로 렌더링한다.
- 기존 `data-testid="u5-situation"`은 본문에 유지해 기존 테스트 계약을 보존한다.
- 패널에 별도 `data-testid="u5-situation-panel"`을 추가할 수 있다.
- 상황 본문은 기존 `progress.situation`만 사용한다. 새 데이터, 아이콘, 위험도 표시나 정답 단서를 추가하지 않는다.

### 6.2 시각 위계

- 패널은 콘솔 가로 폭을 사용한다.
- 콘솔 배경보다 한 단계 밝은 암갈색 판, 얇은 금속·금색 계열 테두리와 작은 모서리 반경을 사용한다.
- 카드와 같은 강한 이중 테두리, 잘린 팔각형, 리벳은 사용하지 않는다. 상황 패널은 판단 근거이며 선택 버튼이 아니다.
- `현재 상황` 제목은 작은 금색 계열 글자와 굵기로 구역을 식별한다.
- 상황 본문은 이전 비교 시안 2안 수준으로 둔다. 구현 기준은 카드 근거와 같은 계열인 `clamp(0.76rem, 0.8cqw, 1.1rem)`과 `line-height: 1.45`다.
- 상황 본문은 카드의 주 조언 문장보다 작고, 카드 근거 문장보다 작아서는 안 된다.
- 제목과 본문 사이 간격은 작게 두되 서로 한 문장처럼 붙어 보이지 않게 한다.
- 패널 padding은 본문 한 줄일 때도 제목과 테두리가 답답하게 붙지 않을 정도로만 둔다. 패널이 큰 카드처럼 보이도록 과도하게 높이지 않는다.

### 6.3 길이와 배치

- 패널 높이는 콘텐츠에 맞춘다. 남은 콘솔 높이를 채우도록 늘리지 않는다.
- 상황 본문은 말줄임표로 자르지 않고 자연스럽게 줄바꿈한다.
- 패널 내부에 별도 스크롤을 만들지 않는다.
- 상황이 두 줄이 되어도 아래 카드 또는 outcome과 겹치지 않아야 한다.
- 공식 1920×1080 캔버스와 1024×640 균일 축소 확인에서 글자가 잘리지 않아야 한다.

## 7. 조언 카드 동결 계약

현재 `main`의 번호 없는 카드 상태를 이번 작업의 기준선으로 고정한다.

다음은 수정하지 않는다.

- `AdviceOption`의 마크업과 내부 정보 순서
- `.u5-advice`, `.u5-advice__button`, `.u5-advice__content`의 높이와 정렬
- `.u5-advice__divider`의 위치, 폭과 색
- 네 모서리 리벳, 잘린 모서리와 이중 테두리
- 카드 주 문장과 근거의 글자 크기
- 카드 3개의 가로 배열과 세로 중앙 정렬
- hover, disabled, 잠금 사유, 비용과 `focus-visible`
- 화면에 숫자 슬롯을 표시하지 않는 상태
- 내부 `slot`, React key와 `onSelectAdvice(slot)` 연결

`어떻게 조언할까?`와 같은 새 안내 문구, 번호를 대신하는 아이콘이나 카드별 장식을 추가하지 않는다.

상황 패널을 추가해 남는 높이가 달라져도 카드 자체를 다시 압축하거나 늘리지 않는다. 필요한 경우 `.u5-advice-mode`의 행 간격만 조정하며 카드 계약은 그대로 둔다.

### `components/game/U5ProgressScreen.test.tsx`

- 기존 번호 없는 카드와 슬롯 callback 회귀 테스트를 그대로 유지한다.

### 공식 문서

## 10. 접근성

- 상황 패널은 `section`과 실제 제목을 사용하고 `aria-labelledby`로 연결한다.
- 제목과 상황 본문은 CSS generated content가 아닌 실제 텍스트다.
- 탭은 실제 `button`, `aria-pressed`와 native Tab 순서를 유지한다.
- 활성 여부는 색뿐 아니라 `aria-pressed`, 테두리와 바탕 차이로 전달한다.
- 탭 `focus-visible`은 활성·비활성 상태 모두에서 분명해야 한다.
- 상황 패널은 버튼처럼 보이거나 클릭 가능하다고 오해할 hover 효과를 갖지 않는다.
- 기존 카드 버튼의 accessible name, focus, disabled와 선택 불가 사유는 변경하지 않는다.

## 11. 오류와 경계 조건

- 상황 본문이 두 줄 이상이어도 패널과 카드가 겹치지 않는다.
- 선택 뒤 outcome이 길어져도 상황 패널이 outcome 위에 남고 기존 outcome overflow 계약을 깨지 않는다.
- 로그 모드로 전환했을 때 상황 패널이 DOM에 남아 숨겨진 중복 정보를 만들지 않는다.
- 탭 전용 CSS를 조정해도 로그 필터 네 개의 크기와 배치가 바뀌지 않는다.
- 패널이 선택 버튼처럼 보이지 않고, 카드가 상황 패널과 같은 정보 상자로 평준화되지 않는다.
- 카드 번호 제거, 카드 구분선 위치와 내부 중앙 정렬은 회귀하지 않는다.

## 12. 테스트 계약

### 12.1 단위·렌더 테스트

- `행동 / 조언`과 `진행 기록`이 실제 버튼으로 렌더링된다.
- 초기 `행동 / 조언` 버튼은 `aria-pressed="true"`, `진행 기록`은 `false`다.
- `현재 상황` 제목과 `progress.situation` 본문이 하나의 상황 패널 안에 렌더링된다.
- DOM 순서는 `탭 → 현재 상황 제목 → 상황 본문 → 조언 카드 목록`이다.
- outcome이 있어도 상황 패널은 결과 영역보다 먼저 렌더링된다.
- `initialMode="log"`에서는 상황 패널이 렌더링되지 않고 기존 기록 필터가 보인다.
- 조언 카드에 `.u5-advice__slot`이나 `1`·`2`·`3` 번호 배지가 되살아나지 않는다.
- 카드 3개가 같은 구조를 유지하고 기존 내부 슬롯 값이 선택 callback에 전달된다.

### 12.2 CSS 계약

- `.u5-situation-panel`은 별도 배경, 테두리와 콘텐츠 기반 높이를 가진다.
- `.u5-situation-panel__title`과 `.u5-situation`의 시각 위계가 분리된다.
- 상황 본문은 `clamp(0.76rem, 0.8cqw, 1.1rem)` 계열과 `line-height: 1.45`를 사용한다.
- 탭 전용 규칙은 `.u5-console__tabs`에 범위가 제한되고 `.u5-log__filters`의 계약을 덮어쓰지 않는다.
- `.u5-advice*` 카드 규칙은 이번 변경에서 수정되지 않는다.
- 새 CSS에 `vw`, `vh`와 화면별 `@media`가 없다.

### 12.3 브라우저 검증

`/u5-test`와 실제 `/campaign` 진행 화면에서 다음을 확인한다.

1. 1920×1080에서 탭이 작고 분명한 상태 전환으로 보인다.
2. `현재 상황` 패널이 탭 바로 아래에서 독립된 판단 근거로 먼저 읽힌다.
3. 상황 본문은 비교 시안 2안 수준이며 카드 주 문장보다 작다.
4. 상황 패널과 카드 사이에 `어떻게 조언할까?` 같은 추가 안내 문구가 없다.
5. 카드 3개는 현재 번호 없는 외형, 높이, 구분선 위치와 중앙 정렬을 그대로 유지한다.
6. 두 줄 상황 fixture에서도 패널, 카드와 결과 영역이 겹치거나 잘리지 않는다.
7. `진행 기록`으로 전환하면 기존 네 필터와 기록 배치가 유지된다.
8. 1024×640에서도 같은 1920×1080 캔버스가 균일 축소되며 스크롤과 clipping이 없다.
9. 키보드만으로 두 탭과 세 카드에 순서대로 접근할 수 있다.

전체 검증은 `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`, `git diff --check`를 포함한다. 게임 수치를 바꾸지 않으므로 `pnpm backtest`는 실행하지 않는다.

## 13. 범위 밖

- 조언 카드의 크기, 높이, 내부 간격, 구분선과 타이포그래피 재설계
- 카드 번호 제거의 재구현 또는 번호를 대신하는 다른 표식 추가
- `어떻게 조언할까?` 등 선택 안내 문구 추가
- 조언 문구, 근거, 비용, 잠금과 선택 결과 변경
- 진행 기록 필터 또는 로그 내용 변경
- 장면 슬롯, 파티 캐릭터, 우측 파티 상태와 CTA 변경
- 전투 replay, 피해, HP, 신뢰, 골드와 RNG 변경
- GameShell 60:40, 진행 장면 40%·콘솔 60% 비율 변경
- 모바일 재배치, 새 breakpoint와 화면별 미디어 쿼리
- 새 이미지, 아이콘과 장식 에셋 제작

## 14. 완료 조건

- `행동 / 조언`과 `진행 기록` 탭이 참고 이미지의 작고 각진 시각 위계로 정리된다.
- 탭 아래에 실제 `현재 상황` 제목과 본문이 있는 독립 패널이 렌더링된다.
- 상황 본문은 승인된 2안 수준의 크기와 줄간격을 사용한다.
- 패널 아래에는 추가 안내 없이 기존 번호 없는 카드 3개 또는 기존 outcome만 이어진다.
- 카드의 외형, 높이, 구분선, 중앙 정렬, 잠금·비용·선택 계약이 바뀌지 않는다.
- 로그 모드, 전투, 우측 패널과 캠페인 규칙에 회귀가 없다.
- 공식 viewport에서 겹침, 잘림과 스크롤이 없다.
- 관련 자동 테스트, 타입 검사, lint, build와 브라우저 검증이 통과한다.
