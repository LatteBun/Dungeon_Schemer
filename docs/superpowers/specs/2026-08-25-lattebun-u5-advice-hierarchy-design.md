# U5 행동·조언 정보 위계 개선 설계

## 문서 정보

- 작성자: LatteBun
- 작성 도구: ChatGPT
- 작성일: 2026-08-25
- 대상: U5 던전 진행 화면의 `행동 / 조언` 모드
- 기준 브랜치: `main` (`10908d4`)
- 상태: 사용자 검토 대기

## 1. 목표

던전 진행 화면의 좌측 하단에서 **상황을 읽고 조언을 고르는 흐름**이 한눈에 들어오도록 정보 위계를 다시 정리한다.

완료 목표는 다음과 같다.

- 기존 1안의 `상황 밴드 → 조언 안내 → 카드 3개` 구조를 적용한다.
- 상황 본문은 비교 시안 2안 정도의 크기로 낮춰 카드 제목과 경쟁하지 않게 한다.
- 카드의 시각적 슬롯 번호 `1 · 2 · 3`을 제거한다.
- 카드 구분선을 조언 문장 바로 아래로 올려 조언과 근거의 위계를 명확히 한다.
- 기존 금속 명패 외형, 동일 카드 규칙, 선택 콜백과 게임 규칙은 유지한다.

이번 변경은 정보 배치와 타이포그래피를 다루는 표현 계층 작업이다. 조언의 내용, 유형, 판정, 비용, 잠금 조건, 선택 결과는 바꾸지 않는다.

## 2. 근거와 현재 문제

근거 문서는 다음과 같다.

- `docs/GAME_PRINCIPLES.md` — 플레이어가 조언의 정답 라벨이 아니라 공개 정보와 현장 단서를 근거로 추론해야 한다.
- `docs/experience/SCREEN_LAYOUT.md` — 상황 묘사를 먼저 보여주고 같은 디자인의 조언 3개를 그 아래 둔다.
- `docs/experience/UI_IMPLEMENTATION_GUIDE.md` — 고정 캔버스에서 핵심 정보의 가독성과 기존 시각 언어를 유지한다.
- `docs/superpowers/specs/2026-08-25-lattebun-progress-screen-ux-design.md` — 낮은 금속 명패형 카드와 동일 외형 계약을 정의한다.

현재 `U5ProgressScreen`은 상황을 장식 없는 단일 문단으로 보여준다. 카드에는 슬롯 번호, 조언 문장, 구분선, 근거 문장이 한 덩어리로 세로 중앙 정렬되어 있다. 이 구조에서는 다음 문제가 생긴다.

- 상황 문장이 콘솔 배경에 묻혀 독립된 판단 근거로 잘 보이지 않는다.
- 카드의 슬롯 번호가 정보 가치에 비해 먼저 눈에 들어오고, 조언을 게임 속 발언보다 객관식 문제처럼 보이게 한다.
- 슬롯 번호가 차지하는 높이 때문에 구분선이 카드 중앙 아래로 밀려 조언 문장과 근거의 관계가 느슨해 보인다.
- 넓은 콘솔 안에서 상황, 선택 안내, 선택지가 같은 시각적 목소리로 놓여 시선의 착륙 지점이 불명확하다.

## 3. 승인된 정보 구조

선택 전 `행동 / 조언` 모드는 다음 순서로 렌더링한다.

```text
행동 / 조언 탭
└─ 상황 밴드
   ├─ 라벨: 현재 상황
   └─ 상황 본문
└─ 선택 안내: 어떻게 조언할까?
└─ 동일한 조언 카드 3개
   ├─ 조언 문장
   ├─ 구분선
   ├─ 근거 문장
   ├─ 선택 비용, 있는 경우
   └─ 선택 불가 사유, 있는 경우
```

선택 뒤 결과가 존재할 때는 다음 구조를 사용한다.

```text
행동 / 조언 탭
└─ 상황 밴드
   ├─ 라벨: 현재 상황
   └─ 상황 본문
└─ 기존 결과 영역
   ├─ 파티원별 반응
   ├─ 사건 결과
   └─ 수치·신뢰 변화
```

`어떻게 조언할까?` 안내는 실제 선택지가 있을 때만 보인다. 결과 화면에는 남기지 않는다.

## 4. 상황 밴드 계약

### 4.1 구조

기존 `p.u5-situation`을 독립된 상황 밴드 안에 둔다.

- 밴드는 콘솔 가로 폭을 사용한다.
- `현재 상황` 라벨과 실제 상황 본문을 분리한다.
- 라벨은 장식이 아니라 구역의 의미를 전달하므로 화면에 실제 텍스트로 렌더링한다.
- 상황 본문은 기존 `progress.situation` 값을 그대로 사용한다.
- 새로운 아이콘, 위험도 색, 정답 단서, 별도 상태 값은 추가하지 않는다.

### 4.2 시각 위계

- 밴드는 콘솔 배경보다 한 단계 밝거나 짙은 암색 판과 얇은 금속·금색 계열 테두리로 구분한다.
- `현재 상황` 라벨은 작은 금색 계열 강조로 표시한다.
- 상황 본문은 비교 시안 2안 수준으로 낮춘다. 구현 기준은 현재 카드 근거 문장과 같은 타이포그래피 규모인 `clamp(0.76rem, 0.8cqw, 1.1rem)`을 사용하고, 줄간격은 약 `1.45`로 둔다.
- 상황 본문은 카드의 주 조언 문장보다 작아야 하지만 카드 근거보다 작아서는 안 된다.
- 밴드 높이는 콘텐츠에 맞춘다. 남은 콘솔 높이를 채우도록 늘리지 않는다.
- 표준 콘텐츠는 1920×1080과 1024×640 고정 캔버스 축소에서 잘림 없이 읽혀야 한다.

## 5. 선택 안내 계약

상황 밴드와 카드 목록 사이에 `어떻게 조언할까?`를 둔다.

- 선택을 요구하는 전환 문구이며 버튼이 아니다.
- 상황 라벨보다 시각적 강조를 낮추고 카드 주 문장보다 작게 표시한다.
- 카드 목록과 가까이 두어 아래의 세 카드가 이 질문에 대한 선택지임을 연결한다.
- `progress.outcome !== null`이면 렌더링하지 않는다.
- 스크린 리더가 카드마다 이 문구를 반복해 읽지 않도록 버튼 내부에는 넣지 않는다.

## 6. 조언 카드 내부 위계

### 6.1 슬롯 번호 제거

- `.u5-advice__slot` 요소를 DOM에서 제거한다. CSS로 숨기기만 하지 않는다.
- `slot` 값은 카드의 식별, React key, `onSelectAdvice(slot)` 호출을 위해 내부적으로 계속 사용한다.
- 화면에 `1`, `2`, `3`을 대신하는 새 배지나 아이콘을 추가하지 않는다.
- 카드의 DOM 순서, 키보드 Tab 순서, 좌우 배열 순서는 기존과 같다.

기존 번호는 `aria-hidden`이었으므로 제거해도 버튼의 접근 가능한 이름은 줄어들지 않는다.

### 6.2 조언과 근거의 위계

카드 내부 정보 순서는 다음으로 고정한다.

```text
조언 문장
구분선
근거 문장
선택 비용, 있는 경우
선택 불가 사유, 있는 경우
```

- 조언 문장은 카드에서 가장 큰 텍스트로 유지한다.
- 구분선은 조언 문장 바로 다음에 둔다.
- 표준 카드에서는 구분선이 카드 세로 중앙보다 위쪽에 위치해야 한다.
- 근거 문장은 구분선 아래에서 보조 색과 작은 글자 크기를 유지한다.
- 비용과 선택 불가 사유는 기존 의미와 접근성을 유지하며 근거 아래에 놓는다.
- 긴 문구가 있는 카드 하나만 높아지지 않는다. 세 카드는 같은 공통 높이를 유지한다.

### 6.3 유지하는 시각 계약

다음은 변경하지 않는다.

- 모서리를 잘라낸 금속 명패 실루엣
- 이중 테두리와 네 모서리 리벳
- 세 카드의 동일한 색, 크기, 장식, hover, focus 표현
- 가로 3열 배치와 카드 목록의 세로 중앙 정렬
- 잠긴 카드의 disabled 상태와 선택 불가 사유
- 조언 유형과 유불리를 외형으로 드러내지 않는 규칙

`help / harm / neutral`, `consistent / contradictory`, 발각 확률, 예상 신뢰 변화는 선택 전후 카드 마크업에 추가하지 않는다.

## 7. 컴포넌트와 데이터 경계

예상 변경 범위는 다음과 같다.

### `components/game/U5ProgressScreen.tsx`

- 상황 밴드의 의미 있는 컨테이너와 `현재 상황` 라벨을 추가한다.
- 선택 전용 안내 문구 `어떻게 조언할까?`를 추가한다.
- `AdviceOption`에서 시각적 슬롯 번호 요소를 제거한다.
- 기존 `slot` 기반 선택 콜백은 유지한다.

### `app/u5-progress.css`

- 상황 밴드, 라벨, 선택 안내의 스타일을 추가한다.
- `u5-advice-mode`의 행 구조와 간격을 새 정보 순서에 맞춘다.
- 상황 본문 글자 크기를 승인된 2안 수준으로 조정한다.
- 카드 콘텐츠의 행과 간격을 조정해 구분선을 위로 올린다.
- `.u5-advice__slot`과 disabled 슬롯 스타일을 제거한다.

### 테스트

- `components/game/U5ProgressScreen.test.tsx`의 마크업·CSS 계약을 갱신한다.
- 필요하면 기존 U5 브라우저 검증에 상황 밴드와 카드 내부 배치의 기하 검사를 추가한다.

다음 데이터와 상태는 변경하지 않는다.

- `U5ProgressView`
- 조언 배열과 `slot` 값
- `onSelectAdvice`
- outcome, log, ecology, battle replay
- HP, 신뢰, 골드, RNG와 사건 판정

## 8. 접근성

- 상황 밴드는 `현재 상황`을 이름으로 갖는 의미 있는 구역으로 표현한다.
- 라벨과 본문은 실제 텍스트로 제공한다.
- 카드 3개는 기존 실제 `button`을 유지한다.
- 슬롯 번호 제거 뒤에도 카드의 보이는 조언 문장과 근거가 accessible name을 구성한다.
- native Tab 순서와 좌우 DOM 순서를 바꾸지 않는다.
- 기존 `focus-visible` 표현을 유지하고 잘린 모서리 안에서 초점이 분명해야 한다.
- disabled 카드와 선택 불가 사유의 연결을 유지한다.
- 상황 밴드, 선택 안내, 카드 구분은 색에만 의존하지 않고 테두리·간격·텍스트를 함께 사용한다.

## 9. 오류와 경계 조건

- 상황 본문이 두 줄이 되어도 밴드와 카드가 겹치지 않아야 한다.
- 카드 제목이 두 줄이 되어도 구분선은 제목 뒤, 근거 앞에 있어야 한다.
- 비용과 선택 불가 사유가 함께 있어도 카드 밖으로 잘리지 않아야 한다.
- 선택지가 세 개보다 적거나 많아지는 새 동작은 이번 범위에서 만들지 않는다. 기존 U5 계약대로 세 개를 전제로 한다.
- 선택 뒤 결과 화면에서 `어떻게 조언할까?`가 남아 다음 선택이 있는 것처럼 보이면 안 된다.
- 로그 모드, 전투 장면, 우측 파티 패널과 다음 단계 CTA에는 레이아웃 회귀가 없어야 한다.

## 10. 테스트 계약

### 10.1 단위·렌더 테스트

- `현재 상황` 라벨과 상황 본문이 조언 안내와 카드 목록보다 먼저 렌더링된다.
- 선택 전에는 `어떻게 조언할까?`가 보이고 선택 뒤 outcome 화면에는 보이지 않는다.
- 조언 카드 3개에 `.u5-advice__slot`이 존재하지 않는다.
- 화면에 슬롯 번호용 배지 `1 · 2 · 3`이 렌더링되지 않는다.
- 카드 3개가 같은 class와 같은 내부 구조를 유지한다.
- 첫째, 둘째, 셋째 카드를 선택하면 기존과 같이 각각 `0`, `1`, `2`가 `onSelectAdvice`에 전달된다.
- 조언 카드 마크업에 내부 판정 어휘가 새지 않는다.
- 선택 불가 사유와 비용 표시의 기존 회귀 테스트가 통과한다.

### 10.2 CSS 계약

- 상황 밴드가 별도 배경과 테두리를 가진다.
- 상황 본문이 승인된 2안 타이포그래피 규모를 사용한다.
- 카드 콘텐츠에서 조언 문장 다음 요소가 구분선이고, 그 다음이 근거 문장이다.
- 슬롯 번호 전용 CSS가 남지 않는다.
- 카드 높이, 잘린 모서리, 이중 테두리, 리벳, focus-visible 계약은 유지된다.

### 10.3 브라우저 검증

`/u5-test`와 실제 `/campaign` 진행 화면에서 다음을 확인한다.

1. 1920×1080에서 상황 밴드가 독립된 판단 근거로 먼저 보인다.
2. 상황 본문은 카드 주 문장보다 작고 카드 근거 문장과 같은 수준으로 읽힌다.
3. 카드 번호가 보이지 않고 세 카드의 폭과 높이가 같다.
4. 표준 카드의 구분선이 카드 세로 중앙보다 위에 있고 조언 문장과 가깝다.
5. 긴 상황·조언 fixture에서도 텍스트, 리벳, 비용, 잠금 사유가 잘리지 않는다.
6. 1024×640에서도 같은 1920×1080 고정 캔버스 배치가 균일 축소된다.
7. 두 viewport에서 겹침, clipping, 가로·세로 스크롤, 콘솔 오류가 없다.
8. 키보드만으로 세 카드를 순서대로 탐색하고 선택할 수 있다.

전체 검증은 `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`, `git diff --check`를 포함한다. 게임 수치를 바꾸지 않으므로 `pnpm backtest`는 실행하지 않는다.

## 11. 완료 조건

- `현재 상황` 밴드가 상황 본문을 독립된 정보 구역으로 묶는다.
- 상황 본문 글자 크기가 승인된 2안 수준으로 적용된다.
- 선택 전 `어떻게 조언할까?`가 상황과 카드 사이를 연결한다.
- 조언 카드에서 시각적 슬롯 번호가 완전히 제거된다.
- 구분선이 조언 문장 바로 아래, 카드 상반부에 위치한다.
- 세 카드는 기존 금속 명패 외형과 동일 디자인 원칙을 유지한다.
- 선택 콜백, 잠금, 비용, 결과, 로그, 전투와 캠페인 규칙에 회귀가 없다.
- 공식 viewport에서 텍스트 잘림과 스크롤이 없다.

## 12. 변경하지 않는 것

- GameShell 60:40과 진행 화면 장면 40%·콘솔 60% 구조
- 행동 / 조언과 진행 기록의 두 탭
- 조언 3개의 가로 배열과 카드 공통 높이
- 카드의 금속 명패 외형과 리벳
- 조언 문구·근거 문구·비용·잠금 데이터
- 도움·방해·중립과 정합 판정
- outcome의 반응 → 결과 → 변화 순서
- 전투 replay, 비전투 파티 장면, 우측 파티 상태, 다음 단계 CTA
- 이미지와 기타 시각 에셋 파일

## 13. 기존 문서와의 관계

이 설계는 `docs/experience/SCREEN_LAYOUT.md`의 다음 공식 계약을 바꾸지 않고 구체화한다.

- 상황 묘사가 조언보다 먼저 온다.
- 조언 세 개는 같은 디자인이다.
- 카드는 남은 높이를 전부 채우지 않고 같은 높이로 중앙 정렬된다.

`docs/superpowers/specs/2026-08-25-lattebun-progress-screen-ux-design.md`의 금속 명패, 리벳, 동일 외형 계약은 유지한다. 다만 해당 문서 3.1절의 **기존 슬롯 번호 유지**와 **번호부터 근거까지의 정보 순서**는 이 후속 설계가 대체한다.
