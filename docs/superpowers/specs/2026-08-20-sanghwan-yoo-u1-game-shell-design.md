## 1. 목적

U1은 인트로부터 정산·엔딩까지 모든 주요 화면이 공유할 게임 셸을 만든다. 셸은 화면별 게임 규칙이나 캠페인 상태를 소유하지 않고, 전체 폭 상단 상태 바와 고정된 본문 두 열을 제공한다. 이후 `U2`~`U6`는 같은 셸에 콘텐츠만 주입한다.

셸은 단순한 grid 골격이 아니라 세 레퍼런스가 보여 주는 다크 판타지 정보 위계의 공통 기반이다. 왼쪽은 플레이어가 읽고 조작하는 세계·공고·지도·장면이고, 오른쪽은 계약 상세·개인 파티 상태·반응·행동처럼 즉시 판단에 필요한 정보를 넓게 제공한다.

구현 결과는 실제 캠페인 규칙을 연결하지 않은 `/u1-test` 프리뷰에서 확인한다. 프리뷰는 다섯 화면의 콘텐츠 교체, 접근성 상태, 3:2 레이아웃과 시각 역할을 검증하는 하네스이며 실제 게임 흐름이 아니다.

## 2. 사용자 승인으로 확정한 핵심 불변 조건

### 2.1 셸은 항상 3:2, 즉 60%:40%다

셸 본문은 어떤 화면·상태·지원 해상도에서도 두 열을 유지한다.

```text
GameShell
├─ TopStatusBar  전체 폭
└─ Body
   ├─ MainContent  3fr · 약 60%
   └─ RightPanel   2fr · 약 40%
```

- 본문 grid track은 항상 `minmax(0, 3fr) minmax(0, 2fr)`이다.
- 인트로처럼 우측에 콘텐츠가 없어도 우측 40% 레일을 구조적으로 렌더링한다. 두 열을 합쳐 MainContent를 전체 폭으로 확장하지 않는다.
- breakpoint나 상태별 예외로 열을 세로로 쌓거나 열 비율을 바꾸지 않는다.
- 좁은 화면에서는 각 열의 내부 콘텐츠가 줄바꿈되고 세로 스크롤만 생긴다.
- `min-width: 0`, 줄바꿈, 유연한 상태 바를 사용해 콘텐츠가 열의 폭을 밀어내지 않도록 한다.
- 브라우저 검증에서 실제 두 grid track의 너비 비율이 3:2인지 직접 확인한다. 단순히 화면이 보이는지만 확인하지 않는다.

기존 3:1·좌 75%·우 25% 선언은 현재 화면 규격과 U1 산출물에서 3:2·좌 60%·우 40%로 일괄 교체한다. 2026-08-18 회의록은 당시 결정을 보존하는 원본 기록이므로 수정하지 않는다.

### 2.2 셸과 콘텐츠를 분리한다

- `GameShell`은 레이아웃·랜드마크·공통 크롬과 상태 표시만 책임진다.
- `TopStatusBar`는 전달받은 표시값만 렌더링한다.
- `U1Preview`는 다섯 화면 중 현재 선택과 프리뷰용 표시 데이터를 보유한다.
- 캠페인 규칙, 도메인 상태, 난수, Zustand, 영속화는 U1에 넣지 않는다.
- 프리뷰 fixture는 프리뷰 경계에 두고 게임 컴포넌트에는 props로 전달한다.

### 2.3 레퍼런스는 시각 언어와 정보 위계를 정하고, PNG 자체는 제품에 넣지 않는다

세 레퍼런스를 실제로 확인한 결과, 다음을 U1의 공통 기준으로 채택한다.

- 전체 폭 상단 상태 바: 등급·명성·골드·승급·남은 던전을 작은 라벨과 값이 짝인 상태 칩으로 나눈다.
- 좌측 조작 영역과 우측 상세 영역: 우측 40%는 보조 컬럼이 아니라 계약·파티·반응·행동을 읽는 동등한 판단 영역이다.
- 다크 판타지 재질감: 짙은 잉크 바탕, 따뜻한 목재·금속 테두리, 양피지형 콘텐츠 면, 금색 강조, 녹색 활성·붉은 위험 단서를 사용한다.
- 정보 밀도: 우측에는 큰 제목 하나만 두지 않고 작은 상태 카드·행동 패널처럼 구획을 나눌 수 있는 프레임을 제공한다. 좌측은 공고·지도·장면·카드처럼 화면별 핵심 조작 대상을 담는다.

레퍼런스 세 장은 화면별 실제 폭이 동일하지 않지만, 사용자 승인에 따라 U1 이후 모든 공통 셸의 수치 기준은 3:2로 통일한다. 레퍼런스는 구도·분위기·정보 위계의 근거이지 픽셀 단위 복제 대상이 아니다. PNG를 배경이나 UI 조각으로 임베드하지 않고, 외부 이미지·새 의존성 없이 CSS와 기존 UI 프리미티브로 구현한다.

## 3. 대안 검토

### 대안 A — 범용 `Panel` 전체를 레퍼런스 스타일로 변경

- 장점: 작성량이 적다.
- 단점: 게임 도메인을 모르는 프리미티브가 게임 전용 아트를 소유하고, 기존·후속 비게임 UI까지 영향을 받는다.

### 대안 B — 슬롯 기반 셸에 게임 전용 크롬을 추가한다 (채택)

`GameShell`은 `main`과 `rightPanel` 슬롯을 유지하고, 게임 셸 전용 class와 토큰으로 프레임·열 경계·상태 칩을 제공한다. 기존 `Panel`은 의미 계약을 유지하고, U1 프리뷰와 후속 게임 화면이 game class를 통해 외관을 입힌다.

- 장점: U2~U6는 같은 셸 API와 다크 판타지 시각 기반을 재사용한다.
- 장점: UI 프리미티브의 게임 비의존 경계를 보존한다.
- 장점: 다섯 프리뷰 화면을 한 viewport에서 비교할 수 있다.
- 단점: U1 프리뷰는 실제 캠페인을 진행하지 않는다.

### 대안 C — 레퍼런스 PNG를 직접 배경·UI로 사용한다

- 장점: 외형을 빠르게 비슷하게 만들 수 있다.
- 단점: 반응형, 접근성, 텍스트·상태 교체, 실제 상호작용과 맞지 않는다.
- 단점: 후속 화면의 재사용 가능한 코드 기반이 되지 못한다.

대안 B가 U1의 재사용 책임과 사용자 승인 범위를 동시에 만족한다.

## 4. 컴포넌트 계약

### 4.1 `GameShell`

위치: `components/game/GameShell.tsx`

책임:

- 전체 게임 화면의 `header`와 `main` landmark를 제공한다.
- 상단 상태 바 아래에 항상 3:2 두 열을 렌더링한다.
- 셸의 바탕, 목재·금속형 프레임, 열 경계와 공통 여백을 제공한다.
- MainContent와 RightPanel의 콘텐츠를 전달받아 표시한다.
- 우측 콘텐츠가 없어도 구조적 RightPanel을 유지한다.

개념적 props는 유지한다.

```ts
interface GameShellProps {
  status: TopStatusView;
  screenTitle: string;
  main: ReactNode;
  rightPanel?: ReactNode;
  rightPanelLabel?: string;
}
```

`main`과 `rightPanel`은 게임 도메인 타입이 아닌 `ReactNode` 슬롯이다. 셸은 슬롯 내부를 해석하지 않는다.

### 4.2 `TopStatusBar`

위치: `components/game/TopStatusBar.tsx`

표시 항목은 길잡이 등급, 현재 명성, 현재 골드, 승급 가능 여부, 남은 던전 수, 선택적 현재 던전명·위험도다. 각 항목은 라벨·값·상태 기호가 함께 있는 독립 상태 칩으로 읽힌다. 승급 가능 여부는 색상만으로 표현하지 않고 `승급 가능` 또는 `승급 조건 미달` 문구를 함께 표시한다.

### 4.3 `U1Preview`

위치: `components/game/U1Preview.tsx`

프리뷰 화면 ID는 다음 다섯 개로 고정한다.

```ts
type U1PreviewScreen =
  | "intro"
  | "board"
  | "map"
  | "progress"
  | "settlement";
```

화면 선택은 버튼으로 구현하고 현재 버튼에 `aria-pressed="true"`를 준다. U1 프리뷰는 실제 규칙 없이도 레퍼런스의 정보 위계를 확인할 수 있도록 화면별 정적 모형을 제공한다.

- 게시판: 좌 공고 카드군, 우 계약·출전 파티·보상 구획
- 지도: 좌 공간형 노드·경로 모형, 우 개인 파티 상태·다음 지점·진입 행동
- 진행: 좌 장면 슬롯과 세 선택 카드, 우 파티원별 최근 반응·현재 행동
- 인트로·정산: 같은 프레임과 우측 레일을 유지한 요약 패널

이 모형은 U2~U6의 실제 데이터·규칙·전이를 구현하지 않으며, 화면별 후속 작업이 대체할 콘텐츠 경계만 보여 준다.

### 4.4 프리뷰 라우트

위치: `app/u1-test/page.tsx`

라우트는 `U1Preview`를 렌더링하는 진입점만 담당한다. 실제 캠페인 시작·전이·저장은 제공하지 않는다.

## 5. 레이아웃과 스타일

### 5.1 본문 grid

셸 본문은 전 viewport에서 동일한 grid 선언을 사용한다.

```css
.game-shell__body {
  display: grid;
  grid-template-columns: minmax(0, 3fr) minmax(0, 2fr);
}
```

열 사이의 구분은 별도 열을 추가하지 않고 RightPanel의 border와 내부 padding으로 표현한다. 따라서 두 track의 너비 비율은 3:2로 직접 측정할 수 있다.

새 breakpoint에서 `grid-template-columns: 1fr`, `display: block`, `grid-column: 1 / -1`을 사용하지 않는다. 이는 3:2 불변 조건을 깨므로 금지한다.

### 5.2 공통 시각 크롬

- `app/globals.css`의 `@theme`에 게임 셸 전용 색상 토큰을 추가한다. 임의의 hex를 개별 JSX에 쓰지 않는다.
- 게임 셸에만 다층 border, inset shadow, 목재·금속에 가까운 명도 차와 양피지형 콘텐츠 면을 적용한다.
- 게임 전용 class를 사용해 `Panel`의 일반적인 구조·접근성·도메인 비의존성을 보존한다.
- 선택·활성·위험은 각각 금색·녹색·붉은색을 쓰되, 라벨·기호·테두리·`aria-*` 중 하나 이상을 함께 제공한다.
- 상단 상태와 우측 세부 정보는 작은 화면에서 줄바꿈할 수 있지만 각 컬럼 내부의 정보 위계를 잃지 않는다.

### 5.3 overflow 방지

- 셸, 본문, 두 열, 상태 바에 `min-width: 0`을 적용한다.
- 긴 텍스트는 `overflow-wrap: anywhere` 또는 동등한 유틸리티로 줄바꿈한다.
- 고정 폭 카드·패널·버튼을 만들지 않는다.
- 가로 overflow를 숨겨 검증을 우회하지 않는다. 콘텐츠 자체가 줄어들도록 만든다.
- 기준 해상도는 1280×720, 최소 지원은 1024×640이다.
- 최소 지원 아래에서도 3:2는 유지하고 세로 방향으로만 콘텐츠가 늘어날 수 있다.

## 6. 접근성

- 화면 전환 컨트롤은 네이티브 button이다.
- 버튼 이름에 화면 목적을 명시한다.
- 현재 화면은 `aria-pressed`와 시각적 상태 단서를 함께 가진다.
- `header`, `main`, `aside` landmark를 의미에 맞게 사용한다.
- 우측 레일이 비어 있는 인트로에서도 구조적 레일은 유지하되 빈 상태가 보조기술에 불필요한 내용을 만들지 않도록 한다.
- 키보드 Tab 순서가 화면 선택 컨트롤에서 셸 콘텐츠로 자연스럽게 이어진다.
- 포커스 표시를 제거하지 않는다.

## 7. 테스트와 검증

### 7.1 자동 검사

- 프리뷰 화면 ID가 정확히 다섯 개이고 중복이 없는지 검사한다.
- 화면별 셸 입력이 MainContent와 RightPanel 슬롯을 제공하는지 검사한다.
- 상태 바 표시값과 화면 제목의 fixture 계약을 검사한다.
- 정적 렌더 결과가 3:2 셸 구조, 인트로의 구조적 우측 레일, 레퍼런스형 프리뷰 구획의 명시적 class·텍스트 계약을 지키는지 검사한다.
- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`

React DOM 동작의 핵심은 Node 단위 테스트로 흉내 내지 않고 실제 브라우저 검증으로 확인한다. 현재 저장소에는 `jsdom`과 React Testing Library가 없으므로 U1에서 별도 테스트 환경을 추가하지 않는다.

### 7.2 브라우저 검증

개발 서버를 실행한 뒤 실제 브라우저 자동화로 `/u1-test`를 확인한다.

검증 항목:

1. 페이지 진입 성공, Next 오류 overlay 부재, console/page error 0건
2. 다섯 화면 선택 버튼과 전체 폭 상태 바 노출
3. 마우스 클릭과 키보드 Enter에 의한 화면 전환
4. 현재 버튼의 `aria-pressed` 변경
5. 화면별 제목·좌측 모형·우측 패널 구획 교체
6. 인트로에서도 우측 40% 구조적 레일 유지
7. 1280×720에서 두 grid track 비율 3:2
8. 1024×640에서 두 grid track 비율 3:2
9. 두 해상도에서 `scrollWidth <= innerWidth`
10. 두 해상도에서 가로로 잘린 셸 콘텐츠가 없고 세로 스크롤만 허용됨
11. 다섯 프리뷰 화면의 실제 스크린샷을 레퍼런스와 비교해, 좌 조작·우 상세의 역할, 상태 칩, 패널 구획, 다크 판타지 대비가 보이는지 육안 확인

브라우저 검증이 실패하면 U1 완료 기록과 공식 문서 갱신을 하지 않는다. 수정 뒤 전체 자동 검사와 브라우저 검증을 다시 실행한다.

## 8. 범위 밖

- 실제 캠페인 상태와 Zustand 스토어 연결

## 10. 완료 기준

- `GameShell`이 모든 프리뷰 화면에서 같은 3:2 구조를 렌더링한다.
- 모든 화면과 모든 지원 viewport에서 MainContent:RightPanel grid track 비율이 3:2다.
- 인트로에도 우측 40% 레일이 유지된다.
- 1280×720 및 1024×640에서 가로 스크롤이 없다.
- 다섯 화면이 버튼과 키보드로 전환된다.
- 상태·포커스·선택 여부가 색상 외 단서와 접근성 속성으로 전달된다.
- 공통 크롬과 프리뷰가 세 레퍼런스의 좌 조작·우 상세 구조, 상태 칩, 다크 판타지 패널 위계를 반영한다.
- 자동 검증 네 명령과 실제 브라우저 검증이 모두 통과한다.
- 현재 공식 문서와 작업 배정표가 구현과 같은 변경 단위로 갱신된다.
