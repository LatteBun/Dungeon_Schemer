## 1. 고정하는 범위

- F5 아이템 콘텐츠와 `ItemDef`·`ItemKind`·`ItemId` 계약을 제거한다.
- merchant는 공용 사건이며, H/X는 유료 개입, N은 0G 비구매다.
- 지도 구조·생태 규칙·조언 반응·골드 승급 비용·계약 보상은 바꾸지 않는다.
- merchant 효과는 즉시형 또는 다음 전투 한 번형만 허용한다. 인벤토리·장비·수량·장기 상태는 만들지 않는다.

## 2. 사건 배치는 원정 시작 시 확정한다

`pendingMerchantEffect`를 이유로 이미 생성한 지도나 사건을 다시 뽑지 않는다.

- E3는 원정 시작 시 지도와 각 일반 지점의 사건을 시드로 확정한다.
- 계약 화면에서 공개하는 지점 제목·분류와 실제 사건은 변하지 않는다.
- 현재 원정에서 같은 사건은 중복 배치하지 않는다.
- 따라서 이전 review의 “pending 상태에서 H/X 모두 delayed-only인 merchant를 신규 배치 후보에서 제외” 규칙과 해당 테스트 가드는 삭제한다.
- pending 상태에서 delayed 성분을 가진 H/X는 계속 표시하되 `효과 중복 불가`로 실행 불가다. neutral과 immediate-only H/X는 정상적으로 선택할 수 있다.

이 결정은 사전 답사 정보, 같은 시드 재현, 생성 오류 시 조용히 재추첨하지 않는 계약을 보존한다.

## 3. 단일 효과 계약

콘텐츠는 효과를 숫자 태그에 흩어 적지 않는다. merchant 조언만 갖는 선언형 계약을 두고 E3와 E4가 같은 값을 해석한다.

```text
MerchantAdvice
- goldCost: 0 이상의 정수
- merchantEffect:
  - immediateHpDeltaPerMember?: 정수
  - nextBattle?: {
      incomingDamageMultiplier?: 양수
      partyDamageMultiplier?: 양수
    }
```

- `neutral`: `goldCost === 0`, `merchantEffect` 없음
- `help`·`harm`: `goldCost > 0`, `merchantEffect` 있음
- immediate와 nextBattle은 한 선택에 함께 있을 수 있다.
- nextBattle 안에서는 피해 감소/증가 또는 파티 공격력 보정 중 하나만 둔다. 여러 보정을 조합하지 않는다.
- H/X의 비용·효과는 조언이 실제 실행될 때 한 번만 적용한다. 전원 의심 또는 방해 즉시 적발이면 둘 다 적용하지 않는다.

`effectTags`는 화면 분류와 서술용으로 유지한다. HP·전투 수치를 해석하는 입력으로 사용하지 않는다.

## 4. 수치와 적용 규칙

### 4.1 즉시 HP

즉시 HP 변화는 살아 있는 파티원 각각에게 적용한다. 회복은 최대 HP를 넘지 않고, merchant의 직접 피해는 HP를 1 미만으로 내리지 않는다.

| 강도 | 회복 | 피해 |
| --- | ---: | ---: |
| 소 | +4 | -3 |
| 중 | +8 | -6 |
| 대 | +14 | -10 |

이 수치는 E3의 일반 사건 피해나 보스 기본 피해를 바꾸지 않는다. 이동·안전 계열의 “현재 위험 조정”도 이 사건 안에서 즉시 적용되는 HP 변화로 표현한다. 지도 노드·분기·시드·미방문 지점 상태는 절대 바꾸지 않는다.

### 4.2 다음 전투

다음 전투는 다음 `monster` 사건의 전투 처리이며, 그 전에 monster가 없으면 보스전이다. 적용 대상 전투가 시작할 때 아래 보정 하나를 적용하고, 성공·실패·전멸과 무관하게 전투 종료 직후 슬롯을 비운다.

| 강도 | 받는 피해 보정 H/X | 파티 공격력 보정 H/X |
| --- | --- | --- |
| 약 | 0.90 / 1.10 | 1.15 / 0.85 |
| 일반 | 0.75 / 1.25 | 1.30 / 0.70 |
| 강 | 0.60 / 1.40 | 1.50 / 0.60 |
| 최상급 | 0.50 / 1.50 | 1.70 / 0.50 |

`incomingDamageMultiplier`는 그 전투에서 파티원이 받는 모든 피해에, `partyDamageMultiplier`는 파티가 가하는 모든 피해에 적용한다. 보스 정보의 개인별 피해 보정과는 별도 입력이며, E4가 두 보정을 한 번씩만 합성한다.

## 5. 예약 효과와 책임 경계

`ExpeditionState`에는 `pendingMerchantEffect | null` 하나만 둔다.

- 즉시형은 슬롯을 사용하지 않는다.
- delayed 또는 복합 효과는 슬롯을 사용한다.
- 슬롯이 차 있으면 새 delayed 성분은 교체·누적·예약하지 않는다.
- 던전 종료, 전멸, 정산 진입 시 남은 슬롯을 폐기한다.
- E3는 merchant의 실행 가능 여부, 결제, 즉시 효과, monster 전투 진입 시 슬롯 소비를 책임진다.
- E4는 보스전 진입 시 슬롯을 읽어 보스전 수치에 한 번 합성하고, 전투 후 슬롯을 비운다.
- 어느 계층도 merchant 효과를 별도 인벤토리나 캐릭터 장비 상태로 복제하지 않는다.

## 7. 타입·콘텐츠 검증

- merchant와 비merchant 조언을 구분하는 식별 가능한 타입을 둔다. 비merchant 조언에 `goldCost`나 `merchantEffect`를 임의로 붙일 수 없게 한다.
- merchant 검증기는 H/X/N의 비용 계약, 효과 유무, numeric multiplier의 양수성, pending 효과의 최대 한 개를 검사한다.
- 공용 조언의 생태 source 금지·보스 modifier 금지, 조언 3개/H-X-N 불변식은 기존 검증기를 그대로 유지한다.
- merchant 30개, 계열별 6개, 가격 편향 가드, 정보 판매·인벤토리 문구 부재를 테스트한다.

## 9. 수용 기준 보정

기존 수용 기준에 다음을 추가하고, 이전 review의 동적 배치 관련 기준은 제거한다.

1. 생성 완료 뒤 pending 상태가 변해도 지도·지점 사건·시드 결과는 변하지 않는다.
2. pending 상태에서 delayed H/X는 표시되지만 실행할 수 없다.
3. immediate-only H/X와 N은 pending 상태에서도 기존 결제·반응 규칙을 따른다.
4. 모든 merchant H/X 효과가 4절과 6절의 수치로 해석된다.
5. 다음 monster 또는 보스전이 끝나면 pending 효과는 정확히 한 번 적용되고 제거된다.
6. 어떤 merchant 직접 피해도 즉시 사망·인벤토리·장기 상태를 만들지 않는다.
