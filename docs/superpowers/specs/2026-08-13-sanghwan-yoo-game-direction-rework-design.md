# 던전 15개 캠페인 게임 방향 개편 설계

> 상태: 사용자 검토 요청
> 작성일: 2026-08-13
> 작성자: SangHwan Yoo
> 작성 도구: Codex

## 목적

기존의 한 번짜리 던전 탐험 프로토타입을 `던전 15개를 모두 처리하는 지속 캠페인`으로 확장한다. 플레이어는 직접 싸우거나 보스와 거래하는 존재가 아니라, 용사 파티에게 경로와 정보를 제공하고 사건에 개입하는 고블린 길잡이다.

이 문서는 게임의 새 대전제와 시스템 간 계약을 확정한다. 세부 구현 plan은 이 문서를 공유 기준으로 삼아 캠페인 규칙, 탐험 규칙, 화면·통합의 세 트랙으로 나눈다.

## 근거와 문서 우선순위

설계 결정은 다음 자료를 바탕으로 한다.

1. [게임 방향 개편 질문지](../2026-08-13-game-direction-brainstorming-questionnaire.md)의 사용자 답변
2. [게임 원칙](../../GAME_PRINCIPLES.md)
3. `docs/design`, `docs/systems`, `docs/experience`의 개편된 공식 문서

규칙이 충돌하면 게임 원칙, 공식 시스템 문서, 이 상위 spec, 과거 spec·plan 순으로 해석한다. 과거 문서는 당시 구현 근거로 보존하되 새 캠페인의 제품 요구사항으로 사용하지 않는다.

## 범위

### 포함

- 던전 15개의 캠페인 생성과 공고 게시판
- 지속되는 3인 파티 15팀, 예비 인원 6명, 충원·재편·회복
- C/B/A/S 등급별 대칭 지도와 제한된 정보 전달 기회
- 용사 파티의 개인별 카드 반응, 사건 행동, 자동 보스전
- 생존·전멸 정산, 명성·골드 승급, 던전 등급 상승
- 정상 완주와 세 조기 종료를 포함한 네 엔딩
- 결정적 시드 재현, 생성 불변식 검사, 10,000개 시드 백테스트
- 관련 공식 문서와 과거 설계 기록의 대체 관계 정리

### 제외

- 저장·복원, 서버, 로그인, Supabase 연동
- 고유 이름·서사·보스를 가진 던전 15개 콘텐츠
- 길잡이의 직접 전투
- 보스 거래 또는 보스에게 파티 정보를 넘기는 행동
- 등급에 따른 `C·B 3명 / A 4명 / S 5명` 출전 규모 변경
- 코드 구현과 배포

마지막 항목 때문에 이번 작업은 공식 문서, 상위 spec, 상세 구현 plan 작성에서 끝난다. 코드는 승인된 spec과 plan이 모두 갖춰진 뒤 별도 작업으로 구현한다.

## 핵심 경험

플레이어는 던전을 미리 답사해 전체 경로와 사건의 성격을 안다. 그러나 정확한 피해, 보상, 난수와 카드 내용은 알지 못한다. 다음 선택을 조합해 용사들의 생존과 자신의 이익을 바꾼다.

- 공개된 두 경로 중 다음 지점 선택
- 일부 사건 직전 진실·거짓·중립 정보 전달
- 사건에서 지원·방해·아이템·거래·관망 선택
- 파티를 살려 명성·계약금·관계를 보존하거나, 전멸을 유도해 유품 획득

모든 던전을 클리어하면 캠페인을 정상 완주한다. C·B·A·S는 모두 유효한 완주 평가이며 S가 최고 목표다.

## 상태 경계

### `CampaignState`

여러 탐험에 걸쳐 유지되는 상태다.

- 캠페인 시드와 이름 붙은 난수 스트림 상태
- 남은 던전, 각 던전의 현재 등급, 같은 등급 안의 고정 정렬 키
- 모든 생존 인물과 사망 상태
- 완성 파티, 손상 파티, 대기 생존자, 미사용 예비 인원
- 인물별 직업·성격·HP·신뢰·소지 골드·행동 기억
- 현재 명성, 현재 골드, 누적 획득 골드, 영구 길잡이 등급
- 현재 게시판과 캠페인 엔딩

### `ExpeditionState`

선택한 공고 한 건을 처리하는 일시 상태다.

- 선택한 던전과 출전 파티
- 생성된 지도, 현재 위치, 방문 기록, 선택 경로
- 정보 전달 기회와 파티원별 반응·미검증 정보
- 사건 선택, HP·신뢰·아이템·자원 변화 기록
- 자동 보스전 입력과 결과
- 클리어·전멸 결과와 정산 입력

탐험 정산이 끝나면 필요한 결과만 캠페인 상태에 병합하고 탐험 상태를 닫는다. 규칙 함수는 상태를 직접 숨겨 변경하지 않고 입력과 결과를 명시하는 순수 함수로 둔다.

## 캠페인 초기화

한 캠페인은 다음 상태로 시작한다.

| 항목 | 초기값 |
| --- | --- |
| 길잡이 등급 | C |
| 현재 명성 | 0 |
| 현재 골드 | 10 |
| 누적 획득 골드 | 0 |
| 던전 | C 6개, B 4개, A 3개, S 2개 |
| 완성 파티 | 서로 다른 직업·성격의 3인 파티 15팀 |
| 예비 인원 | 직업·성격·초기 신뢰가 생성된 6명 |
| 인물별 소지 골드 | 시드로 정한 10~30 |

시작 골드 10은 기존 프로토타입 자원 계약을 유지한 값이며 누적 획득 골드에는 포함하지 않는다. 프로토타입 던전은 고유 서사 없이 등급과 번호로 표시한다. 내부 식별자는 캠페인 동안 변하지 않으며 전멸로 등급이 올라가도 같은 던전으로 추적한다.

## 공고 게시판

게시판을 열 때 다음 순서를 적용한다.

1. 남은 던전을 C→B→A→S로 정렬한다.
2. 같은 등급은 캠페인 생성 때 만든 시드 정렬 키를 끝까지 유지한다.
3. 출전 가능한 완성 3인 파티를 시드 기반 순서로 정한다.
4. 앞에서부터 `min(5, 남은 던전 수, 완성 파티 수)`개를 중복 없이 짝짓는다.
5. 공고마다 지원 최소 명성을 검사하되, 막힌 공고도 이유와 함께 보여준다.

던전과 파티는 영구 1:1로 묶이지 않는다. 정산 후 게시판을 다시 만들며 같은 던전이 다른 파티와, 방금 출전한 파티가 다른 던전과 즉시 연결될 수 있다. 게시판을 단순히 다시 열거나 화면을 전환하는 행위는 재추첨을 일으키지 않는다.

완성 파티가 1~4팀이면 그 수만큼 공고를 만든다. 0팀이면 공고를 만들지 않고 파티 소진 엔딩 후보가 된다.

## 던전 등급 기준

아래 수치는 첫 백테스트를 위한 프로토타입 상수다.

| 등급 | 지원 최소 명성 | 3명 생존 명성 | 3명 생존 골드 | 전체 지도 지점 |
| --- | ---: | ---: | ---: | ---: |
| C | 0 | 10 | 20 | 7 |
| B | 30 | 15 | 35 | 9 |
| A | 60 | 25 | 55 | 11 |
| S | 100 | 40 | 80 | 13 |

전멸한 던전은 제거하지 않고 `C→B→A→S`로 한 단계 올린다. S급 전멸은 S급을 유지한다. 다음 등장부터 새 등급의 지원 조건, 계약 보상, 지도 길이와 전투 데이터를 모두 사용한다.

## 지도와 사건 흐름

지도는 입구에서 두 갈래로 나뉘고 보스 전 공통 지점에서 합쳐지는 대칭형 비순환 그래프다.

| 등급 | 갈래별 지점 | 전체 지점 | 실제 경로 일반 사건 | 정보 전달 기회 |
| --- | ---: | ---: | ---: | ---: |
| C | 2 | 7 | 4 | 2 |
| B | 3 | 9 | 5 | 3 |
| A | 4 | 11 | 6 | 4 |
| S | 5 | 13 | 7 | 5 |

전체 지점에는 입구, 양쪽 갈래의 개별 지점, 공통 합류 지점, 보스방이 포함된다. 어떤 갈래를 골라도 같은 수의 일반 사건과 정보 전달 기회를 지난다. 모든 실제 경로에는 몬스터·휴식·상인·특수 사건이 최소 한 번씩 등장하고 한 던전 안에서 같은 사건 콘텐츠를 중복하지 않는다.

입장 전에 전체 경로, 보스 위치, 사건 제목·분류, 대략적인 위험 성격, 정보 전달 기회 위치를 공개한다. 정확한 피해·보상·난수와 카드 내용은 해당 지점에 도착할 때까지 숨긴다.

일반 지점은 다음 순서로 처리한다.

```text
지도에서 다음 지점 선택
→ 표시된 지점이면 정보 전달 기회 처리
→ 사건 상황 공개
→ 지원·방해·아이템·거래·관망 중 허용된 행동 선택
→ HP·신뢰·자원 변화와 원인 기록
→ 다음 지도 또는 보스방
```

정보 전달 기회는 사건 행동을 대신하지 않는다. 사건 도중 전멸하면 남은 지점과 보스전을 건너뛰고 실패 정산으로 간다.

## 정보 카드와 개인 반응

카드는 살아 있는 용사 파티원에게만 전달한다. 보스는 카드 수신자가 아니지만 카드 주제는 경로·사건·몬스터뿐 아니라 보스의 약점과 행동을 포함할 수 있다.

각 정보 전달 기회에서 진실·거짓·중립 카드 중 하나를 고른다. 같은 카드를 받은 파티원도 성격, 현재 신뢰와 시드 판정에 따라 독립적으로 수용·의심·즉시 적발한다. 수용한 사람에게만 카드의 즉시 효과를 적용하고, 반응과 미검증 정보는 개인 기록으로 보스전 또는 사후 검증까지 유지한다.

선택한 실제 경로에서 보장할 보스 관련 정보 수는 다음과 같다.

| 던전 등급 | 보스 관련 정보 보장 |
| --- | ---: |
| C | 1 |
| B | 1 |
| A | 2 |
| S | 2 |

개인별 수용 확률과 신뢰 변화량은 [정보와 기만](../../systems/INFORMATION_AND_DECEPTION.md)과 [파티와 신뢰](../../systems/PARTY_AND_TRUST.md)를 단일 기준으로 사용한다.

## 상인과 자원 소비

상인은 일반 사건의 한 종류다. 현재 골드로 치료제·독·정보·가짜 지도 같은 콘텐츠 데이터 상품을 구매한다. 구매 후 현재 골드는 줄지만 누적 획득 골드는 줄지 않는다. 잔액보다 비싼 구매는 거부하고 상태를 바꾸지 않는다.

## 자동 보스전

보스방에서는 새 카드, 보스 거래, 길잡이의 직접 전투를 제공하지 않는다. 파티원별 현재 HP, 사건 효과, 사용한 아이템, 수용한 보스 정보와 미검증 기록을 입력으로 전투를 자동 해결한다.

수용한 보스 정보는 해당 파티원이 받는 보스 피해에 다음 보정을 준다.

| 반응한 카드 | 피해 보정 |
| --- | ---: |
| 수용한 진실 | -20% |
| 수용한 중립 | -10% |
| 수용한 거짓 | +25% |
| 의심·즉시 적발 | 0% |

여러 장은 합산하며 최종 보정을 `-30%~+50%`로 제한한다. 보정은 파티원마다 독립 적용하고 등급·보스 콘텐츠가 제공한 기본 피해에 한 번 적용한다. 정수 변환은 공통 피해 계산 규칙을 사용한다. 전투 뒤 거짓과 의심 결과를 검증해 신뢰 변화와 사람이 읽을 수 있는 이유를 남긴다.

한 명 이상 살아남으면 클리어, 전멸하면 실패다. 보스별 기본 피해와 아이템 수치는 코드에 흩어 놓지 않고 검증 가능한 콘텐츠 데이터로 둔다.

## 파티 지속, 충원과 재편

정산 뒤 출전 파티를 다음 순서로 처리한다.

1. 3명이 생존하면 같은 팀을 유지한다.
2. 1~2명이 생존하면 직업이 겹치지 않는 예비 인원으로 먼저 충원한다.
3. 예비 인원만으로 완성할 수 없으면 모든 손상 파티의 생존자를 자동 재편한다.

자동 재편의 우선순위는 다음과 같다.

1. 만들 수 있는 완성 3인 파티 수 최대화
2. 기존 동료가 함께 남는 쌍의 수 최대화
3. 동률이면 캠페인 시드로 결정

완성 파티에 들어가지 못한 생존자는 대기한다. 파티가 바뀌어도 HP·직업·성격·개인 신뢰·소지 골드·행동 기억은 인물에게 남는다.

초기 신뢰는 기존 성격별 생성 규칙을 유지한다. 기본값에 시드로 고른 `-5~+5` 정수를 더하고 0~100으로 제한한다.

| 성격 | 초기 신뢰 기본값 |
| --- | ---: |
| 의심 많음 | 35 |
| 신중함 | 45 |
| 탐욕스러움 | 50 |
| 정의로움 | 55 |
| 충동적 | 60 |

### 비출전 회복

한 탐험 정산 때 그 탐험에 출전하지 않은 모든 생존자는 완성 파티 소속이나 게시판 등장 여부와 무관하게 회복한다.

```text
회복량 = max(1, round(현재 HP × 0.05))
회복 후 HP = min(최대 HP, 현재 HP + 회복량)
```

출전한 생존자는 정산 뒤 다른 파티로 재편되더라도 그 정산에서는 회복하지 않는다.

## 정산

파티원 수는 프로토타입에서 3명으로 고정한다. 한 명 이상 생존한 클리어의 계약 보상 비율은 다음과 같다.

| 생존자 | 기본 명성·골드 배율 |
| ---: | ---: |
| 3 | 100% |
| 2 | 60% |
| 1 | 30% |

각 자원 보상에 배율을 적용한 뒤 소수점 이하는 버린다. 부분 생존 클리어에서는 죽은 사람의 소지 골드를 얻지 않고 감액된 계약 보상만 받는다.

전멸하면 계약 보상을 받지 않고 해당 등급의 3명 생존 기본 명성만큼 현재 명성을 잃는다. 사망자 전원의 소지 골드는 길잡이가 유품으로 챙겨 현재 골드와 누적 획득 골드에 모두 더한다.

현재 명성은 음수가 될 수 있다. 현재 골드와 누적 획득 골드는 0 미만이 될 수 없으며 누적 획득 골드는 소비로 줄지 않는다.

정산 순서는 다음과 같다.

1. 생존·사망과 신뢰 결과 확정
2. 계약 보상 또는 전멸 손실·유품 반영
3. 던전 제거 또는 등급 상승
4. 승급 점수와 영구 등급 갱신
5. 충원·자동 재편
6. 비출전 생존자 회복
7. 엔딩 판정
8. 계속되면 다음 게시판 생성

## 승급

명성과 골드의 개별 최소 조건을 두지 않고 가중 합산 점수 하나를 사용한다.

```text
승급 점수 = 현재 명성 × 2 + 누적 획득 골드
```

| 영구 길잡이 등급 | 필요한 점수 |
| --- | ---: |
| C | 0 |
| B | 120 |
| A | 274 |
| S | 370 |

매 정산 후 점수가 만족하는 가장 높은 등급으로 즉시 승급하므로 여러 등급을 건너뛸 수 있다. 한 번 달성한 등급은 점수나 현재 명성이 내려가도 강등되지 않는다. 단, 현재 명성은 계속 공고 지원 조건을 제한한다.

승급 기준은 특정 던전 수를 별도 조건으로 세는 방식이 아니다. 아래 진행을 했을 때 목표 등급에 도달하도록 만든 프로토타입 밸런스 기준이다.

- C→B: C급 3개를 각각 3명 전원 생존으로 클리어
- B→A: B 승급 뒤 B급 2개를 각각 3명 전원 생존, 새 C급 1개를 2명 이상 생존으로 클리어
- A→S: S급 1개 또는 A급 2개를 각각 2명 이상 생존으로 클리어

기준 체크포인트는 다음과 같다.

| 시점 | 현재 명성 | 누적 골드 | 점수 |
| --- | ---: | ---: | ---: |
| C급 3개 전원 생존 뒤 | 30 | 60 | 120 |
| 이후 B급 2개 전원 생존 + C급 1개 2명 생존 뒤 | 66 | 142 | 274 |
| 이후 S급 1개 2명 생존 뒤 | 90 | 190 | 370 |
| 대신 A급 2개 각각 2명 생존 뒤 | 96 | 208 | 400 |

명성 또는 골드 기여에 상한을 두지 않는다. 수치와 가중치는 첫 백테스트 결과로 후속 밸런스 패치할 수 있지만, 변경할 때 공식 문서와 기준 시나리오를 함께 갱신한다.

## 엔딩

정산 뒤 다음 우선순위로 하나만 판정한다.

1. `불신의 대가`: 이번 탐험에 생존한 출전자가 한 명 이상이고 생존자 전원의 신뢰가 0
2. `원정 종료`: 던전 15개를 모두 클리어
3. `길잡이 자격 박탈`: 공고가 한 개 이상 만들어졌지만 모두 현재 명성 제한에 막힘
4. `용사들의 시대가 끝나다`: 완성 가능한 3인 파티가 없어 공고를 만들 수 없음

정상 완주 화면은 영구 길잡이 등급 C·B·A·S 중 하나를 최종 평가로 보여준다. 조기 엔딩도 최종 영구 등급과 캠페인 기록을 함께 보여준다.

## 상태 전이와 화면

정상 흐름은 다음 단계만 허용한다.

```text
campaignBoard
→ partyIntro
→ pathChoice
→ infoOpportunity(선택된 지점에서만)
→ event
→ pathChoice 반복
→ bossFight
→ settlement
→ campaignBoard 또는 campaignEnded
```

전멸하면 현재 단계에서 `settlement`로 이동한다. 잘못된 단계에서 선택을 보내거나 이미 처리한 사건을 다시 처리하는 전이는 명시적으로 거부한다.

모든 캠페인 화면의 고정 헤더에는 영구 등급, 현재 명성, 현재 골드, 누적 획득 골드, 승급 점수, 남은 던전 수를 표시한다. 게시판은 잠긴 공고도 보여주고 필요한 명성과 부족한 값을 설명한다. 정산은 선택→개인 반응→피해·신뢰→보상·손실→승급·파티 변화의 원인 사슬을 보여준다.

## 결정적 재현과 오류 처리

캠페인 시드 하나에서 목적별 난수 스트림을 이름으로 분리한다. 최소 스트림은 던전 정렬·콘텐츠, 공고 파티 연결, 파티·예비 생성, 소지 골드, 지도·사건, 정보 반응, 신뢰 변동, 전투 결과다. 한 영역의 난수 소비가 다른 영역의 결과를 우연히 바꾸지 않아야 한다.

같은 시드와 같은 사용자 선택 순서는 같은 캠페인 상태와 결정 기록을 만든다. 게시판 화면 재진입처럼 규칙상 선택이 아닌 동작은 난수를 소비하지 않는다.

다음 상태는 조용히 재추첨하거나 기본값으로 덮지 않고 구조화된 오류를 반환한다.

- 중복되거나 존재하지 않는 던전·인물·사건 식별자
- 등급별 지점 수, 경로 대칭, 정보 횟수 또는 보스 정보 보장 위반
- 사건 콘텐츠 부족과 같은 던전 내 중복
- 직업 중복 파티 또는 죽은 인물의 출전
- 잔액을 넘는 구매와 음수 골드
- 허용되지 않은 상태 전이와 중복 정산

## 검증과 백테스트

### 규칙 테스트

- 게시판 정렬·최대 5개·1~4개 축소·명성 잠금·0파티 처리
- 던전 실패 등급 상승과 S급 유지
- 개인 상태 보존, 예비 충원, 자동 재편 우선순위, 비출전 5% 회복
- 3/2/1명 보상과 전멸 명성·유품 처리
- 승급식, 체크포인트, 다단계 승급, 무강등
- 네 엔딩의 조건과 우선순위
- 정보 개인 반응, 보스 카드 보장, 피해 보정 합산·상한
- 허용 상태 전이와 오류 원자성

### 생성 불변식

10,000개 캠페인 시드에서 다음 위반이 0건이어야 한다.

- 초기 던전·파티·예비 인원 수 또는 식별자 오류
- 중복 직업·성격을 가진 완성 파티
- 잘못된 지도 지점 수, 비대칭·단절·순환 경로
- 어느 선택 경로에서든 정보 전달 횟수 또는 보스 정보 보장 부족
- 사건 콘텐츠 부족으로 즉시 플레이할 수 없는 던전
- 같은 시드·선택을 재실행했을 때 다른 결과

### 밸런스 보고서

10,000개 시드를 생존 우선, 균형, 전멸 골드 우선 전략으로 실행해 다음을 보고한다.

- 최초 B/A/S 승급 시점과 도달률
- 정상 완주와 각 조기 엔딩 비율
- 남은 파티·예비·대기 인원과 평균 HP·신뢰
- 현재 명성, 현재·누적 골드, 최종 등급 분포
- 던전별 실패·등급 상승과 보스 사망률

전략별 목표 비율은 첫 결과를 본 뒤 별도 밸런스 변경으로 정한다. 이번 완료 기준은 기준 체크포인트의 정확성, 생성 불능 0건, 결과 보고서 생성이다.

## 구현 경계와 순서

상세 plan은 공유 도메인 계약을 먼저 완료한 뒤 세 트랙을 병렬화한다.

1. 공유 기반: `CampaignState`, `ExpeditionState`, 식별자, 결과·오류, 난수 스트림 계약
2. 캠페인 규칙: 초기화, 게시판, 지속 파티, 정산, 승급, 엔딩, 백테스트
3. 탐험 규칙: 등급별 지도, 정보, 사건, 자동 보스전
4. 화면: 게시판·HUD, 지도·정보·사건, 정산·엔딩
5. 통합: 게시판부터 엔딩까지 연결하고 전체 검증

세 트랙의 실제 작업 ID와 의존성은 [프로토타입 작업 배정표](../../technical/PROTOTYPE_WORK_ASSIGNMENT.md)를 따른다. 담당자는 상세 plan 승인 때 배정한다.

## 역사 문서 처리

기존 spec과 plan은 삭제하거나 새 규칙으로 다시 쓰지 않는다. 단일 탐험, 기존 지도 크기, 이전 정보 흐름, 이전 화면·상태·작업 배정을 제품 요구사항으로 설명하는 문서 상단에는 `대체됨` 안내를 추가한다. 기존 코드가 어떤 합의로 만들어졌는지 확인하는 역사 자료로만 사용한다.
