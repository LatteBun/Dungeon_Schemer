## 1. 목적과 범위

C2는 현재 `CampaignState`에서 게시판 공고를 결정적으로 만드는 순수 규칙이다. 게시판은 미클리어 던전을 비교할 수 있게 보여 주고, 각 공고에 서로 겹치지 않는 서로 다른 직업 3인의 임시 파티와 공개 환경 특성을 붙인다.

포함:

- 현재 위험도와 길잡이 등급으로 공고 후보를 고르는 규칙
- 최대 5개의 공고와, 3인·서로 다른 직업을 보장하는 공고별 임시 파티
- 같은 게시판 안의 공고 간 캐릭터 중복 금지
- 위험도와 환경 특성으로 이루어진 공개 위험 정보
- 생태 패키지·출현 몬스터·공개 환경 특성의 콘텐츠 검증
- 시드와 `worldTurn`에 따른 게시판·파티 재현성 테스트

제외:

- 계약 수락, 선택 공고 보관, `phase` 전이와 상태 머신 (`C7`, `I1`)
- 던전 지도·사건·정보·보스전 (`E1`~`E4`)
- 정산·월드턴·승급·엔딩 판정 (`C3`~`C6`)
- 게시판·계약 화면 렌더링 (`U3`)

## 2. 공개 환경 특성 콘텐츠 계약

던전 이름은 이미 테마를 포함한다. 따라서 공고의 환경 특성은 테마 이름을 반복하지 않고, 해당 생태 패키지의 실제 출현 몬스터에서 읽을 수 있는 넓은 위험 성격을 한 개만 표시한다. 화면은 기존 `riskLevel`의 `★N` 배지와 이 환경 특성 배지를 함께 보여 준다. 위험도 문자열을 별도 태그로 중복 저장하지 않는다.

`ThemeContent`는 테마마다 정확히 세 개의 공개 환경 특성 후보를 소유한다. 후보는 안정 ID, 표시 문구, 근거가 될 수 있는 몬스터 `traits` 문구 목록을 가진다. `EcologyProfile`은 그중 하나의 ID를 `publicEnvironmentTagId`로 참조한다.

확정한 후보와 패키지 매핑은 다음과 같다.

| 테마 | 후보 환경 특성 | 생태 패키지 → 공개 환경 특성 |
| --- | --- | --- |
| 거미굴 | `진동 경계` · `시체 흔적` · `어둠 잠복` | `spider-shallow-a` → 진동 경계, `spider-shallow-b` → 어둠 잠복, `spider-carrion-route` → 시체 흔적, `spider-dark-passage` → 어둠 잠복, `spider-queens-forecourt` → 어둠 잠복 |
| 사막 | `열기 노출` · `수분 지대` · `발자국 소실` | `desert-scorched-well` → 수분 지대, `desert-wind-well` → 열기 노출, `desert-buried-trail` → 발자국 소실, `desert-dry-trail` → 수분 지대, `desert-burning-waste` → 열기 노출 |
| 묘지 | `소리 경계` · `빛 노출` · `매장물 수호` | `graveyard-quiet-guard` → 매장물 수호, `graveyard-dim-crypt` → 빛 노출, `graveyard-grave-robber` → 매장물 수호, `graveyard-hunters` → 소리 경계, `graveyard-blighted-tomb` → 소리 경계 |

콘텐츠 검증기는 후보가 정확히 세 개인지, 후보 ID·문구가 중복되지 않는지, 패키지가 자기 테마의 후보만 참조하는지, 그리고 패키지 `activeMonsterIds` 중 하나 이상의 `traits`가 선택한 태그의 근거 목록에 있는지를 확인한다. 예를 들어 `어둠 잠복`은 그림자거미의 `어둠 속에서만 활동`을 근거로 삼는다. 결함은 조용히 바꾸거나 재추첨하지 않고 `RuleError("INVALID_GENERATION")`으로 실패한다.

## 3. 공고와 파티 데이터 경계

`BoardOffer`에는 다음 필드를 추가한다.

- `publicEnvironmentTag`: 공고가 공개하는 환경 특성의 안정 ID와 표시 문구
- 기존 `riskLevel`: 계약 시점의 현재 위험도를 계속 보관한다

공개 API는 `createBoardOffers(state: CampaignState): readonly BoardOffer[]`다. 이 함수는 입력을 바꾸지 않으며 시간·전역 상태·`Math.random()`을 읽지 않는다. `state.phase`와 `state.offers`도 바꾸지 않는다. C7/I1이 결과를 캠페인 상태에 저장하고 단계 전이를 담당한다.

공고 ID는 `offer-${worldTurn}-${dungeonId}`로 만든다. ID와 파티는 한 번의 게시판에만 유효한 스냅샷이다. 플레이어가 한 공고를 계약해 원정을 마치면 그 파티는 해체된다. 정산·월드턴 뒤 다음 게시판을 만들 때는 현재 캐릭터 풀과 새 `worldTurn`으로 모든 공고와 파티를 다시 만든다. 던전과 파티 사이에는 캠페인 전체에 지속되는 관계가 없다.

## 4. 생성 흐름

난수는 캠페인 시드와 `worldTurn`을 결합한 시드로 `createRng`를 호출해 만들고, 그 결과에서 `board`와 `party` 파생 스트림을 분리한다. 따라서 게시판 동률 정렬과 파티 편성의 난수 소비 순서는 서로 영향을 주지 않는다.

1. `canDeploy`를 통과한 캐릭터를 직업별 후보로 나눈다.
2. 남은 후보에서 서로 다른 직업 세 개를 골라 한 파티를 만들고, 세 캐릭터를 즉시 후보에서 제거한다. 가능한 한 많은 완전 3인 파티를 만들도록 남은 후보 수가 많은 직업을 우선하며, 동률의 직업·같은 직업의 캐릭터 순서는 `party` 스트림으로 정한다.
3. 최대 5개까지 만든 완전 파티 수를 이번 게시판의 공고 상한으로 삼는다. 3인 파티를 하나도 만들 수 없으면 빈 공고 목록을 반환한다. 이는 게임 진행에서 가능한 상태이며 C6이 인력 소진을 판정한다. 부분 파티·캐릭터 재사용·자동 대체는 만들지 않는다.
4. 미클리어 던전 중 `riskLevel <= RANK_RISK_LIMIT[state.rank]`인 진입 가능 후보를 현재 위험도를 저울로 삼아 `board` 스트림으로 하나씩 뽑는다. 뽑힐 무게는 `riskLevel ** 2`이므로 ★4는 ★1보다 열여섯 배 자주 걸리되 ★1도 걸린다.
5. 공고 상한까지 진입 가능 후보를 먼저 넣는다. 자리가 남으면 미클리어·진입 불가 후보를 현재 등급에 가장 가까운 위험도 오름차순으로 넣고, 같은 위험도만 `board` 스트림으로 섞는다. 잠금 사유는 `rankTooLow`다.
6. 선택한 던전과 앞에서 만든 파티를 순서대로 한 번씩 연결한다. 따라서 한 게시판에서 캐릭터가 두 공고에 나타날 수 없다. 선택되지 않은 파티와 던전은 반환하지 않는다.

### 2026-08-26 개정 — 내림차순에서 위험도 가중으로

처음에는 진입 가능 후보를 **위험도 내림차순**으로 정렬했다. 등급이 오를수록 게시판이 험해지게 하려는 것이었고, 그 목적은 이뤘다 — 걸리는 던전의 평균 위험도가 C 1.80, B 2.80, A 3.60, S 4.00이었다.

그러나 두 가지가 드러났다.

**첫째, 캠페인마다 같은 게시판을 본다.** 등급 C에서 갈 수 있는 던전이 일곱인데 그중 ★2가 넷이라, 그 넷이 언제나 먼저 차고 남은 한 칸만 ★1 셋이 돌아가며 채웠다. 시드 예순 판에서 서로 다른 조합이 **세 가지**뿐이고 ★2 넷은 100%로 걸렸다.

**둘째, 후반에는 그 목적마저 지켜지지 않는다.** 던전을 정복해 나가면 남은 후보가 줄어, 내림차순이라도 남은 것이 그대로 걸린다. 실제 캠페인을 돌려 보니 월드턴 17에서 `[3,1]`처럼 한 게시판 안의 위험도 편차가 2.50까지 벌어졌다. 내림차순의 보장은 후보가 넉넉한 초반에만 성립한다.

그래서 정렬 대신 **위험도를 저울로 삼아 뽑는다.** 험한 쪽이 자주 걸리되 늘 그렇지는 않다.

| 등급 | 내림차순 | 위험도 가중 |
| --- | --- | --- |
| C | 1.80 | 1.73 |
| B | 2.80 | 2.53 |
| A | 3.60 | 3.15 |
| S | 4.00 | 3.46 |

등급별 상승은 남기고, 서로 다른 조합은 세 가지에서 열다섯 가지가 된다. 100%로 걸리는 던전은 없어진다.

진입 가능한 던전이 하나도 없어도, 완전 파티가 존재하고 미클리어 잠금 던전이 있으면 잠금 공고를 보여 준다. C6은 이 결과가 모두 잠겼는지를 읽어 실직을 판정한다.

## 5. 오류 처리와 불변식

| 경우 | C2 처리 |
| --- | --- |
| 환경 특성 후보·패키지 참조·몬스터 근거가 잘못됨 | 콘텐츠 검증에서 `RuleError("INVALID_GENERATION")` |
| 출전 가능 캐릭터로 3직업 3인을 만들 수 없음 | 빈 공고 배열. 인력 소진 판정은 C6의 책임 |
| 미클리어 던전이 없음 | 빈 공고 배열. 원정 종료 판정은 C6의 책임 |
| 진입 가능한 던전이 없음 | 잠긴 공고를 가능한 수만큼 반환. 실직 판정은 C6의 책임 |

모든 정상 반환 공고는 다음을 만족한다.

- 개수는 5 이하이며, 공고마다 정확히 서로 다른 직업 3명의 파티가 있다.
- 같은 게시판에서 어떤 캐릭터 ID도 두 번 등장하지 않는다.
- 던전은 미클리어이며 공고의 `riskLevel`은 해당 던전의 현재 `riskLevel`과 같다.
- 진입 가능 공고는 진입 불가 공고보다 먼저 있다.
- 진입 가능 구간의 평균 위험도는 등급이 오를수록 높아진다.
- 같은 던전이 모든 캠페인의 첫 게시판에 걸리지는 않는다.
- 잠긴 공고는 현재 등급에 가까운 위험도부터 나오며 모두 `rankTooLow` 사유를 가진다.
- 같은 입력은 같은 공고 값과 순서를 반환하고, 반환 배열·공고·파티 참조는 다른 호출과 공유하지 않는다.

## 6. 테스트와 파일 경계

| 영역 | 파일 | 책임 |
| --- | --- | --- |
| 도메인 | `lib/domain/ids.ts`, `lib/domain/dungeon.ts`, `lib/domain/campaign.ts`, `lib/domain/index.ts` | 환경 특성 ID·정의, 패키지 참조와 공고 공개 태그 타입 |
| 콘텐츠 | `lib/content/themes.ts`, `lib/content/theme-validation.ts` 및 테스트 | 후보 세 개, 확정 매핑, 몬스터 특성 근거 검증 |
| 규칙 | `lib/rules/board.ts` 및 테스트 | 시드·차수 기반 공고 선택과 중복 없는 파티 편성 |
| 문서 | `docs/systems/DUNGEON_THEMES_AND_ECOLOGY.md`, `docs/systems/CHARACTER_POOL_AND_WORLDTURN.md`, `docs/design/CORE_GAME_LOOP.md`, `docs/README.md`, 작업 배정표 | 공식 규칙과 구현 기록 동기화 |

규칙·콘텐츠 테스트는 아래를 보장한다.

- 테마별 후보 세 개, 확정한 15개 패키지 매핑, 출현 몬스터 `traits`의 근거
- 동일 시드·`worldTurn`의 deep equal과 참조 비공유
- 초기 C급에서 ★2 네 공고와 시드에 따라 달라지는 ★1 한 공고
- 진입 가능 공고 부족 시 가까운 위험도의 잠금 공고 우선
- 모든 공고의 정확히 세 명·직업 중복 없음·공고 간 캐릭터 중복 없음
- 인력·직업 분포가 부족하면 만들 수 있는 완전 파티 수만큼만 공고가 나오고 부분 파티가 없음
- 다음 `worldTurn`에서 공고 ID·파티 스냅샷이 새로 만들어지며, 이전 던전-파티 관계가 재사용되지 않음
- 콘텐츠 결함은 `INVALID_GENERATION`, 게임 진행상 편성 불가는 빈 배열

자동 검증은 관련 Vitest 테스트, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`다. C2는 순수 규칙과 콘텐츠 계약만 구현하므로 브라우저 검증은 U3 및 통합 작업의 책임이다.
