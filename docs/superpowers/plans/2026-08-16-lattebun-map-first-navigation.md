# 지도 우선 탐험 시작 구현 계획

## 목표

계약 수락 후 입구 사건을 자동 실행하지 않고 지도 화면에서 첫 노드를 고르게
하며, 설정집·규칙 검증·화면 라우팅·회귀 테스트를 동일 계약으로 맞춘다.

## 작업 순서

1. 공식 문서 계약 갱신
   - `docs/design/CORE_GAME_LOOP.md`의 탐험 단계와 진행 단계 설명을 지도 우선으로 갱신한다.
   - `docs/systems/DUNGEON_EVENTS_AND_BOSSES.md`의 등급별 실제 경로 사건 수와 일반 진행 예시를 갱신한다.
   - 위 spec의 수치·상태 전이와 문서가 일치하는지 확인한다.

2. 지도 생성 규칙 갱신
   - `lib/rules/map.ts`에서 입구 정보 슬롯을 제거한다.
   - 입구 사건을 소비하지 않도록 일반 사건 풀 예약·용량 검사를 조정한다.
   - 경로 사건 수 계산과 검증 기대값을 `branchLength + 1`로 변경한다.
   - 기존 지도 구조와 시드 RNG 순서의 의도하지 않은 변경이 없는지 테스트한다.

3. 캠페인 전이 갱신
   - `lib/flow/campaign-machine.ts`의 `acceptContract`가 생성한 원정을 `map` 단계로 반환하도록 수정한다.
   - `arriveAt`과 `selectNode`의 정보·사건·보스 분기는 유지한다.
   - 입구 재선택 거부와 첫 갈래 선택 전이를 회귀 테스트로 고정한다.

4. fixture·화면 계약 갱신
   - `/play` 및 U3/E1 fixture에서 계약 수락 직후 예상 단계를 `map`으로 바꾼다.
   - 지도에서 첫 노드를 선택한 뒤 encounter로 이동하는 테스트를 추가한다.
   - 직접 URL/phase-route 가드가 새 상태를 반영하는지 확인한다.

5. 검증 및 보고
   - focused 규칙·전이·라우트 테스트를 먼저 실행한다.
   - lint, typecheck, 전체 Vitest, Next build를 실행한다.
   - 변경 파일·명령·결과를 작업 보고서에 기록하고 한글 제목/본문 커밋으로 남긴다.
